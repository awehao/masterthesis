# 時空代價場 — 改動記錄

目標:動態避障軌跡平滑、**不無故折返**,且不犧牲安全與成功率。

原則:`ST_WEIGHT=0` 永遠等價於驗證過的 98% 配置(已用數值測試確認誤差 0.00e+00),
任何改動都可用單一參數退回。

---

## 已完成的改動

### C1. 時空代價場本體 — `gmpc.py::_build_spacetime_cost()`
在 GMPC 的 QP 成本中加入對**預測**障礙位置的高斯軟障壁:

```
C_k(p) = W · exp(−‖p(k) − o_i(k)‖² / 2σ_k²)
o_i(k) = o_i(0) + v_i·k·dt          （與 CBF 相同的等速度預測）
σ_k    = σ₀(1 + growth·k)           （預測越遠越不確定）
```

二階泰勒展開後併入 `P`、`q`,**不增加決策變數**;`δp_k = A_k z`,
`A_k = R_ref(k) S_k Γ`。

**為什麼**:硬 CBF 只在即將違反時才動作,所有避障都變成對固定參考路徑的
「臨時變形」。軟代價場在數公尺外就給梯度,讓控制器提早微幅偏轉。

### C2. Hessian 半正定投影 — `_psd_project_2x2()`
高斯峰頂是**凹的**,原始 Hessian 負定,直接加進 `P` 會讓 QP 非凸。
對每個 2×2 Hessian 做特徵值裁切(Gauss-Newton 式近似)。

**驗證**:2000 次隨機對稱矩陣,最小特徵值 −2.2e-16(浮點零)。

### C3. 尺度修正(關鍵)
最初把 `W_eff = W·σ²·trace(Q)/2`,想「錨定到追蹤權重」,結果 `W=30` 變成
`W_eff ≈ 200`。但該比的是**典型偏差下的追蹤成本** `Q×0.1² ≈ 0.15`,
不是 `Q` 本身 —— **差三個數量級**。

症狀:機器人變成純斥力場逃跑者。2D 實測 路徑 27.6→48.9 m、
淨距暴增到 +0.45、deg/m 192→1389、到不了終點。gz 三次全部 0/2 失敗。

**修正**:`st_weight` 直接就是單一障礙的峰值成本,合理範圍 **O(1)**(實測 1~5)。

### C4. 梯度與曲率雙重截斷
只夾 Hessian 不夠 —— **梯度進的是 `q`,才是驅動解的主力**。
只夾 Hessian 時仍震盪(deg/m 5226)。兩者都夾在
`2 × max(Q) × 0.01`(典型追蹤成本量級)。

### C5. 未收斂解的可行性防護 — `gmpc.py::solve()`
`maximum iterations reached` 的解**不保證可行**。加了代價場後 OSQP 曾回傳
違反加速度上限的點(|du/dt| = 1.07 vs a_max 0.80),底盤收到階躍指令。

**修正**:僅對**未收斂**的解做 `a_max` 硬夾;已收斂的解本來就滿足約束,不碰。

**曾經改壞又還原**:一度把求解失敗的 fallback 從「煞停」改成「保持上一步速度」,
理由是避免煞停的 jerk。但求解失敗正好發生在障礙物附近,滑行過去直接撞上
(基準從 0 碰撞 / +0.037 m 變成 2 碰撞 / −0.077 m)。**已還原為煞停**。

## 折返的真正機制（本次確認）

對 dyn_obs_1 區域的 42 個折返點，比對該障礙物自身的掉頭時刻：

| | 實測 | 若與掉頭無關 |
|---|---|---|
| 距最近掉頭時刻（中位） | **3.3 s** | ~9.8 s |
| 落在掉頭 ±3 s 內 | **43%** | ~15% |

**折返集中發生在障礙物自己掉頭的時候。**

dyn_obs_1 在 y 3.0↔5.55 之間 ping-pong，週期 39.2 s；機器人以 0.22 m/s 通過該區要十幾秒，
所以它正在閃避時，障礙物很可能中途反向。CBF 與時空代價場都用等速度外推
`o(k) = o(0) + v·k·dt`，障礙物一掉頭，整段預測就反了，控制器只能重新決策 —— 那就是折返。

**這不是控制器缺陷，是等速度預測假設被違反時的正確反應。**

這一併解釋了兩個介入為何失敗：
- 時空代價場用同一套等速度預測，掉頭時同樣被騙；
- 感知遲滯讓過期的速度多留幾幀，掉頭後錯得更久，所以折返反而增加。

### 可能的方向（尚未實作、未驗證）
1. **預測不確定性隨時間膨脹**：CBF 的 keep-out 半徑隨 k 增大，等價於「越遠期越不信任預測」。
   目前 σ 只在時空代價場裡膨脹，CBF 的 margin 是固定的。
2. **多模態預測**：對會往復運動的物體，同時考慮「維持」與「反向」兩種假設，取較保守者。
3. **場景層面**：ping-pong 障礙的往復週期與機器人通過時間相當，是這個現象的放大器。
   真實行人多為單向通過，折返率應顯著較低 —— 值得用單向通過的場景另做一組對照。

### 目前定案
`ST_WEIGHT=0`、遲滯關閉（`release_track_speed=0.10`、`frames=0`）
= **維持原本驗證過的配置**。兩項功能的程式碼都保留且可用單一參數開啟。

## C6. 承諾式繞行 `detour.py` — 直接針對「往後躲」而非「往左前繞開」

前面每一項介入（時空代價場、感知遲滯、殘差 RL）都在**同一個框架內**微調，
全部無效。這一項改的是框架本身：**改寫要被追蹤的參考**。

### 為什麼前面都失敗
CBF 是疊在**固定參考路徑**上的硬約束。QP 裡沒有「從左邊繞過去」這個概念，
只有「參考往這邊拉、約束往那邊推」。兩個後果：

1. **每一步都重新選邊。** 障礙物掉頭，機器人就跟著掉頭 —— 這正是先前量到的
   「43% 的折返落在障礙物掉頭 ±3 s 內」。
2. **往後讓與往旁邊繞，追蹤成本一樣。** 所以「停下來等」是合法解，
   而且常常是最省的解。

MPPI 沒有這兩個問題，因為它取樣的是**整條軌跡**，選中的那條本身就是一條完整的繞法。

### 三個機制
1. **鎖定同倫類（`DetourState`）**：障礙物進入前方 ±30° / 2.0 m 錐形時
   一次性選定 LEFT 或 RIGHT，在該障礙真正被甩到身後（body-frame x < −0.3 m）
   之前**不重選**。選邊規則：走障礙物**不在**的那一側；正前方時用它的側向速度
   決定（從它來的方向後面過，不橫切它的去路）。
2. **參考側移（`apply_offset`）**：鎖定期間把時域內的參考點沿法線推開，
   形狀 `sin²(πk/N)`，中段峰值、**末端歸零**。於是追蹤成本 Q **主動把機器人拉去繞**，
   而不是抵抗 CBF 的推。`sin²` 在兩端 C1 連續 —— 折線參考正是輸入平滑成本要對抗的東西。
3. **前進速度下限**：繞行期間 `u_min[0] = 0.10 m/s`，把「停下來等」移出解空間。

### 已驗證
| 檢查 | 結果 |
|---|---|
| 選邊（障礙 y=+0.5→RIGHT、y=−0.5→LEFT）| ✓ |
| **障礙左右擺盪 60 步，鎖定邊切換次數** | **0 次** ✓ 這是治折返的核心 |
| 障礙移到身後 → 解鎖 | ✓ |
| 參考變形為拱形、峰值 0.35 m @ 中段、末端 +0.000 | ✓ |
| `detour_enable=False` 參考完全未變 | ✓ 誤差 0.00e+00 |

啟用方式：`DETOUR=1 DETOUR_OFFSET=0.35`（預設關閉）。

### 2D 沙盒對此無判別力
2D 快篩的折返數在所有配置都是 ~0，重現不了 gz 的 7.7 次/趟。

要往這裡查，而不是往選邊邏輯查。

## 一個必須更正的診斷錯誤

**我先前說「第一輪四次碰撞全部撞牆」是錯的。**

那個診斷的做法是：找出「離牆最近」的那一刻，然後在**該時刻**比較
「離牆距離」與「離柱子 / 離動態障礙**路徑線段**的距離」，取最小者命名。
問題在於：**路徑線段不是障礙物當下的位置**。障礙物在那條線上來回移動，
拿機器人到整條線段的距離當「離障礙的距離」會嚴重低估實際間距，
於是「牆」總是贏。

改用正確量法（整趟對 `/gmpc/obstacles` 實際追蹤到的障礙位置取最小值）：

| | 最貼牆 | 最近動態障礙 | 判定 |
|---|---|---|---|
| 第一輪 seed1 | 0.364 | 0.274 | 擦動態障礙 |
| 第一輪 seed5 | 0.391 | 0.312 | 擦動態障礙 |
| 第一輪 seed6 | 0.300 | 0.300 | 擦動態障礙 |
| 第一輪 seed8 | 0.300 | 0.237 | 擦動態障礙 |
| 第二輪 seed1/4/5/8/9 | 0.300~0.381 | 0.180~0.320 | 全部擦動態障礙 |

機器人半徑 0.30、障礙半徑 0.25，接觸距離 0.55。
**兩輪、九次碰撞，最貼牆距離全都 ≥ 0.30（貼邊但未穿透），而離障礙只有 0.18~0.32。
沒有一次是撞牆。**

代價：牆感知選邊（C6）**打在錯的目標上**，而為它加的那條「偏好側被擋就改走
另一側」的退路，等於把參考彎向**障礙物所在的那一側**，讓安全性更糟
（淨距 +0.008 → −0.086、碰撞 4 → 5）。已改為**偏好側沒空間就不繞行**。

## C8. 真正的機制 — 彎過去的參考點落在 CBF 禁區裡

一個算術問題：

```
CBF 禁區半徑  r_eff = r_obs + margin = 0.25 + 0.38 = 0.63 m
繞行推開參考        max_offset       = 0.35 m
時域內橫移上限      vy_max * T = 0.25 * 1.0 = 0.25 m
```

**參考點被彎到障礙旁 0.35 m 處，而那裡在 0.63 m 的禁區內。**
追蹤成本 Q 拚命把機器人拉向一個 CBF 禁止的點，兩者對抗，
結果是貼著約束邊界走，鬆弛變數一啟動就穿透。實測參考點離障礙中心最近只有
**0.015 m**。

**加大 offset 解決不了**：需要 0.63 m，但時域內只能橫移 0.25 m，
參考會變成追不到的目標。

**修正 `clear_reference()`**：彎完之後，把每個落在禁區內的參考點
**沿徑向投影到禁區邊界外**（用與 CBF 相同的等速度預測 `o(k)=o(0)+v·k·dt`）。
Q 與 CBF 從此方向一致，不再對抗。

| 驗證 | 結果 |
|---|---|
| 只彎參考 → 離障礙中心最近 | **0.015 m（禁區內）** |
| 彎完再投影 → 離障礙中心最近 | **0.680 m（禁區外）** ✓ |
| 無動態障礙時投影不動參考 | 誤差 **0.00e+00** ✓ |
| 靜態牆點不投影（與牆的 CBF 可能互相矛盾）| 設計如此 |

開關：`DETOUR_CLEAR_REF=0` 可關閉。
`evaluation/test_detour.py` 19 項全過。

### C9. 速度下限是全部安全性損失的來源

`vx_floor` 是 `u_min[0]` 的**硬約束**，不是成本。當 CBF 需要減速到 0.10 m/s
以下才能維持間距時，**QP 沒有其他可行解，只能付鬆弛去違反 CBF**。
速度下限等於把安全控制器最主要的手段（減速）從解空間裡拿掉。

拿掉之後（第 5 輪 vs 第 4 輪）：

| | floor 0.10 | floor 0 |
|---|---|---|
| 平均淨距 | +0.001 | **+0.037** |
| 碰撞趟 | 5 | **2** |
| **折返/趟** | **4.4** | **4.1** ← 完全沒退 |
| solve ms | 2.80 | 2.51 |

**折返的改善完全來自「鎖定同倫類」，一點都不來自速度下限。**
solve 時間也從 +22% 降到 +5%，因為鬆弛不再頻繁啟動。

1. ~~撞牆~~ → 九次碰撞全是擦動態障礙（見上方更正）
2. ~~參考落在 CBF 禁區內~~ → 真的是問題，投影後最差趟 −0.525 → −0.040，但不是全部
3. ~~參考餘裕不足~~ → pad 0.05 → 0.18 反而更差（+0.011 → +0.001），**正是這個否證把矛頭指向 vx_floor**

## C7. 範化缺口 — 多障礙情形其實完全沒被測到

問「這能範化到各種動態障礙嗎」，先量涵蓋率。錐形視野（±30°、2.0 m）內
同時存在的動態障礙數，繞行組 10 趟共 20240 個控制幀：

|---|---|---|
| 0 | 18402 | 90.92% |
| **1** | **1820** | **8.99%** |
| **2** | **18** | **0.09%** |

**繞行作動的時間裡有 99% 只面對單一障礙。**
「折返 7.7→3.6」這個結果實質上只證明了**單一、慢速（0.13~0.15 m/s）、
正面來的往復障礙**這一種情況。順帶暴露兩個結構性缺陷：

### C7-1. `_side_free` 只檢查牆，不檢查其他動態障礙
閃避 A 可能直接轉進 B。已修：其他 mover 用**等速外推 1.5 s** 的預測位置一併檢查
（`side_clear_dyn = 0.38`，與動態 CBF margin 一致）；被繞的那顆用 `ignore` 排除，
因為它依定義在另一側，該次通過由 CBF 保護。

### C7-2. 障礙身分比對是壞的
`locked_id = id(blk)`，但障礙訊息的線格式是 `[x, y, r, vx, vy]`（stride 5）
**沒有 ID 欄位**，而節點每則訊息都重建 dict。實測 CPython 會回收位址再利用：

```
第1次 [...342080, ...377728, ...376192]
第2次 [...596736, ...377280, ...534656]
第3次 [...342080, ...377728, ...376192]   ← 與第1次相同
```

**每隔一次「碰巧」對上**，多障礙時還可能對上**錯的那一顆**。
目前被掩蓋，是因為 fallback 會重找錐形內最近的障礙，而 99% 的時間只有一顆。
已改為**位置關聯**（`assoc_gate = 0.5 m` 的最近鄰），這是在沒有 ID 的前提下
誠實可得的做法。

其中四項是先前完全沒測到的：

| 新測項 | 結果 |

| 第二顆 mover 停在偏好側 → 改走另一側 | ✓ |
| 第二顆 mover **即將**進入偏好側（現在還很空）→ 改走另一側 | ✓ |

`enable=False` 完全無作用）同樣全過。

### 仍未解決的範化限制
1. **只對正前方作動**：`_blocking` 要求 `fx > 0` 且在 ±30° 內。
   垂直高速穿越的障礙很晚才進錐形；從後方追上的永遠不觸發。
2. **速度尺度**：`trigger_range = 2.0 m` 是對 0.13 m/s 調的。
   換成行人 1.2 m/s 只剩約 1.7 s 反應時間。
3. **依賴全向底盤**：20 Hz、N=20、v_nom 0.30 → 時域 1.0 s ≈ 0.30 m 前進距離，
   拱形峰值在 ~0.15 m 處要求 0.35 m 側移 —— **那幾乎是純橫移**。
   差速底盤上這條參考追不動。
4. **`_side_free` 的牆感知範圍**：只看得到 tracker 發佈的牆點（機器人自身 +
   ±0.3 m 四探針、範圍 1.2 m、最多 4 點），即**貼在身側的牆**。
   看不到 1 m 外正前方的轉角。
5. **場景本身**：要證明多障礙可用，需要**雙障礙對向交會**的新場景，
   現有場景的四顆動態障礙彼此距離太遠。

## C10. 碰撞率的統計對照 — 更正兩個我先前的錯誤說法

問題起點：「為什麼每一組都有碰撞？之前 margin 0.38 不是都沒碰撞嗎？」

### 更正一：從來沒有零碰撞
第三次報告的 98% 那批（N=40）寫的是「碰撞 **1/40**」、「**零深撞**」——
零深撞不等於零碰撞。從 git 撈回該批原始 CSV（2026-06-30，N=35）：

```
34/35 到達 (97%)、碰撞 1
min 淨距 平均 +0.0275、中位 +0.0500、最差 −0.186
```

### 更正二：`dyn_obs_1 = 0.15` 不是碰撞增加的原因
我先前推論「0.15 比 0.13 難，所以碰撞變多」。**錯了 ——
98% 那批本來就是 0.15。** 該檔案的變更史只有：
0.15 →(7/29）→ 0.13 →(7/30 我改）→ 0.15 →（改回）→ 0.13。

`analyze.py` 的碰撞判定自 2026-06-02 未變，`clearance_source` 三批都是
`gt_pose+static`，所以可以直接比較。

### 統計檢定（Fisher exact 雙尾，對照 N=35）

| 配置 | 碰撞 | 率 | 95% CI | 淨距中位 | p |
|---|---|---|---|---|---|
| N=35 (06-30) 0.15 無繞行 | 1/35 | 3% | 1–15% | +0.050 | — |
| archive_w0 0.13 無繞行 | 1/10 | 10% | 2–40% | +0.034 | 0.399 |
| detour5 0.13 繞行+**徑向** | 2/10 | 20% | 6–51% | +0.040 | 0.119 |
| **alpha3p0 0.15 繞行+側向 α3.0** | **4/10** | 40% | 17–69% | **+0.000** | **0.006** |
| **alpha1p5 0.15 繞行+側向 α1.5** | **3/10** | 30% | 11–60% | +0.050 | **0.030** |

**基準與已驗證的繞行（徑向）和 98% 那批在統計上無差異。沒有退步。**
「以前沒碰撞」的印象，實際是「以前 1/35、後來 1/10，n=10 分不出來」。

**唯二顯著變差的兩組，共同點是側向投影**（C8 之後加的）。
速度、margin、繞行本身、α 都已排除：
98% 那批就是 0.15 + margin 0.38，徑向繞行 p=0.119，α 兩個值都變差。

### 機制上說得通
徑向投影把參考往**後**拉（機器人退開 → 安全但打結）；
側向投影把參考推到禁區**邊界上**再繞過去（貼著邊界走 → 順但容易擦）。
`clear_pad` 只有 0.05，所以側向版等於沿著 keep-out 邊界 5 cm 外繞行。

### 也要更正：margin 8 cm 不是「新問題」
`cbf_safe_margin = 0.38` → 目標淨距 0.63 − 0.55 = **8 cm**，
實測平均落在 3–4 cm。算術沒錯，但**它不是最近碰撞增加的原因** ——
margin 從頭到尾都是 0.38 而 98% 那批只有 1/35。
我把一個長期存在的設計特性誤當成新出現的問題。

### 結果 — 兩個假設都被否證，真正的答案是繞行本身

三組各 10 趟，全部 `dyn_obs_1 = 0.15`（與 1/35 那批相同）：

| 配置 | 到達 | 碰撞 | 平均淨距 | 中位 | 折返 | deg/m | p vs 1/35 |
|---|---|---|---|---|---|---|---|
| **全關（今日程式碼）** | 10/10 | **2** | **+0.036** | **+0.050** | 7.5 | 91.6 | **0.119** |
| 繞行 + 徑向 | 9/10 | 4 | −0.006 | +0.000 | 11.6 | 100.9 | 0.006 |
| 繞行 + 側向 | 10/10 | 5 | −0.011 | −0.016 | 5.6 | 87.6 | 0.001 |

**否證一：側向投影不是元兇。** 徑向 4/10、側向 5/10，無差異。
兩種機制完全不同的投影給出相同的碰撞率。

**否證二：基準沒有漂移。** 我懷疑 ROS 升級 / 手臂整合 / `gmpc.py` 的新程式路徑
讓 baseline 退步，所以補跑了這個對照。**淨距中位 +0.0500，與 2026-06-30 那批
完全相同**，p=0.119。程式碼沒有問題 —— 這個檢查做對了，但假設是錯的。

**真正的歸因：繞行整體讓淨距中位掉 5 cm**（+0.050 → +0.000 / −0.016）。
整個分佈本來就只離接觸邊界 5 cm（見 C10 的 margin 算術），所以這 5 cm
足以把一半的趟數推到負值。機制上合理：繞行的本質是「繞過去」而非
「讓開等待」，那必然選擇貼著障礙通過。

### 最重要的發現：繞行的效益對障礙速度高度敏感

| | dyn_obs_1 = 0.13 | dyn_obs_1 = 0.15 |
|---|---|---|
| 折返改善 | 7.7 → 4.1（**−47%**）| 7.5 → 5.6（−25%）|
| 淨距 | +0.030 → **+0.037（變好）** | +0.036 → **−0.011（崩掉）**|
| 結論 | 免費的午餐 | 用 2.5 倍碰撞換 25% 折返 |

**先前五輪驗證全部在 0.13 下進行，所以完全看不到這個代價。**
0.15 只是把週期從 19.6 s 縮到 17.0 s，機器人通過該段要十幾秒，
掉頭發生在閃避途中的機率大增 —— 徑向繞行的折返因此從 4.1 暴增到 11.6。

**對論文的意涵：不能只用單一場景宣稱繞行有效。** 定案配置的成果表必須
註明 `dyn_obs_1 = 0.13`，並把 0.15 的結果一併呈現為敏感度分析。

### 側向投影的價值仍然成立，只是換來的是平滑度不是安全性
0.15 下 徑向 → 側向：折返 11.6 → 5.6（−52%）、deg/m −13%、倒退 1.80% → 0.59%
（−67%，對應「參考不再被往後拉」）。碰撞則無差異。
**在 0.15 下徑向繞行比完全不繞行還糟 —— 折返、deg/m、碰撞三項全輸。**

### 方法學教訓：小樣本
今天有三次在小樣本上下了後來被推翻的結論：繞行 N=3 顯示折返 3.3（實為 4.1）、
`clear_pad` 假設、以及徑向組「前 5 趟 0 碰撞」（實為 4/10）。
碰撞率的真實值約 10–40%，n=10 的 95% CI 寬達 20–30 個百分點，
**連 N=10 都只能分辨「差很多」而非「差一點」**。

消融實驗因此應分兩層：平滑度指標（deg/m、折返，雜訊小）用 N=10 排序；
碰撞率只當「有沒有明顯崩壞」的守門員，不做細部比較 ——
48 組 × N=10 在多重比較下會產生大量假陽性。

# 方法命名（2026-07-31 定案）

## 控制器層

**全時域 CBF 幾何模型預測控制**
**Full-Horizon CBF Geometric MPC — FH-CBF-GMPC**

SE(2) 上的幾何 MPC（李群測地誤差），CBF 約束施加在 `k = 0…N` 的**每一步**、
對**預測的**障礙位置，而非只在當前步。

## 系統層

**時域匹配的非結構化環境動態避障**
**Horizon-Matched Navigation in Unstructured Environments**

核心論點：

> **障礙應交給「時域與其可預測性相符」的那一層處理。**
> 靜態幾何可預測無限久 → 全域規劃(秒~分鐘尺度)；
> 動態障礙只在約 1 秒內可信 → 只給 CBF，並從規劃器視野中移除。
> 把動態障礙餵給以 3 秒為週期重規劃的規劃器是**範疇錯誤** ——
> 機器人抵達時那份規劃早已過期。

架構：

```
時域匹配導航 (系統貢獻)
├─ 感知:動靜三分流 + 形狀感知群集(圓擬合 / 展開下限 / 多圓覆蓋)
├─ 規劃:Nav2 全域規劃,只看靜態幾何(/scan_filtered)
└─ 控制:FH-CBF-GMPC + S-curve 參考混合
```

## 支持「範疇錯誤」論點的量化證據

| 量測 | 數值 |
|---|---|
| 重規劃週期 | 3 s |
| 讓機器人前方 0–2 m 路徑橫移 >0.25 m 的比例 | **24%** |
| 該位移的 p90 / 最大 | 0.44 m / **1.82 m** |
| 參考朝向跳動 p90 / 最大 | 26° / **63°** |
| 大跳動後 0.3 s 內的平均 \|du/dt\|/a_max | **0.964** |
| 同期間加速度飽和佔比 | **88.5%**（其餘時間 13.5%）|

## 誠實的貢獻界定

| 組成 | 原創性 |
|---|---|
| SE(2) 幾何 MPC（李群測地誤差）| 既有（Lie-group MPC 文獻）|
| CBF 作為 QP 約束 | 既有（Ames et al.）|
| CBF 施加於整個預測時域 | 較少見但有（MPC-CBF, Zeng 2021）|
| **依可預測性把障礙分流到對應時域的層** | **本論文的系統貢獻** |

最強的宣稱在**架構**，不在控制器數學。

## 標籤對應

先前批次標籤 `plan3` = 架構完整啟用的配置，之後改稱 **`hm-full`**：

```
PLANNER_SCAN=/scan_filtered   動態障礙不進規劃器
PLAN_BLEND=1.0                S-curve 參考混合
CBF_ALPHA=1.5                 障壁提早溫和介入
（感知層的圓擬合 / 三分流 / 多圓覆蓋為預設行為，無開關）
```
