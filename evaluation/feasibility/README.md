# 離線可行性核對腳本

這些腳本產生 `evaluation/results/wgmpc_drawer_open_close.yaml` 的
`offline_feasibility_check` 區塊。**可重跑**，不依賴任何執行中的節點。

| 檔案 | 回答什麼 |
| --- | --- |
| `drawer_open_close_reach_boundary.py` | 固定底盤時 TCP 沿世界 y 的可達區間；接觸前暫停位姿是否就在邊界上 |
| `drawer_open_close_ik_sweep.py` | 夾持位姿與 0→200 mm 行程在「固定底盤」與「底盤參與」兩種情形下是否可達 |
| `drawer_open_close_motion_split.py` | 全身解把多少 TCP 位移分給底盤、多少給手臂；固定底盤從同一夾持位姿能開多遠 |

共同前提：姿態鎖 `R_DES`、TCP 高 0.55、判準與階段 A 相同
（位置 ≤5 mm、姿態 ≤0.02 rad、有效限位餘裕 >0、`joint_margin` 0.05）。
起點取 spawn 趟次**保持窗結束**的實測位姿。

**方法限制**：用的是阻尼最小平方 IK（多種子），只回答「存在解」與
「最小範數解怎麼分配」。它**不是** W-GMPC 的解 —— W-GMPC 有自己的代價
（`w_s`、`w_a`、分底盤／手臂的變化率權重），分配會不同。所以
`finding_4` 只能說「底盤主導解合法且存在」，不能說「W-GMPC 會那樣走」。
逐點自碰與屏障可行性**沒有核**，那要等接觸政策接好後實跑。

## 設計改版後新增（2026-10-03）

| 檔案 | 回答什麼 |
| --- | --- |
| `drawer_park_distance.py` | 底盤該停多近：掃停位，看手臂在整段行程裡的關節餘裕與離奇異點距離 |
| `drawer_hold_posture_and_stow.py` | 底盤 1 比 1 跟退時手臂是否全程維持同一好姿態；導航用的收攏姿態候選 |

**為什麼要改版**：原先把階段 A 結束時的底盤位姿當成給定條件，於是算出
「手臂伸到極限、夾持位伸不到」並當成限制。那是**停錯位置的症狀** ——
底盤能動，停位是設計變數。改停到 y=0.56（手臂伸 0.590 m）之後，底盤
1 比 1 跟退就讓手臂全程待在同一姿態、關節餘裕恆 +0.9072 rad。

`drawer_open_close_reach_boundary.py` 等三支仍然有效，但要讀成
「階段 A 那個停位的性質」，不是本實驗的停位。

## 速度：兩邊同時出力（2026-10-03 追加）

| 檔案 | 回答什麼 |
| --- | --- |
| `drawer_split_speed.py` | 手臂在夾持姿態下能貢獻多少 TCP 速度；把行程拆給兩邊後歷時變多少 |
| `drawer_speed_effort_tradeoff.py` | 快速 vs 省力的取捨曲線：各分擔比例下的歷時、手臂行程、關節餘裕、奇異值 |

**要修正的一個數字**：先前把單趟行程的歷時下界寫成 5.7 s，那是假設底盤
獨自走完 200 mm。兩邊同時動時 TCP 速度相加，下界由**底盤的分擔量**決定。
守住「底盤沿軸 ≥0.10 m」的閘門 ⇒ 下界是 **2.84 s**。

## 速度界限的兩層結構（2026-10-03 更正）

我曾寫「執行端沒查輪級、輪級正常輸出限制尚未實作」，**兩句都錯**。實際是：

1. `wheel_ok()` —— 低速介面界限（0.05 m/s），越界即**閂鎖**；
2. `limit9()` —— **再**施加輪速與輪加速度限制，以
   `u_out = u_prev + λ(u_req − u_prev)` 修改**完整九維增量**；
3. `_apply()` —— 用限制後的命令積分設定點、交付執行。

誤導我的是 E2 紀錄欄位 `wheel_level_note`（從舊檔帶來的過時字串，和同字典的
`wheel_level_limiting_implemented = True` 矛盾）與 `guards_not_started`
（那指兩個 **ROS 節點**沒起，檢查由 `CmdChain` 承接）。讀程式就能查清。

`drawer_split_speed.py` 末段的「底盤解到 N mm/s」是**算術推演,不是建議**。
本輪裁定暫不放寬速度框。另外那些上限只是**現有輪矩陣的本體座標可行上限**,
世界開抽屜方向要按底盤 yaw 換算(停位 yaw 1.2973 ⇒ 0.2882 m/s,不是 0.2775),
而且沒有證明馬達、負載與輪地接觸真能交付;`wheel_w_max = 5.55 rad/s` 仍缺
獨立來源。
