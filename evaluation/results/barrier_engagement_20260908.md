# 近障礙閉迴路屏障驗證（固定底盤、已知靜態場景）

日期：2026-09-08。世界 `arm_barrier_test.sdf`（單一靜態箱體 obs_0，世界位姿 0.74/0/0.60，
尺寸 0.40 × 1.00 × 1.20 m）。堆疊 `evaluation/barrier_stack.py`，驅動端
`evaluation/barrier_probe.py`，畫面 `evaluation/viz_barrier_live.py` ＋
`evaluation/foxglove_layout_barrier.json`。原始資料
`evaluation/results/barrier_probe_3phase.json`（458 週期）。

## 這是什麼、不是什麼

**是**：已知靜態場景、固定底盤（`fix_base:=true`，底盤三個速度在**求解中**限為零）下，
連桿屏障的閉迴路作用驗證。

**不是**：
- **不是感知驗證。** 障礙來自世界檔，是 ground truth；`require_occlusion_feed:=false`，
  沒有 self-filter 在跑。這輪對感知路徑什麼都沒說。
- **不是全身 GMPC 驗證。** 輸入命令由 probe 以阻尼最小平方產生，不是 MPC。
- **不是自碰撞驗證。** 迴路中沒有自碰撞約束。
- **不是加速度限制驗收。** 見 `actuation_selftest_20260908.md`。

## 第 0 步：先確認沒有 probe 時手臂保持停止

20 s 靜置量測：六軸位移 **0.00 µrad**、速度 **0.00 µrad/s**；控制器命令 958 則全為
**0.000**；安全節點 reason 全程為 1（無輸入命令），n_rows 0。閘門在無上游命令時送零，
手臂不動。

模型與 Gazebo 對齊：whole-body FK 算出的 TCP 世界座標與 Gazebo 的 TF 逐位吻合；獨立取樣
上界（節點線上算）與離線用同一姿態獨立重算的值同為 262.0 mm。

## 兩條界線與它們不對稱的證據力

- `min_d_model` = min(d − ρ)，屏障實際執行的量，是真實間距的**下界**。
- `clearance_ub` = 獨立隨機表面雲（seed 4242，屏障的取樣器沒用過）到箱體的最小距離，
  是真實間距的**上界**（在表面子集上取最小值只會偏大）。

`bound_violation = 下界 − 上界` **轉正**能證明距離模型或資料對齊有問題；**非正不能反過來
證明下界正確**，因為夾擠中間仍有空隙。下界的可信度來自 §10.11 的涵蓋半徑認證及其適用條件，
這張圖只是線上交叉檢查。

### 一個必須扣掉的量測偏差

兩者取樣率不同（下界約 60 Hz，上界 3 Hz），**運動中逐週期相比是不成立的**。上界被保留
`age` 秒期間，連桿以 v 移動，上界最多落後 `v·age`；後退時這使上界偏小。原始訊號因此出現
乾淨的鋸齒：每次上界更新跳到 −9.9 mm，保留 320 ms 後爬回 +9.95 mm ≈ 48 mm/s × 0.21 s。

扣掉 `實測 TCP 速度 × 上界陳舊時間` 後，三個相位共 458 週期中為正的有 0 個。

**但這只是誤差分析，不是嚴格的時間補償界。** 最近點可能落在任何一根連桿上，而**不同連桿的
速度不等於 TCP 速度**——旋轉時肘部或夾爪的線速度可以明顯大於或小於 TCP 的。以 TCP 速度乘上
年齡當補償量，沒有涵蓋這個差異。因此本輪的正式措辭是：

> 非同步比較，補償後未觀察到正值。

嚴格核對留待離線進行：以**同一份關節姿態與障礙物狀態**同時計算兩條界線，兩者之間沒有時間差，
比較才成立。不為此再擴充線上功能。

`viz` 已改為一併發布 `clearance_ub_age`，probe 一併記錄，避免日後再把這個鋸齒讀成發現。

## 第 1 步：低速接近（TCP 目標 50 mm/s）

起始姿態由 `--home 0 0 0.30 0 0 0` 伺服到位（殘差 9.8 mrad），不是沿用上一輪的結束姿態。

| 量 | 結果 |
| --- | --- |
| 模型下界 min(d−ρ) | 207.0 → **89.3 mm**，之後停住（最小 89.2） |
| 獨立上界 | 220.0 → 101.5 mm |
| 輸入違反屏障的週期 | **106 / 153**，最大 resid_in **+53.02 mm/s** |
| 輸出仍違反的週期 | **0 / 153**，最大 resid_out **−0.13 mm/s** |
| 作用列數 | 最大 48 |
| 命令 \|max\|（作用期間中位） | 0.2091 → 0.1688 rad/s（削減 19%） |
| **實測 TCP 速度**（TF 差分，非命令） | 未作用時 45.6 → 作用時 **35.3 mm/s** |
| bound_violation（扣偏差後） | 最大 −12.62 mm，正的週期 0 |

理論停距：$d_{stop} = d_0 + v\tau + v^2/2a + \varepsilon \approx 0.05 + 0.0075 + 0.03
\approx 88$ mm，與觀測到的 89 mm 平台一致。

### 快照（輸入違反 → 輸出滿足 → 實測速度下降的第一個週期）

resid_in **+20.88** → resid_out **−0.559 mm/s**，7 列作用，實測 TCP **38.8 mm/s**，
上界陳舊僅 18 ms。q = [0.0041, 0.3526, 0.7318, 0.0002, −0.1447, 0.0001]。

作用連桿：`uflite_gripper_link` 4 列、`uflite_finger1` 2 列、`uflite_finger2` 1 列，
法向全為 [1, 0, 0]（指向箱體前面）。最緊列 `uflite_finger1` d = 117.81 mm、ρ = 12.68 mm、
d − ρ = 105.14 mm。全部 15 欄逐列存在 JSON 的 `snapshot.rows`，供離線精確網格檢查使用。

## 第 2 步：切向與後退對照

| 相位 | 輸入違反週期 | 命令 \|max\| 入 → 出 | 模型下界 | 實測 TCP |
| --- | ---: | --- | --- | ---: |
| 切向（+y） | **0 / 152** | 0.1581 → 0.1578 rad/s | 89.3 → 90.9 mm（最小 85.6） | 47.9 mm/s |
| 後退（−x） | **0 / 153** | 0.1335 → 0.1335 rad/s | 91.7 → 354.3 mm | 48.6 mm/s |

兩個相位都**沒有任何一列被違反**，命令未被修改。切向相位維持在箱體前面範圍內
（8 s × 50 mm/s = 0.4 m < 半寬 0.5 m），距離近乎不變而屏障不作用，與「屏障約束的是接近率
$n^TJv$ 而非距離本身」一致。後退相位屏障完全不介入。

依審查意見，這裡**不作歸因**：兩者都沒有被修改，所以沒有需要歸因的對象；這只說明在這組
軌跡上沒有出現非接近方向被誤擋的情形，不等於已排除任何特定機制。

## 過程中發現並修正的三個缺陷

1. **實測 TCP 速度原本是假的。** 以 wall-clock 差分 TF 查詢結果，得到的是「probe 多久轉一次
   executor」而不是「手臂多快」：相鄰查詢回傳同一份快取（速度 0），累積後跳成 300 mm/s。
   改為用**transform 自己的時間戳**差分，並在整個週期持續 spin 而不是每週期只 spin 一次。
   修正後量到 48.6 / 50.0 mm/s，與目標一致。

2. **開迴路後退不是回到起始姿態的方法。** TCP 越過肩部後，阻尼逆解會把 joint1 整個繞過去；
   三次這樣的復位把手臂帶到 joint1 = 2.50 rad，背對箱體，此時離箱體最近的是**固定底座**，
   回報間距變成一個手臂動作改變不了的常數 354.3 mm。改為 `--home` 以 P 控制伺服到指定關節
   角，命令一樣經過 cmd_in，屏障對回位動作同樣生效。

3. **`ros2 run` 的孫程序在收拾時活了下來。** `ros2 run X Y` 執行的是包裝器，真正的節點是
   孫程序；只對包裝器送訊號會留下節點繼續執行。三次重啟累積出**六個約 80% CPU 的孤兒節點**，
   全部還在同樣的 topic 上發布：load average 19、`/joint_states` 出現 337 ms 空隙、每個安全
   topic 上有四個發布者。**因此在此之前的所有屏障數字都已作廢並重跑**，本檔所有數值均取自
   確認過「每種節點各一個、cmd_out 與 points 各只有一個發布者」的乾淨圖。堆疊改為每個子程序
   自成 process group、以群組收訊號，並在結束時查核殘留（現在會印「所有程序群組已結束」）。

清理後 `/joint_states` 126.8 Hz、間隔中位 7.0 ms、p99 7.5 ms、最大 16.3 ms，超過 300 ms
的空隙 0 個。

## 附錄：測試起始姿態的精確自碰撞間距

以 `evaluation/mesh_distance.py` 做三角面對三角面的精確檢查（非取樣），排除相鄰連桿與
夾爪／雙指互相配對後共 35 組：

| 姿態 | 最小自碰撞間距 | 配對 | 相交 | 至箱體（獨立取樣上界） | 耗時 |
| --- | ---: | --- | ---: | ---: | ---: |
| j3 = +0.1494 | 7.306 mm | link4 ↔ link6 | 0 | 262.0 mm | 230 s |
| **j3 = +0.3000（本輪起始）** | **7.306 mm** | link4 ↔ link6 | 0 | 222.7 mm | 421 s |

兩者相同並非巧合：joint4/5/6 均為零，link4 與 link6 的相對位姿與 joint3 無關。

7.306 mm 的正確讀法只有一句：

> 本次起始姿態、目前碰撞配對清單下的最小幾何間距。

**link4 ↔ link6 保留在清單裡。** 沒有機構依據之前，不因為它成了最近配對就把它排除掉——那是
先看答案再改題目。

**不能拿它跟 §10.12 的 8.792 mm 比。** 那是全零姿態、另一組排除集合；本次是 joint3 = 0.30、
本節的排除集合。**姿態與排除集合都不同，兩個數字不能拿來判斷哪個姿態更安全。**

另外，本輪迴路中沒有自碰撞約束，這個數字只描述起始姿態，不涵蓋測試過程中經過的姿態。
