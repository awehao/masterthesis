## 三、計時：QP 不是瓶頸，迴圈結構才是

| 量 | p50 | p95 | max |
| --- | ---: | ---: | ---: |
| QP 求解 | 2.06 ms | 5.91 ms | 15.58 ms |
| 整體 `solve()`（重建約束＋QP） | 10.18 ms | 14.62 ms | 24.69 ms |
| **實際發布間隔** | **61.19 ms** | **65.37 ms** | **74.86 ms** |
| 其餘（drain 迴圈＋guard＋TF 量測＋記錄） | 50.85 ms | — | 52.28 ms |

**標稱週期 50 ms，超時比例 100%。**

歸因明確：驅動迴圈**先 drain 滿一個標稱週期（50 ms）再做事**，所以實際週期恆為
「50 ms ＋ 工作量」，工作量中位約 11 ms。**超時來自 harness 的迴圈結構，不是 QP**——QP p95
5.9 ms、整體求解 p95 14.6 ms，兩者都塞得進 50 ms。

**因此目前不能宣稱滿足即時控制。** 修法在迴圈（drain 應為 `週期 − 工作量`，或改用固定週期
timer），不在求解器。迭代峰值（先前記錄 4100–25900）**不是排程指標**，不能用來論證是否超時。

## 四、舊求解器設定的失敗：另列為數值診斷，不屬 μ 掃描結論

先前以 `eps = 1e-7`、`max_iter = 8000`、`polish = False` 執行時，μ = 1.0 / 0.3 / 0.1 皆以
「QP 求解未收斂」被 fail closed 中止。離線在同一狀態上比較設定後確認那是**數值問題**：相同問題
在 `eps = 1e-6` 下最多 2575 次迭代即收斂。**該批失敗不構成 μ 的性質**，已與掃描結論分開記錄。

新設定下的掃描仍是單變數實驗（只改 μ，`kp_p`／`kp_r` 不動）。

## 五、後續比較的規則

W-GMPC 以**本基線（B, μ = 0.03）為主要比較對象**；A（任務求解 → 投影）保留為**架構分離的消融
對照**。比較時必須統一：任務容差、硬體與碰撞限制、**實際使用的下游濾波器**、計算預算。

## 六、已知限制（保留，不阻擋移植）

- 成功的是**實測的 μ = 0.03 與 0 兩點**，不能推論整個 μ ≤ 0.03 區間。
- 單一障礙位置、單一目標、單一起點；靜態已知場景，不涉感知。
- **控制週期 100% 超時**（原因已定位在迴圈結構，未修）。
- μ = 0.1 的停滯機制未單獨分析（只知它停在 24.6 mm 達 37 秒）。
- **關節精確觸及 URDF 上限後無法退出**，底層原因未定位；已加 0.02 rad 保守裕度迴避。
- 下游濾波器修改量僅有**尾段**中位（5.8e−4 至 5.9e−3）可述；全程最大曾達 0.99920（第 0 週期）。
- Gazebo 以 `VelocityControl` 直接寫入速度，**停止距離不可沿用至 Isaac Sim 或實機**。
