# Isaac Sim Gate 0：純底盤幾何、根部與關節清單

日期：2026-09-09　模擬器：Isaac Sim 6.0.1（RTX 5070，GPU 37–39 °C）
腳本：`evaluation/isaac_base_check.py --gate 0`
輸入：`/tmp/omni_bot_base.urdf`（93 links／92 joints，全部 fixed）
紀錄：`evaluation/results/isaac_base_gate0.json`

## 匯入過程中必須修正的三處（否則量到的是錯的東西）

1. **變體選擇懸空**。URDF importer 產生的根層寫 `variants = {string Physics = "physx"}`，
   但變體集只定義 `"none"` 與 `"physics"`。選擇對不上就什麼都不組合，stage 上只有幾何、
   完全沒有物理，之後表現為 `Pattern '/World/omni_bot' did not match any articulations`。
   這句錯誤看起來像「模型沒有物理」，實際上是選擇字串打錯。腳本現在明確選 `physics`。
2. **instancing 擋住走訪**。link 子樹被標記 `instanceable`，`stage.Traverse()` 遇到 instance
   不會下探，只掃到 5 個 link 的視覺件。必須用 `Usd.TraverseInstanceProxies`（→ 78 個）。
3. **碰撞幾何 purpose = "guide"**。預設 bbox cache 不含 guide，`ComputeWorldBound` 回傳空範圍，
   7 個碰撞體在分類前就被過濾掉，一度誤報「沒有碰撞幾何」。需另建含 guide/proxy 的 cache。

要點：

- 視覺件的 x/y 最大半寬由 base_link 的 0.300 決定；滾輪最遠 0.264，**沒有任何視覺件超出底盤圓柱半徑**。
  （早先報過 0.4243，那是 AABB 角點距離，對圓柱會高估到 √2 R；已改報 x/y 半寬。）
- 四顆支撐球最低點 z = 0.0000，如設計般接地；視覺件最低點 +0.9 mm（滾輪懸空 0.9 mm，純視覺不接地）。
- **碰撞 AABB 比視覺 AABB 高 45 mm**：相機碰撞盒頂 0.375 高於視覺頂 0.330。這來自 URDF 本身，
  不是匯入誤差，但在檢查「是否撞到上方物體」時要以 0.375 為準。

## 根部

- ArticulationRootAPI：`/World/omni_bot/Geometry/base_footprint`（唯一一個）
- 位姿 p = (0.0000, 0.0000, 0.0000)，姿態 q(w,x,y,z) = (1, 0, 0, 0)
- 速度命令將施加於此 prim

## 關節與剛體清單

- USD：84 個 RigidBodyAPI、83 個 PhysicsFixedJoint、`num_dof = 0`
- URDF：93 links、92 joints（全 fixed）
- 差 9 個：URDF 中有 10 個既無視覺也無碰撞的座標框（`base_camera_depth_frame`、
  `base_camera_*_optical_frame` 等），除根 `base_footprint` 外全被匯入器併除。
  純底盤運動測試不受影響；**但這些相機座標框在 USD 裡不存在 prim**，
  之後要接相機時不能假設可以直接用 URDF 的 frame 名稱定位。
- `num_dof = 0` 是預期的：底盤沒有可動關節，唯一的自由度是浮動基座的 6 DOF。
  它是單連桿 articulation，不是裸剛體——先前「全 fixed 所以沒有 articulation」的推論是錯的，
  物理一直都在，只是變體選擇懸空沒被組合進來。

## 結論

Gate 0 通過：幾何與 URDF 一致（底盤圓柱誤差 0.00 mm），根部唯一且位於原點，關節清單差異已完全解釋。
可以進 Gate 1，並把 `hold／once`（速度狀態的施加方式）與 `zero／silence`（停止方式）當作兩個獨立維度。
