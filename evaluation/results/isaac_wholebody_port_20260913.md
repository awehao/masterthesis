## 3. frame 接線：已修正並驗證

原本打算直接發 `odom → base_link`，**那是錯的**：

* 模型鏈是 `odom → base_footprint → base_link`，
  `base_footprint → base_link` 是 URDF 的固定 **+0.05 m**。
  另發 `odom → base_link` 會讓同一個 child 有兩個父節點。
* **兩份 URDF 用途不同，不可互換**：
  `omni_bot_manip.urdf`（根 `base_footprint`）給 robot_state_publisher 發 TF；
  `omni_bot_wholebody_expanded.urdf`（根 `world → virtual_base → base_x/y/theta`，
  底盤是**真實關節**）只當距離／安全節點的 FK **參數**。
  我一開始把全身版拿去發 TF，根本結構就不同。

`/lite6_vel_controller`**（Gazebo 行為不變）；Isaac runner 明確指定
`/isaac_wholebody_sim`。核對對象因此是**真的會執行這些數字的那一端**。

三處共用 —— `joints` 參數回報、六個速度分量的積分、articulation 的 DOF 索引

目的：分清「讀錯位置」與「底盤確實沒有按命令走」。

### 9.1 同步記錄的三路

| 欄位 | 來源 |
|---|---|
| `sent_prev_vwx/vwy/wz` | **上一步實際傳進** `set_linear_velocity`／`set_angular_velocity` 的世界速度 |
| `phys_x/y`、`phys_vx/vy` | 下一物理步後 PhysX 經 articulation 回報的位置／速度 |
| `usd_x/y` | 同步的 USD `base_footprint` 位姿 |

迴圈順序是「物理步進 → 讀量測 → 套用新命令」，所以同一列的量測是**上一列命令**
的結果；`sent_prev_*` 在套用新命令**之前**先存下，就是為了讓 log 逐列對得上。

### 9.2 位姿來源：交叉一致，**不是三個獨立證據**

`SingleArticulation` 的 `prim_path` 從寫死的 `/World/omni_bot` 改為
**搜尋到的 articulation root** `/World/omni_bot/Geometry/base_footprint`
（與導航版 `isaac_bigarena_sim.py` 一致，用 `isaac_common.physics_parts`）。

**實際只有兩個來源**，記錄時要說清楚：

| log 欄位 | 來源 |
|---|---|
| `phys_x/y` | `robot.get_world_pose()`（articulation root） |
| `usd_x/y` | `XformCache` 取 `base_footprint` prim 的世界變換 |
| `base_x/y` | **與 `usd_x/y` 同一個運算式**（`isaac_wholebody_sim.py` 同時寫入 `bp[0], bp[1]`） |

| 比較 | 最大差 | 說明 |
|---|---|---|
| 物理端 vs USD `base_footprint` | 0.000000000 m | **本趟唯一實質比較** |
| ~~USD vs 送交 TF 的 `base_x/y`~~ | ~~0.000000000 m~~ | **恆等式**，同一變數寫兩次，不構成證據 |

因此本趟能說的是：**物理端回報的位置與 USD `base_footprint` 的世界變換一致**。
TF 本就取用同一份 USD 位姿，相同是預期結果。
**不宣稱**「不存在讀錯位置的空間」—— 先前這樣寫是過度推論。

> **已知記錄缺陷（不改本基線）**：`usd_*` 與 `base_*` 欄位重複，
> 容易被誤讀成兩個獨立來源。凍結基線不動，待 log schema 下次變更時一併修。

### 18.1 撤回什麼

初版把「覆蓋連桿幾何所需的半徑 ρ」當成「還可以額外移動的空間」。**那是錯的。**
ρ 已經花在覆蓋幾何上，不能再花第二次：

    幾何淨距下界      d_lower     = d − ρ
    再移動 δ 之後     d_lower,new ≥ d − ρ − δ    （靜態障礙物、δ 為有效位移上界）

所以 **δ < ρ 不代表安全**；要比較的是扣除覆蓋半徑與其他保留量之後的
**剩餘淨距**，不是 ρ 本身。

一併撤回：**單一位形、有限取樣點的 Jacobian 最大值，
不能直接稱為整個連桿、整段停止路徑的位移上界。**

## 34. 手臂命令衰減的離線定位 —— **根因已重現**

**先更正我的說法**：§32.4 我寫「中間話題本趟未記錄」是**錯的**。
`solver_out.json` 逐週期同時記錄了 `cmd_in` 與求解器收到的 `cmd_out`，
不需要新增趟次就能分析。

同時收窄 §32.4 的因果宣稱：已量到連續同動 16.19 s，**不能說手臂完全沒動**；
單筆 0.9 rad/s 也**不能**直接除以 34 s 的設定點增量而宣稱全程固定 100 倍衰減。

### 34.1 既有資料的分項分析

`cmd_in`／`cmd_out` 是求解器**當次發布**與**最近收到**的兩欄，
**沒有來源序號逐筆配對**，所以逐週期比值**不是**精確的單筆衰減倍率。

| 分量 | `cmd_in` \|max\| | `cmd_out` \|max\| | 同號比例 |
|---|---|---|---|
| vx / vy / wz | 0.035255 / 0.001973 / 0.001321 | **完全相同** | 100 % |
| dq1 / dq4 / dq6 | 0.000622 / 0.000177 / 0.000234 | **完全相同** | ~100 % |
| **dq2** | 0.983780 | **0.020900** | **16.9 %** |
| **dq3** | 0.999900 | **0.024771** | 100 % |
| **dq5** | 0.999900 | **0.024771** | 100 % |

**不需要配對的證據**：`cmd_out` 序列**自身**的逐週期變化量，
手臂分量中位 **2.4e-5**、p95 2.7e-4、max 1.09e-3 rad/s。
全程 `n_bar_rows = 0`、`n_binding = 0`、`resid_in = resid_out = 0`、
QP 680/680 收斂、0 次失敗。

### 34.2 離線與線上的輸入差異 —— **這就是根因**

離線核對餵給濾波器的是**空點集合**；線上是距離節點產生的
**11 列 `STATUS_NODATA`**。兩者不等價：

| 濾波器輸入 | 障壁列 | **速度上限 `cap`** |
|---|---|---|
| 離線：空點集合 | 0 | **inf**（無上限） |
| 線上：11 列 NODATA | 0 | **0.05** |

`_box_rows` 取 `vmax = min(cfg.vmax, cap)`，所以 `cap = 0.05`
會把**整個 9 維速度框**壓到 0.05（線速度 m/s、角速度與關節 rad/s）。

### 34.3 重播既有濾波函式：**精確重現**

用該週期記錄的 `q`、`base`、`v_prev`、`v_prev2`、`dt`，
呼叫**既有** `filter_velocity`（不調參數、不關保護）：

| 情境 | dq2 | dq3 | dq5 | 與觀測差 |
|---|---|---|---|---|
| **觀測 `cmd_out`** | −0.003555 | +0.000683 | −0.004541 | — |
| 空點集合 ＋ 標稱 dt | +0.881924 | +0.899576 | −0.915643 | 0.911102 |
| **11 列 NODATA ＋ 標稱 dt** | **−0.003555** | **+0.000683** | **−0.004541** | **0.000000** |

**線上輸入重現到小數第六位。** 空點集合則完全不衰減
（該狀態下 v_in 不違反任何一類約束：障壁 0 列、關節限位 0 違反、
速度／加速度框 0 違反、jerk 0 違反）。

> **根因**：自由空間下距離節點對每個連桿產生 `STATUS_NODATA` 列，

> 那是**退化**而且**並不保守** —— 量測到 6 s 中斷期間底盤命令中位數
