# PARK_HOLD v2.1：運動中偏移觀測（候選修正）

日期：2026-10-05。依 Codex `reviews/20261005_125840_reply.md`。**v2 規格、程式、凍結與 `ph_func_H／ph_func_M` 結果原樣保留**；v2.1 是看過 v2 功能確認後的候選修正，
改的是共用的手臂偏移估計器（閉迴路行為），所以另立版本，兩組（PARK_HOLD 與 MOTM）共同啟用。

## 為什麼（候選，未證實為根因）

`park_hold_grip_diagnosis.yaml`：既有估計只在「設定點每輪變化 < 2 mrad」時更新；PARK_HOLD 手臂獨自收回 200 mm，OPEN 期間只 1.5% 週期可更新（MOTM 56%）。
同期 PARK_HOLD 的雙指承載逐漸不對稱。**移動中的 q−s 含正常追蹤落後**，不能直接當「實際下垂」；以模型一致的速度補償粗算，j3 殘差相對 d̂ 約 −0.5～−2 mrad。

## 觀測式（逐軸，與現有離散模型一致）

模型：q⁺ = q + α(s − q) + α d、s⁺ = s + dt_p·ṡ ⇒ 等速穩態 q − s = d − (dt_p/α)·ṡ ⇒

    d_obs = (q − s) + (dt_p/α)·ṡ           （α ≈ 0.095、dt_p = 0.01 s ⇒ 係數約 0.105 s）

- ṡ 由**同步量測**的設定點與其**實際模擬時間差**計算（不用求解請求）。
- 等速判定（事前固定）：窗口 0.30 s（≈ 3 × 0.105 s）、窗內 ≥ 5 個 ṡ 樣本、各軸 |ṡ_k − 窗均值| ≤ 0.01 rad/s（ṡ 偏差的補償誤差 ≈ 1 mrad）。
  **實作容差（揭露）**：程式以「窗口跨度 ≥ 0.30 − 0.06 = 0.24 s」判定窗口已滿（容許一個控制週期的取樣抖動），不是一律要求完整 0.30 s；
  功能確認兩趟實際採用的運動中更新窗口跨度均約 0.30 s。不改程式、不重跑（Codex 20261005_131146）。
- 缺資料、時間不前進、非有限、形狀錯 ⇒ 不給觀測。
- 既有靜止門檻路徑**完全不變**；只在它不成立且等速判定成立時用 d_obs 更新（同一濾波 dt/τ、同一限幅）。
- 逐輪記錄 ṡ、窗口判定、d_obs、更新路徑（static／moving／none）、更新後 d̂；求解輸入的 arm_bias 照舊逐輪保存（重播還原）。

## 介面

求解節點 `--offset-moving`（需 setpoint 模型＋offset-free；預設關）；運行器 `OFFSET_MOVING=1`。

## 離線核對（既有資料，不開模擬）

`test_offset_moving.py` 12/12（靜止、正／負等速＝合成真值 20 mrad；舊係數 0.095 s 會偏 1 mrad；加速暫態與線性減速窗內不給觀測；非有限／時間不前進／形狀錯／窗未滿）。
以既有實錄回放觀測器：PARK_HOLD（ph_func_H）OPEN 期間 42% 週期給出觀測（j2 d_obs 20.1–25.5 mrad，原凍結 d̂ 25.73；j3 −12.4～−9.5，原 −9.65）；
MOTM（ph_func_M）OPEN 期間 1%（多數已走靜止路徑）。這只說明觀測可取得，不預測閉迴路結果。

## 功能確認（審後）

新開發版凍結後，PARK_HOLD＋MOTM 各一趟（兩組都帶 OFFSET_MOVING=1）。仍要求原停車模式判準與 S1–S6；另報雙指承載、力峰值、漂移、底盤逐步速度、
運動中更新次數。仍違規 ⇒ 停下回報，不再調參。通過也只稱「候選修正有效」，不宣布偏移估計是根因。
