# 最小配對診斷：Gazebo 對 Isaac，同一案例的真值分歧

日期：2026-09-09　案例：`gmpc_cbf` seed 0，250 s，目標 (17, 17)，初始定位 (0,0)
資料：`evaluation/bags/gz_gmpc_cbf__seed0`、`evaluation/bags/isaac_gmpc_cbf__seed0`
工具：`evaluation/diagnose_divergence.py`　CPU 全程 ≤79 °C

## 〇、先補上 Gazebo 的機器人真值

Gazebo 以前沒有機器人真值位姿，所以 `/odom`（由 `/cmd_vel` 積分）沒有任何可對照的對象。
在 `ammr_base.urdf.xacro` 加上 `PosePublisher`（**純輸出**，20 Hz，與動態障礙物用的同一個外掛），
發布 `/model/ammr_base/pose`——與 `isaac_bench_sim.py` 相同的 topic，因此同一份分析可讀兩邊。
它只發布，不改動力學、接觸或控制路徑。

先試過場景廣播器的 `dynamic_pose/info`：**不可用**。ros_gz 的 `Pose_V → TFMessage`
轉換是從每個 pose 的 header data 取 frame 名稱，而廣播器沒有設定該欄位，
所以雖然 gz 原始訊息裡有 `name`，橋接出來的 frame id 全是空字串。

## 一、四條資料都已同步記錄

真值、命令積分 `/odom`、AMCL 位姿、實際命令 `/cmd_vel`，加上 `/scan`、`/tf`、`/tf_static`
與各自時間戳，兩邊皆同。

## 二、依序檢查（先座標系，再幾何，再時序，最後接觸）

| 檢查 | Gazebo | Isaac |
| --- | --- | --- |
| 前 60 s \|amcl − truth\| 中位 | 66.6 mm | 0.6 mm |
| → `map` 與模擬器 world | 視為同一座標系 | 視為同一座標系 |
| 雷射對真值幾何 中位殘差 | **−0.2 mm** | **+0.5 mm** |
| 動態障礙位姿間隔 | 50.0 ms（最大 50.0） | 50.0 ms（最大 50.0） |
| 最小間距（含動態物） | 0.240 m | 0.240 m |
| 低於內接半徑 0.200 m（**必定接觸**） | **0 / 4142** | **0 / 5856** |
| 低於外接半徑 0.283 m（可能角接觸） | 62 / 4142 | 586 / 5856 |

座標系、雷射幾何、障礙更新時序三項**在兩邊都乾淨**，可以排除。
雷射殘差是對真值幾何逐束比對算出來的，**Isaac 的 PhysX raycast 通過了 Gazebo 通過的同一項檢查**。

## 三、首次分歧：**兩個模擬器都會分歧**

| | Gazebo | Isaac |
| --- | ---: | ---: |
| truth vs `/odom` 首次持續分歧 | t = **195.37 s** | t = **164.76 s** |
| truth vs AMCL 首次持續分歧 | t = **199.32 s** | t = **161.76 s** |
| 分歧前 \|truth − odom\| 中位 | **4.2 mm** | **0.6 mm** |
| map→odom 修正量最大 | 3.46 m、yaw 10.82° | **31.02 m、yaw 175.33°** |

兩點結論：

1. **分歧不是 Isaac 特有的。** Gazebo 同案例也分歧，只是晚了約 30 s 且幅度小很多。
2. **`/odom` 在分歧前非常準**（Gazebo 4.2 mm、Isaac 0.6 mm 中位）。
   因此先前那個「`/odom` 路徑長度高估 +7.6%」**完全來自分歧之後**，
   不是 `/odom` 的系統性偏差。我先前的敘述給人「命令積分本身不準」的印象，這裡更正：
   命令積分在定位正常時與真值一致到毫米級。

   **但「命令積分誤差變大是 AMCL 分歧造成的」這句話目前沒有證據。** 兩者可能互相影響
   （定位壞掉 → 控制器下錯命令 → 機器人實際走位改變 → 命令積分與真值差更大），
   也可能有共同原因。本輪**只記錄先後關係**：
   Gazebo 是 odom 先（195.37）、AMCL 後（199.32）；Isaac 是 AMCL 先（161.76）、odom 後（164.76）。
   兩邊先後次序相反，這本身就說明不能直接推定因果方向。

## 四、機制線索（尚未定案）

以真值位姿計算「比地圖預期更短的雷射回波」比例：

| | 分歧前 中位 | 分歧後 中位 | 全程最大 |
| --- | ---: | ---: | ---: |
| Gazebo | 10.5% | 4.5% | 26% |
| Isaac | 10.1% | 49.4% | 66% |

**分歧前兩邊幾乎相同（10.1% 對 10.5%）**，代表分歧前的雷射環境沒有差別。

Isaac 首次分歧當下（t=161.76）最近的物體是 **`dyn_obs_2`，距離 0.261 m，且不在地圖裡**；
同一時刻未建圖回波比例衝到 66%。Gazebo 首次分歧當下最近的三個物體
（`obs_14` 0.982 m、`obs_15` 1.066 m、`obs_17` 1.519 m）**全在地圖內**，全程最大也只有 26%。

可能的機制是：以 0.26 m 掠過一個未建圖的移動圓柱時，該物體占據大量光束，
AMCL 的掃描匹配被拉走。**但這只是與時間戳對上的線索，還不是證明**——
還沒有量 AMCL 內部的匹配品質或粒子分佈。

## 五、這次配對的限制：**兩趟不是同一個情境實例**

`dynamic_obstacle_driver` 依回授位姿做 ping-pong，是閉迴路且**沒有種子**，
相位由節點啟動時刻決定。實測同一 sim 時間下兩趟的障礙物位置差：

| dyn_obs_0 | dyn_obs_1 | dyn_obs_2 | dyn_obs_5 |
| ---: | ---: | ---: | ---: |
| 0.17–2.43 m | 1.09–1.86 m | 0.11–0.62 m | 0.39–1.01 m |

因此 **兩趟的結果差異不能歸因於模擬器**：Isaac 遇到的 0.26 m 近距掠過，
這趟 Gazebo 根本沒有遇到。要做真正的配對，必須先讓障礙物相位可重現
（例如改以模擬時間為基準推算位置），那是對節點的功能變更，須另記。

## 六、仍未解釋的一項

Isaac 那趟真值/命令速度比的 p05 = 0.35。低比值樣本的命令變化量沒有比較大
（中位 0.0070 對其餘 0.0113 m/s），所以命令跳變的暫態解釋不成立。

**但接觸尚未排除。** 內接圓判準只能排除「圓心進入障礙物 0.200 m 內」這一類接觸；
底盤是 0.4×0.4 的方形，角點可及 0.283 m，兩個半徑之間的樣本
（Gazebo 62 個、Isaac 586 個）**仍可能是角接觸**。因此不能把低速度比標成「既非接觸」，
只能說：**沒有內接圓判準能確認的接觸，角接觸仍在候選之中。**
`isaac_bench_sim.py` 現在會記錄速度狀態（`vx_meas`／`wz_meas`），
下次重跑可以判斷這是 20 Hz 位置差分的量測假象，還是真的執行不足。

## 七、結論與下一步

- 座標系、雷射幾何、障礙更新時序：**兩邊都排除**。
- 接觸：**尚未排除**。只排除了內接圓判準能確認的接觸（兩邊皆 0 個樣本侵入），
  可能的角接觸仍在（Gazebo 62、Isaac 586 個樣本落在內接與外接半徑之間）。
  先前用速度比 p05 推測「期間確有接觸」的講法不成立，已撤回；
  但反過來標成「既非接觸」同樣沒有依據。
- 分歧：**兩個模擬器都會發生**，Isaac 較早且幅度大很多。
- **在障礙物相位可重現之前，不能宣稱移植重現基線，也不能宣稱 Isaac 較差。**
- 下一步應先讓情境可重現，再重跑這一組配對；實驗組維持不開。
