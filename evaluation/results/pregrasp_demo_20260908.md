## 過程中修掉的兩件事

### 螢幕錄影無法在這台機器上安全使用（重要）

前兩次錄影用 ffmpeg 的 x11grab 抓 Gazebo 視窗所在的**螢幕區域**。x11grab 抓的是該區域被合成
出來的畫面，不是視窗自己的內容，所以只要有別的視窗蓋在前面，錄到的就是那個視窗。**兩次都
錄到使用者的私人瀏覽器頁面**（一次是含學號、姓名與住址的註冊費頁面）。檔案已刪除；經確認
**沒有進入任何 git 提交，也沒有推上遠端**（最後一次 auto-commit 在影片產生之前）。

改為在世界檔中放一顆 `demo_camera` 相機感測器，橋接 `/demo_cam` 後由
`evaluation/record_gz_camera.py` 把影像逐幀送進 ffmpeg。**相機感測器只可能看到模擬場景**，
這是結構上的保證，不是操作上的小心。日後任何需要畫面的工作都走這條路，不再抓螢幕。

### `arm_barrier_test.launch.py` 少了 `GZ_SIM_SYSTEM_PLUGIN_PATH`

`gz_ros2_control-system` 只會從這個路徑載入。這個 launch 一直缺它，之所以能跑，是因為最初
啟動它的那個 shell 已經 export 過。從乾淨環境啟動時 plugin 被靜默略過、controller_manager
從不出現、每個 spawner 重試到放棄，而且沒有控制器抓住關節，手臂會直接在重力下垮下來。已比照
`omni_bot_arm.launch.py` 補上。
