# K3-M：底盤可動的小角度協同開門（規格 draft-1＋離線核對；不開模擬）

依 Codex 20261023_200048：固定底盤的補償／調參支線不再擴張，轉入「底盤可動的小角度協同開門」。
本規格只送**規格＋離線核對**，不實作、不開跑。

**定位**
- 先驗證「**邊移動邊開門**」：W-GMPC 同時使用底盤與手臂，在維持把手接觸下開到小角度。
- 不等同「持續抓持並穿過門洞」（門向機器人側拉開，門扇會掃進機器人所在空間，穿門路徑另議）。
- 不預先宣稱底盤可動就能解決 finger1 卸載；固定底盤 K3-A 的成功也不作為本規格的前提。

## 1. 控制結構（W-GMPC 共同使用底盤 3＋手臂 6 自由度）
- **求解器**：沿用 K3-A INT EV 跑法（`run_door_k3a_int_ev.sh`）的求解節點與參數，唯一差異是**不帶 `--park-hold`**。
  - 整個時域的底盤三軸由 W-GMPC 決定，不加 base_fixed／base_hold 等式。
  - 速度框（底盤 lin 0.035255 m/s、ang 0.1999 rad/s、手臂 0.9999 rad/s）、加速度框、輪級限制、低速介面閂鎖（lin 0.05、ang 0.20）全部照舊。
- **門角**：仍由被動接觸產生；執行端從不對門關節下命令（沿用 K2／K3 執行端）。
- **控制權只有一個來源**：
  - 轉交前：導航側保持靜止，停車閘門（`/park/gate`）通過後才轉交，這部分沿用 PARK_HOLD 的閘門；
  - 轉交後：底盤與手臂命令都只來自 W-GMPC → adapter → 命令鏈 E2；
  - **不啟用停車伺服**：求解器不帶 `--park-hold`，執行端不再核「套用命令 ≤ 停車伺服上界」（HoldMonitor 停用），兩者不會互相對抗；
  - 執行端改以被動的**底盤包絡監看**（§4）取代保持監看。它只監看並閂鎖中止，不產生命令。

## 2. 基礎對照與配置差異（逐項登錄）
- 任務策略用 K3-A（`K3APolicy`），**不疊加 B／U／X**（無承載平衡、無 HOLD 參考卸載或重對齊）。
- 偏移觀測器照舊用 interval（`--offset-observer interval`），取證照舊用 EV（evidence.jsonl）。

| 項目 | K3-A INT EV（固定底盤） | K3-M |
|---|---|---|
| 求解器 `--park-hold` | 有（u_base＝停車伺服） | **無**（底盤由 W-GMPC 決定） |
| 近目標輸出整形（`--near-target-gamma 1.0`） | 參數在，但 PARK_HOLD 時程式停用 | **生效**（同一參數，不再被停用） |
| 執行端模式 | PARK_HOLD：閘門＋保持監看 | 閘門＋**底盤包絡監看**（新旗標，版本化執行端） |
| 策略底盤漂移中止 | 20 mm／2°（相對錨點） | **底盤包絡**（§4，相對錨點的前進／側向／偏航框） |
| 判定器底盤核對 | 20 mm／2° | **同一底盤包絡** |
| 其他（目標、門角範圍、接觸、腕力、抓取漂移、熱中止、夾爪） | — | 全部相同 |

## 3. 離線核對（已完成，只讀實錄 door_k3a_ev_1 的錨點、HOLD 目標與夾爪開度）
### 3.1 W-GMPC 閉迴路運動學重播
`door_k3m_offline_replay.py` → `results/door/door_k3m_offline_replay.json`
- 受控體與控制器沿用 `wgmpc_closed_loop_sim.run`：
  - 手臂設定點模型用 free4 辨識；底盤命令→實測增益 0.9／0.9／0.82；
  - 控制器是 `solve_sp` 本體，延遲 1.4 週期，補償 1.6／1.0（發布歷史查表）；
  - 權重同跑法（N 5、w_s 0.001、w_a 0.05、w_s_arm 0.05）。
- **門跟隨夾爪**：由實際 TCP 經剛性夾持關係推得門角，餵給 DoorTargetK3（一個控制週期落後）；到 8° 後保持 4 s。
  - 初版用「門理想跟隨參考角」，手臂落後時門扇會穿入夾爪，屬建模假象；該輸出保留為 `_v0_ideal_door.json`，不採用。

| 求解失敗 | 0 | 0 |

- 描述：free 解中底盤大致隨把手移動（每開 1° 約後退 10 mm、側移 7.7 mm、偏航 0.43°），手臂幾乎不動；底盤淨空隨之增加。
- 這是無接觸、無夾持力、無安全層的運動學篩選，不代表 Isaac 會收斂，也不預測卸載。

### 3.2 底盤包絡 × 門角的靜態取樣
`door_k3m_offline_envelope.py` → `results/door/door_k3m_offline_envelope_r2.json`（r1 無 +0.02 m 前進，保留）
- 取樣網格（相對錨點）：前進 {−0.15, −0.10, −0.05, 0, +0.02} m × 側向 {−0.05, 0, +0.05, +0.10} m × 偏航 {−6, −3, 0, +3, +6}° × 門角 {−1, 0, 2, 4, 6, 8, 9}°，共 700 樣本。
- 每個樣本：剛性夾持下的目標＋該底盤位姿解手臂 IK，再核淨空與關節餘裕。
- 結果：IK 失敗 286（到不了，主要是底盤後退多而門角小），**IK 成功的 414 個全部符合既有淨空門檻**。
  - IK 成功樣本的最小值：非手指 7.09 mm、手指對門板 35.6 mm、立柱 52.9 mm、底盤 65.2 mm、關節餘裕 0.09 rad。
- 剛性夾持成立時，實際位形一定是 IK 可達的，所以「可達即淨空」支持把整個網格框當監看包絡；IK 不可達的格位在夾持中不會出現。
- 淨空剛體涵蓋手臂各連桿、夾爪殼、兩指、`link_eef`（其碰撞網格為 `d435_with_cam_stand.stl`，即腕部相機＋支架），以及底盤圓盤。
- 近似：點雲／盒／膠囊、取樣之間未核、TCP 精確到達的靜態假設；不是碰撞安全證明。
- 3.1 的 free 軌跡落在框內：前進 −82 mm、側向 +61 mm、偏航 3.4°。

### 3.3 速度需求
- 門角速率上限 1°/s，把手距鉸鏈約 0.80 m ⇒ TCP 弧速度最大約 14 mm/s。
- free 重播的底盤需求 0.0144 m/s，約為速度框的 41%、低速介面閂鎖的 29%。

## 4. 底盤包絡監看（取代固定底盤 20 mm／2°）
- 量：底盤實測位姿相對停車錨點（`/park/gate` anchor），錨點座標分解為前進、側向與偏航差。
- **登錄界限＝§3.2 的取樣框**：前進 ∈ [−0.15, +0.02] m、側向 ∈ [−0.05, +0.10] m、|偏航| ≤ 6°。
- 三處一致：
  - 執行端逐物理步監看，越界即閂鎖中止，走與 K2 中止相同的閂鎖路徑；
  - 策略每週期監看，越界即中止 `base_envelope`；
  - 判定器以 room 逐物理步重算。
- 已登錄的風險：W-GMPC 沒有門扇／門框避碰限制，底盤只靠此包絡監看界住；包絡外沒有取樣淨空的支持。

## 5. 小角度目標、接觸監看與中止處置
- **目標**：同 K3-A。θ_goal 8°、DoorTargetK3（R∩L∩G、首步不推進、只由門角決定）、HOLD 1.0 s → OPEN → SETTLE → END_HOLD 3 s → DONE；不張爪、不退離。
- **監看**（除底盤漂移改為 §4 外全部照舊）：
  - 單指 < 0.5 N 持續 0.2 s、非預期接觸 0.1 N、牆接觸、腕力 30 N；
  - 門角 OPEN 起 −1…9°、|q̇| ≤ 0.05 rad/s；
  - 抓取漂移對**原始 G_T_H_grasp** 5 mm／2°（不重新初始化）；
  - 新鮮度、求解失敗、閂鎖；92 °C 熱中止。
- **中止後**（沿用既有路徑，不新增行為）：
  - 任務端送 `/door/k2_abort` 閂鎖並停發目標、停求解器；
  - 執行端閂鎖讓鏈內命令過期 ⇒ 命令鏈逾時路徑：**底盤經輪級限制減速到零**（`limit9_timeout`），**手臂速率立即歸零**，設定點凍結、手臂保持；
  - 夾爪維持閉合命令，不放爪、不退離；觀察 3 s 後結束。
  - 執行端包絡越界時走同一條閂鎖路徑。
