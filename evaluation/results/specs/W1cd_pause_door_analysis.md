- 不新增模擬、不改控制；單趟描述，不作統計或因果結論。

**工具與輸出**
- `door_w1cd_pause_door_analysis.py` → `results/door/w1cd_pause_door_analysis.json`
  - 圖：`第七次進度報告素材/圖表/w1cd_暫停期門與底盤對齊.png`

**方法**
- 門角一律用角度差，不用已知不一致的 raw 門速。
- 底盤實測速度＝世界位姿 0.1 s 位移轉本體（不用 meas_vb_body 單步差分）。
- 偏差＝實測 − 套用命令（base_cmd_body）。

## 結論（r2；Codex 20261025_020934 收斂措辭）
1. **W1c 淨空下降並未伴隨顯著底盤位移。**
   - STOPPED→中止 5.32 s 內底盤位姿變化很小：整段淨位移折合 0.007 mm/s；0.1 s 滑動窗口最大 0.321 mm/s。
   - 同期門轉 0.119°，TCP 相對實測把手沿 y 增加 1.62 mm，兩指法向承載平穩（F1≈6.2 N、F2≈3.7 N）。
   - 這**不能排除**底盤控制或接觸受力的影響；淨空下降的來源本輪未辨識。
   - W1d 新命令套用後，底盤與門共同移動（約 2.5 mm/s、門約 3 mrad/s），但 TCP 相對把手 ≤ 0.017 mm。
2. **現有接觸資料不足以計算繞鉸鏈的淨接觸力矩 ⇒ NA。**
   - 原樣計算的 τ_z 與被動模型所需量級相差 15–4100 倍。這只是**未驗證的診斷量**，不作排除任何機制的證據。
   - 法向正負約定、摩擦錨點作用側都未核對。
3. **表觀速度殘差（候選）。**
   - 多趟資料在部分接觸前及夾持階段，都呈現實測運動與命令之間的方向性殘差。
   - W1d 重設後的運動，與「保持伺服抵消某種表觀速度偏差」相容。
   - 但尚未確認加性偏差模型，也未排除門—機器人接觸與物理求解的影響。
   - 依據（r2 統一時間語意，`door_base_cmd_residual_r2.py` → `results/door/base_cmd_residual_r2.json`）：
     - **算法**：第 k 列位姿與命令都在 world.step 前取得；本步寫入 API 的是 set_linear_velocity(R(yaw_k)·cmd_k)（世界座標根速度）。同一物理區間內，把逐步命令轉世界座標後積分，再與同區間位移相減，轉回本體座標。
     - **已確認無接觸力的相位**（leaf／wall 接觸紀錄每步可讀且力值皆 0），四趟一致：
       - UNFOLD 殘差模約 1.25–1.29 mm/s；
       - APPROACH 約 2.57–2.58 mm/s。
     - **有接觸的相位**：ENGAGE 3.34–3.38、HOLD 3.99–4.02、OPEN 2.71–2.86、SETTLE／PAUSE 約 2.53–2.59 mm/s。方向都約為本體 (−0.8, +0.6)。
     - **W1d 各段**：
       - PAUSE→ZERO_PUB (−2.05, 1.48)；
       - 新命令套用前 (−1.97, 1.49)；
       - 套用→FAIL (−2.00, 1.50)；
       - FAIL→中止 (−2.14, 1.46) mm/s。
   - 「|命令|／k_p ＝ 錨點差」（W1c 1.243 vs 1.250 mm）主要反映伺服律本身的一致性，**不是**偏差來源或穩態受力平衡的獨立證據。
   - **被動設定讀回**：門的 joint_friction 0、drive 0、linear_damping 0、角阻尼 2.0（只繞質心）。
     - 這只說明門沒有設定的鉸鏈摩擦或驅動；**不代表**接觸、慣性與約束反力不存在。
     - r1 的「不是門負載」「門無法提供 mm/s 級負載」**已刪除**（速度不是負載量）。
   - **仍缺的證據**：
     - 無門時的零命令與 PARK_HOLD 響應；
     - 步進前後的根速度（寫入值 vs 步進後讀回）；
     - 輪／滾子關節狀態；
     - 滾子—地面接觸力。
- **r1 說明**：r1 主分析用「窗口位移速度 − 瞬時命令」，附表用「同窗命令平均」，兩者時間語意不一致，r2 統一取代。r1 檔保留不覆寫。
