> v1 → v2 的兩項改正：**(1) B 基線凍結設定找得到**（v1 誤稱找不到）；
> **(2) 不啟動原 guard 節點 ≠ 取消其必要功能**。

底盤與手臂同時運動累計 3.50 s、位置誤差 697.5 → 0.8 mm）接到 **Isaac 執行端**。

`isaac_drawer_sim.py`（抽屜）**一律不動**。

## 1. 命令介面：承接完整 9 維，不是多開兩個訂閱

上游 `/wb_vel_cmd`（Float64MultiArray, 9）已把底盤**本體**速度與六軸關節速度
放在**同一筆訊息**，源自單一全身求解。

**規格**：

* 新執行端**只訂閱 `/wb_vel_cmd` 這一個 topic**，不分別訂閱底盤與手臂。
* **同一物理步套用同一份命令快照**：每步取一次 `(seq, stamp, 9 維向量)`，
  底盤與手臂分量用**同一份**。
  各自取兩個 topic 的最新值**不算同步**，本規格明確禁止。
* 記錄每步實際套用的快照時間戳與序號，供事後核對。

### 1.1 手臂致動轉接層（**新增，必須驗證**）

Isaac 的手臂以位置驅動；上游給的是關節**速度**。所以需要
「速度積分成位置設定點」的轉接層。**這不是原生速度控制**，明列如下：

| 項目 | 規格 |
|---|---|
| 積分時間差 | `world.current_time` 的**相鄰物理步差**（`physics_dt`），不用牆鐘、不用訊息到達間隔 |
| 初始設定點 | 第一筆命令到達時，由**實測關節位置**建立（`robot.get_joint_positions()`），不由命令歷史推得 |
| 命令逾時 | 超過 `max_cmd_age`（模擬時間）未更新 ⇒ **停止積分**，設定點凍結在最後值；不外插。**凍結設定點只代表停止積分，不代表手臂實際速度瞬間為零** —— 實際停止行為須另行量測並記錄 |
| 時間重設 | 偵測到 `current_time` 非單調遞增 ⇒ 停止，不試圖續算 |
| 關節限位 | 積分結果夾在 `LITE6_SAFE` 之內；**一旦夾限即記錄並停止**，不靜默飽和 |

積分誤差與實測位置的偏差逐步記錄，作為轉接層是否忠實的證據。

## 2. 唯一命令鏈：先確立接線與端點身分

**已證實的衝突**：`evaluation/arm_vel_gate.py` 發布 `/cmd_vel`（`BASE_CMD`），
`ammr_wholebody_mpc/wheel_limit_guard.py` 也發布 `/cmd_vel`
（`/cmd_vel_smoothed → /cmd_vel`）。**兩者照原樣一起啟動會有兩個發布者。**

### 2.1 本移植採用的接線（單一鏈）

```
wholebody_pregrasp  --/wholebody_safety/cmd_in-->  wholebody_safety_node
                    --/wholebody_safety/cmd_out--> arm_vel_adapter
                    --/wb_vel_cmd-->               isaac_wholebody_sim
```

**本移植不啟動 `arm_vel_gate`，也不啟動 `wheel_limit_guard` 這兩個節點。**

理由：Isaac 執行端直接吃 `/wb_vel_cmd` 這一筆完整命令，不需要把它拆成
`/cmd_vel` ＋ 控制器 topic，也就不需要閘門去維持「唯一發布者」。
**這是與 Gazebo 鏈路的實質差異，必須記錄，不能宣稱兩者等效。**

### 2.1a **不啟動節點 ≠ 取消其必要功能**

完整 9 維 topic 解決的是**命令拆分**問題，**不能取代有效性與輪級檢查**。
新執行端**至少**要自行承接下列檢查（缺一不可）：

| 檢查 | 規格 |
|---|---|
| 結構有效性 | 長度**恰為 9**、**全部有限**（非 NaN/Inf）；不符即整筆拒收 |
| 來源與新鮮度 | 來源可辨識；接收時間超過 `max_cmd_age`（模擬時間）即視為過期 |
| 同步 | **同一物理步使用同一份快照**（見 §1） |
| 底盤輪級限制 | 依輪系幾何檢查底盤分量是否可實現 |
| 手臂命令限制 | 關節速度、積分後位置的限位檢查 |
| 失效處置 | **整體失效**：不合規時走明訂的整筆處置，**不得原樣執行**，**也不得只縮底盤分量後宣稱全身安全仍成立** |
| 接收端逾時 | **獨立於上游**的逾時判定與停止紀錄 |

### 2.1b 序號與時間戳的命名

`Float64MultiArray` 的九個數值**本身沒有序號與時間戳**。執行端若要編號，
一律命名為 **`recv_seq` / `recv_sim_t`（接收序號／接收時間）**，
**不得冒稱來源發布時間，也不得據此宣稱完整端到端延遲**。

### 2.1c 輪級輸出限制尚未實作時的範圍限制

若輪級的**正常輸出限制**（而非僅越界中止）尚未實作，
**只能做有明確低速界限、越界即中止的介面測試**，
**不得進入完整的自由空間預抓取驗收**。

### 2.2 端點身分

| 角色 | 節點 | 說明 |
|---|---|---|
| 整筆命令有效性 | `wholebody_safety_node` | 9 維一起放行或一起歸零；無資料一律輸出零 |
| 格式轉換 | `arm_vel_adapter` | 世界→本體座標旋轉，**不裁剪、不平滑、不重新限幅** |
| 交給 Isaac | `isaac_wholebody_sim` | 唯一消費端 |
| 輪速限制 | **本移植不啟用** | 見 2.3 |

### 2.3 輪級限制的未決事項

`wheel_limit_guard` 若介入，會**修改底盤分量**。修改後的底盤分量
**不再是**上游全身求解的輸出，因此：

* **不得宣稱「修改後仍保有上游所有安全性質」。**
* 若日後要啟用，必須記錄**修改前後的完整 9 維命令**，並重新論證。
* 本移植先不啟用，把「全身命令原樣抵達 Isaac」這件事先建立起來。

## 3. 求解模式：明確指定，不用預設值冒充

`evaluation/wholebody_pregrasp.py` 的 `--solver` 有 `dls` 與 `qp` 兩個分支，
**預設 `dls`**（說明：dls = 任務求解後再下游投影；qp = 任務、碰撞與硬體限制
在同一次求解內）。

* **介面煙霧測試**明確指定 `--solver dls`，不依賴預設值；輸出一律標示 DLS。
* **預設 DLS 不等於整合式單步 B 基線。**

**B 基線的凍結設定存在**（`evaluation/results/baseline_B_frozen_20260909.md`），
內容包含：

| 項目 | 凍結值 |
|---|---|
| 控制器 | `wholebody_pregrasp.py --solver qp` |
| 求解器 | OSQP，`eps_abs = eps_rel = 1e-6`、`max_iter = 50000`、`polish = True` |
| 主要基線 μ | 0.03（補充對照 0） |
| 其餘權重 | `base_weight 3.0`、`kp_p = kp_r = 1.0`、`damping 0.06`、`kp_post 1.2`、`k_limit 1.5`、`limit_margin 0.35` |
| 任務容差 | `tol_p 0.005 m`、`tol_r 0.02 rad`、`settle_s 2.0 s` |
| 控制率 | 標稱 20 Hz |
| **下游濾波器** | **保留於迴路中，是基線的一部分，比較時不得略去** |
| 程式版本 | git `6ef269be65ee`（執行當下工作區有未提交改動） |

* **介面通過後，正式移植必須核對這份 B 基線**。
* **文件存在不代表目前程式已與凍結版一致** —— 凍結紀錄本身註明
  「執行當下工作區有未提交改動」，因此移植前仍須**逐項核對現行程式**，
  核對通過才可稱 B。

## 4. 驗收順序（依序，前一項不過不進下一項）

1. **底盤單獨小動作** —— 手臂分量恆零，底盤走小位移；核對實際位移與命令一致
2. **手臂單獨小動作** —— 底盤分量恆零；核對積分設定點與實測關節位置
3. **同步小動作** —— 兩者同時非零，**同一快照**；核對兩者在同一物理步套用
4. **既有自由空間全身預抓取** —— 重跑 Gazebo 已驗收的那個任務。
   **前提**：輪級正常輸出限制已實作。未實作前只能停在第 3 項
   （有明確低速界限、越界即中止的介面測試）。

每一項都要驗證：

* **共同命令過期時，底盤與手臂的停止行為**（兩者必須一起停，不得一動一停）
* **安全層所需資料真的在線**（`/arm_link_distance/points`、`/joint_states`、
  TF `report_frame → base_link`）
* **缺資料就停** —— 不以關閉安全層換取同動
