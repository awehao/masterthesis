# 低速、自由空間、求解器驅動的受限測試規格 v1

> **狀態：定版，但開跑前的離線核對未通過（見 §8）。尚未執行任何趟次。**

**執行版本 E2**。上游安全層**繼續在線**。
**不**把接觸操作判準當成前提 —— 這是自由空間測試。

---

## 0. 這份規格要驗什麼、不驗什麼

前面五趟驗的都是**介面**：命令能不能傳到、底盤／手臂會不會動、
同動、斷訊、輪級限制。命令源一律是**有界測試剖面**。

本規格第一次讓**既有全身求解器**產生命令，驗的是：

> 求解器驅動下，底盤與手臂能不能協同把 **TCP 移到指定位置**，
> 且全程符合既有的介面界限與輪級限制。

**不驗**（且必須明列為未獲得的保證）：

| 項 | 狀態 |
|---|---|
| 命令被輪級限制修改後，上游全身安全性是否仍成立 | **未重新論證** |
| 停止掃掠範圍的避碰保證 | **沒有**（見停止預算撤回書） |
| 接觸操作的適用性 | **不在範圍內**，本測試為自由空間 |
| 動態障礙物 | **不在範圍內** |

## 1. 場景：自由空間，無接觸目標

* 地面 ＋ 機器人，**不放抽屜、不放櫃體、不放任何接觸目標**
* 目標是一個**自由空間中的 TCP 位姿**，不靠近任何幾何
* 距離節點（`arm_link_distance`）與安全層照常運行並記錄，
  但本場景預期其距離讀數**不會接近障壁** —— 這一點要**實測記錄**，
  不是假設

## 2. 命令來源：既有求解器

* 使用既有的全身求解器（`wholebody_safety` 下游鏈路），
  **不新寫求解器**、不改增益、不改濾波器
* 求解器輸出經**既有安全鏈**（`/wholebody_safety/cmd_in` → 安全層 →
  `arm_vel_adapter` → `/wb_vel_cmd`）抵達 E2 執行端
* E2 的輪級限制照常作用；λ < 1 的步數要記錄

## 3. 幅度與保護：**沿用，不放寬**

| 項 | 值 | 來源 |
|---|---|---|
| 低速介面界限 | `lin 0.05 m/s`、`ang 0.2 rad/s` | 執行端現值，不動 |
| 手臂速率整筆拒收門檻 | 1.0 rad/s | 不動 |
| 輪速／輪加速度 | `w_lim 0.2775 m/s`、`α_max 125 rad/s²` | 不動 |
| 熱中止 | 92.0 °C | **不得上調** |
| pregrasp | 仍由 `PREGRASP_PRECONDITIONS_MET` 禁止 | 不動 |

> 本測試**不是** pregrasp。目標是自由空間位姿，不是抓取姿態，
> 也不接觸任何物體。因此不需要解除 pregrasp 禁止。

## 4. 目標選擇（事前固定，與結果無關）

目標 TCP 位置必須：

1. 在手臂的可達範圍內（用既有的可達性掃描結果選）
2. 與任何幾何保持充裕距離（自由空間）

~~需要底盤與手臂同時運動才能到達~~ —— **此條已刪除**。
單一終點通常**不能**強迫同時運動；同動是求解器實際產生的行為，**要量測**。
若到達但同動不足，就分別報「到達通過／同動未通過」，
**不換目標追求通過**。

目標一經寫入本規格即**不得因為某趟未到達而更換**。

## 5. 判準（草案，開跑前定版為 YAML）

| 類 | 判準 |
|---|---|
| **R 到達** | TCP 位置誤差 ≤ 事前門檻；**以實測 FK 為準**，不以求解器自報的誤差代替 |
| **C 協同** | 由**實測運動**判定的同時運動累計與最長連續時間（沿用 sync 趟次的門檻與方法，**不以命令分量同時非零代替**） |
| **B 界限** | 全程 `|vx| ≤ 0.05`、`|wz| ≤ 0.2`、手臂速率 ≤ 1.0；執行端界限設定值未被放寬 |
| **L 輪級** | 逐步輪速 ≤ 0.2775、輪加速度 ≤ 6.25；λ < 1 的步數與原因要記錄 |
| **S 停止** | 到達後保持；沿用停止判準（實測速率低於門檻並持續、位移取窗內最大原始值） |
| **D 保護** | pregrasp 仍禁止、熱中止 92.0、獨立 domain 與趟次目錄 |
| **N 未獲保證** | 輸出必須明列 §0 表格中的四項 |

**到達誤差門檻的訂定**：要在**看到任何求解器趟次結果之前**訂定，
依據是「本階段低速自由空間可接受的定位誤差」，
**不得**由某一趟量到的誤差向上取整。

## 6. 不做的事

* 不追加同類介面測試（base／arm／sync／斷訊已足）
* 不追查安全層為何衰減 `wz`（保留為已知限制）
* 不刻意製造 `stop_unverified`
* 不把接觸操作判準當成前提

## 9. 開跑前三項核對的結果

### 9.1 起始配置、參數與座標系 —— **通過**

* 目標是**固定的世界座標** `(0.300, 0.000, 0.550)`，
  不是相對當下 TCP 自動加偏移（`T_des[:3,3] = a.target`，直接賦值）
* 求解器的底盤位姿取自 **`/odom`**（`_on_odom`），
  `MODEL_Z = 0.0` ⇒ 運動學模型根部與模擬器世界在 z 上一致
  ⇒ **求解器的世界座標與 `odom` 一致**
* 起始配置：底盤原點、手臂全零（＝ `test_start`，與 spawn 位姿一致）
* 姿勢項參考 `pregrasp_reference = [0, 0.3641, 0.5263, 0, −1.4086, 0]`
  （**不是**全零）

### 9.2 可達性與路徑幾何 —— 重建結果顯示可達

離線重建 `dls` 解算（含姿勢項與限位勢，**不含下游安全濾波器**）：

| 量 | 值 |
|---|---|
| 起始 TCP | (0.1970, 0.0000, 0.4000) |
| 起始誤差 | 位置 182.0 mm、姿態 1.5708 rad |
| 到達 | **4.5 s**，位置誤差 **4.53 mm**、姿態誤差 **0.0194 rad** |

兩項都落在 5 mm／0.02 rad 內，但**餘裕很小**（4.53/5.00、0.0194/0.0200）。

### 9.3 低速界限相容性 —— **未通過，這是開跑前的阻斷項**

| `--v-task` | `--base-weight` | 底盤線速度峰值 | 執行端界限 |
|---|---|---|---|
| 0.10（預設） | 3.0（預設） | **0.3589 m/s** | 0.05 |
| 0.10 | 6.0 | 0.3590 | 0.05 |
| 0.10 | 12.0 | 0.3591 | 0.05 |
| 0.05 | 3.0 | 0.3865 | 0.05 |
| 0.03 | 3.0 | 0.3975 | 0.05 |
| 0.02 | 3.0 | **0.4031** | 0.05 |

**峰值約為界限的 7 倍，且既有旋鈕解不掉** ——
降 `--v-task` 反而讓峰值變大（姿態任務主導，底盤被用來滿足旋轉誤差；
角速度全程 0.0000，底盤是在**平移**去滿足旋轉任務，
與程式註解記載的「底盤衝過目標」同一類行為）。

執行端對越界命令是**整筆中止**（設計如此，不裁切），
所以照現況開跑會在第一筆命令就中止。

**依指示回報，不偷偷放寬界限、不裁切命令、不改目標。**

## 10. 本次核對自身的限制（必須一併聲明）

1. **未含下游安全濾波器。** 求解器與執行端之間還有安全層，
   它確實會修改命令 —— E2 趟次實測 `wz` 由 0.18 被衰減到 0.041（約 4.4 倍）。
   實際抵達執行端的線速度**可能遠小於** 0.3589，**但我沒有驗證**，
   也不能據此宣稱相容。
2. **joint3 餘裕未量得。** 我的記錄變數初始化為零，導致 `min(q3 − lower)`
   恆為 0，**該欄無效**。`arm_initial_pose.yaml` 記載 joint3 安全範圍單邊
   `[−0.0611, +2.9356]`、起始位置僅高於下限 0.0611，
   而**趟次自身的 guard 在 lower + 0.05 = −0.0111 就中止**，
   只剩 0.011 rad —— 且「已有兩次全身嘗試因此中止」。
   這一項**必須在開跑前另行量得**。
3. 重建的是任務解算，不是完整節點（缺失效守衛、排程、距離約束）。
