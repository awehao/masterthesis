### 對這些修補的未決驗證項（**尚未進行**）

以下為需要在「新版本整合驗收」中回答的問題，本工作階段**不作答、不背書**：

1. **出口修正往 `ξ_prev` 縮回的可行性前提**。`ξ_prev` 來自哪一級輸出？如何驗證它
   本身可行？若上一筆命令已超輪速、設定剛切換、或 `ξ_prev` 並非最後真正發布的命令，
   輪速可行集不一定包含它。輪速限制與加速度限制暫時無共同可行命令時的失效處置為何？
   **不可聲稱「一定有閉式可行解、不引入階躍」。**
2. **輪級可行 ≠ CBF 仍可行**。沿出口縮回會改動 QP 的答案；需重新計算修改後命令的
   CBF 殘差，並**分開記錄原始解、出口修正後、smoother 最終輸出**。
   「收斂解 λ=1」應改為「**通過出口檢查的解** λ=1」——求解器回報收斂不代表數值上未超限。
3. **`wheel_enforce_output=False` 不足以保證舊結果逐位元重現**。這批同時改了 TF 年齡、
   障礙逾時、停止狀態機與路徑接收邏輯；關閉輪級出口修正只關掉那一項。逐位元回歸
   測試必須**限定到確實測過的函式與輸入**，不可宣稱整個閉迴路可重現。
4. **`--odom-vel-source`**：需**分開**核對 pose 與 twist 的來源，以及 EKF 實際融合哪些
   欄位；並含時間戳、座標系與閉迴路影響。
5. **「舊 22 欄全部視為求解週期」需確認舊發布邏輯確實如此**——列長本身不能代替
   有限值與有效性檢查。
