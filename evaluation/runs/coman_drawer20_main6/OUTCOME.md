## 新發現：F18　`_on_pts` 的資料競爭

```
File "wholebody_pregrasp.py", line 266, in _on_pts
    self.min_d = float((self.rows[ok, 6] - rho[ok]).min()) if ok.any() \
IndexError: boolean index did not match indexed array along dimension 0;
            dimension is 1109 but corresponding boolean dimension is 1111
```

`_on_pts` 先用 `self.rows` 算 `ok`（1111 列），再用 `self.rows` 取值
（已被換成 1109 列）—— 兩次存取之間，`self.rows` 被**另一個執行緒的**
`_on_pts` 換掉。

**這是既有缺陷，但由我的改動暴露。** `ReentrantCallbackGroup` 下有**兩個**
executor 同時在轉這個節點：`TransformListener(spin_thread=True)` 的背景執行緒，
加上 F17 新加的主迴圈 `_pump()`。並發提高後競爭才顯現。

修法很小（把陣列綁進區域變數，讓整段計算對同一份快照自洽），
但**本趟未修、未重跑** —— 依約定界線封存。
