# 這一趟（與 solve2／solve4）對**求解器行為**無證據力：底盤命令座標系錯誤

* 原因：`wgmpc_wg2_node._publish_u` 發的是**世界座標**九維命令
  （docstring：「body → world 後發給安全鏈，adapter 之後會轉回 body」）。
  本趟把它直接接到 `/wb_vel_cmd`，而抽屜模擬器的命令鏈把那裡當**本體座標**
  （執行端自己做 `wx = vx·cosθ − vy·sinθ`）。底盤的 x/y 因此被旋轉
  θ ≈ 1.2973 rad（74.3°）。
* 症狀：求解期間底盤走了 Δx = −59.30 mm、Δy = +6.73 mm、Δθ = −9.71°，
  而離線核出的精確解要的是 Δy = −25 mm、Δx = 0、Δθ = 0、手臂不動。
* 影響範圍：**手臂分量與 wz 不受影響**（`body_to_world` 只旋轉前兩個分量），
  所以誤差仍由 25.21 降到 11.8 mm —— 那是手臂做的，底盤在亂走。
* 因此作廢的結論：
  * 「11.8 mm / 1.55° 是求解器自願停留的代價權衡駐點」
  * 「平台與起點無關」（solve4 vs solve5 的對照同樣帶著這個錯誤）
  * 對候補 A（w_bt 正則）與候補 B（視野太短）的一切推論
* 仍然有效的部分：
  * 握手與 ARM 通路（api_applied 與介面契約的修正）
  * 目標話題通路（2337/2338 輪用 topic、0 筆被拒、最大年齡 0.08 s）
  * 兩套到達判定彼此吻合（它們量的是同一個實測狀態，與命令座標系無關）
  * 離線核算：精確解存在（底盤 −y 30 mm ＋ 設計抓取角，0.0155 mm / 0.00000°）
* 已修：求解節點改發中性話題 `/wgmpc/cmd_world`，由 `arm_vel_adapter`
  做世界→本體那一次旋轉（轉換只保留一份，不在下游另寫）。
