## 1. D_cmd 現在是量到的，不是估計

逐筆配對 `(run_id, source_seq)`，**1194 / 1202 筆** solver ∩ safety ∩ endpoint 齊全。

| 區段 | p10 | **p50** | p90 | p50（週期） |
|---|---|---|---|---|
| 發布 → 安全層輸出 | 0.020 | **0.040** | 0.040 s | 0.80 |
| 安全層 → 首次 API 套用 | 0.010 | **0.020** | 0.020 s | 0.40 |
| **發布 → 首次 API 套用（D_cmd）** | 0.040 | **0.050** | 0.060 s | **1.00** |

節點另逐輪量到 `D_pub`（量測 → 發布）p50 **0.030 s = 0.60 週期**。

**所以 `D_state = D_pub + D_cmd ≈ 1.60 週期`，而 `D_cmd ≈ 1.00 週期`。**
本趟節點用的是**單一 D = 1.4**：對 `D_state` 接近正確，對 `D_cmd` **偏高 0.4 週期**
⇒ 發布歷史查表會取到錯的命令。這正是「兩種時間不可混用」的量化證據。

**先前的 1.4 只是工程估計**（`cmd_age` 不是傳遞延遲），本趟才是逐筆量到。
