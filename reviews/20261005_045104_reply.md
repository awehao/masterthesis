**T3 功能確認可收，T2＋T3 可以作為正式六趟的候選配置。** 但批次入口有一個確定會壞的寫法，修好並凍結後才能起跑；不用再追加 T3 功能趟。

### 起跑前必修兩項

**1. 修正批次腳本的環境變數傳法。**

目前這行：

```bash
${AREF:+MOTM_A_REF="$AREF"}
```

Bash 不會把展開後的文字重新辨識成變數賦值。我用最小反例重現了：

```text
MOTM_A_REF=0.004: command not found
```

改成直接、固定的賦值：

```bash
MOTM_A_REF="$AREF"
```

MotM 給 `0.004`、停車給空字串，runner 現有的條件展開會略過空值。只需用假入口核對兩種方法實際收到的環境與引數，不必再開模擬。

**2. 更新 `plan_T.yaml` 再凍結。**

目前它仍是舊提案：T2 寫提高倒退速度、T3 寫重估軟啟動，與實際改動不同。改為：

- T2：僅 RETREAT 的 TCP 退開斜坡 `0.05 m/s`。
- T3：兩節點共同 `motm_a_ref=0.004`，含 `a_stop` 的連帶作用。
- T1 暫不做；正式順序固定為 **M、P、P、M、M、P**。
- 修正先前的 ENGAGE_WAIT 時間數字，並保留共同終點 OPEN 的比較。

### 正式比較可以照你的設計

核對實錄：兩節點都是 `0.004`；相對 T2，task 參數只差 `motm_a_ref`；S1–S6 通過、RETREAT **1.08 s**。這足以進正式比較，**不足以證明減速剖面是唯一原因，或全程已變快**。

正式六趟固定 H5、共同版本與原限制；三對配對差皆負且任務判準成立，作為本批工程目標。失败、中止、變慢全部保留，S6 仍只涵蓋已量測的抽屜配對。

完成上述兩項與新凍結後即可跑，不新增其他前置驗證。**正式結果不論是否達到「更快」，都整理進第六次進度報告素材。**
