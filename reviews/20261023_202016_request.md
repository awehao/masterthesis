## 你的五點如何交代
1. **3＋6 自由度、門角被動**
   - 沿用 K3-A INT EV 的求解器與參數，唯一差異是拿掉 `--park-hold`，整個時域底盤由 W-GMPC 決定。
   - 速度、加速度、輪級與低速閂鎖全部照舊。
   - 執行端從不命令門關節。
2. **控制權單一**
   - 轉交前沿用 PARK_HOLD 的停車閘門（任務節點要等 /park/gate 通過）。
   - 轉交後底盤與手臂只來自 W-GMPC → adapter → E2。
   - 不啟用停車伺服：求解器無 park_hold，執行端不建 HoldMonitor，改用只監看、不產生命令的底盤包絡監看。
3. **基礎對照不疊加 B／U／X**：策略用 K3APolicy。規格 §2 表列配置差異：
   - 求解器 park_hold；
   - 近目標整形在 PARK_HOLD 時被程式停用，K3-M 會生效（同一參數）；
   - 執行端模式；
   - 策略與判定器的底盤漂移改為包絡。
4. **離線核對**
   - **(a) 閉迴路運動學重播**：受控體與控制器沿用 `wgmpc_closed_loop_sim.run`，`solve_sp` 本體，延遲與權重同跑法。
     - 門角由實際 TCP 經剛性夾持推得，再餵 DoorTargetK3，即門跟隨夾爪。初版用「門理想跟隨參考角」，手臂落後時門扇會穿入夾爪，屬建模假象；該輸出保留但不採用。
     - free 結果：9.7 s 到 8°。底盤後退 82 mm、側移 61 mm、偏航 3.4°，速度 0.0144 m/s（框的 41%）。手臂只到 0.007 rad/s，每輪關節變化 ≤ 0.0004 rad，關節餘裕 ≥ 0.829 rad。追蹤誤差 ≤ 3.8 mm。
     - 取樣淨空：非手指 7.2、手指對門板 35.7、立柱 52.8、底盤 202 mm。
     - fixed 對照：參考超前撞到 0.5° 上限，追蹤誤差 8.3 mm，底盤淨空 106 mm。
   - **(b) 底盤包絡 × 門角**：700 個靜態樣本。IK 失敗 286 個（底盤後退多而門角小時到不了）；IK 成功的 414 個全部符合既有淨空門檻，最小值為非手指 7.09 mm、底盤 65 mm、關節餘裕 0.09 rad。
   - 淨空剛體含 `link_eef`，其碰撞網格為 d435_with_cam_stand，即相機＋支架。
5. **小角度目標、監看與中止**
   - 目標、相位與監看同 K3-A，只有底盤漂移改為包絡：前進 [−0.15, +0.02] m、側向 [−0.05, +0.10] m、|偏航| ≤ 6°，即取樣框。
   - 中止沿用既有閂鎖路徑：鏈內命令立即過期，底盤經 limit9_timeout 減速，手臂速率歸零、設定點凍結；夾爪保持閉合，不放爪、不退離。已核對 `K2AbortLatch.expire_chain`。
