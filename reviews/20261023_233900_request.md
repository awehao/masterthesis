### 一、門角與門速
- **來源**：同一個門扇 RigidPrim view（leaf_state，與 leaf_pair 同一個 prim）。門角取姿態 −yaw，門速取 −ω_z。兩者在 API 寫入之後、world.step 之前同時讀取，寫在同一列。
- **靜止**（0–15 s）：兩者都是 0，沒有常數偏差。
- **時序**：門明顯移動時（OPEN、閂鎖後 0–1 s），本列門速與**下一步**的角度差分相關 0.92–0.97，與本步差分的相關較低。也就是同一列的角與速指向不同的物理步區間。
- **幅值**：每個有運動的窗口，門速平均都大於角度斜率，比值 1.28–5.41（OPEN 約 2.3、閂鎖後 1–10 s 約 3.9–5.4），比例不固定。長窗平均不受一步時移影響。閂鎖 1 s 後，與下一步差分的相關降到 0.43–0.56。
- 原因未查，可能方向只列出、不判定。沒有套用比例修正。
- **對保護**：門速保護與觀察器都讀這個欄位。不能把它當作門角速率的可靠量測，也不能據此說保護保守或失效。長窗的停止判定用位移差分，不受影響。

### 二、零命令至物理狀態
- **順序**：讀位姿 → ex.step → 用同步 yaw 轉世界座標 → set_linear_velocity／set_angular_velocity → 手臂 apply_action → 記錄 → world.step。
- **寫入來源**：底盤速度寫入只有這兩處。沒有 physics callback、set_world_pose、施力或關節速度寫入；門沒有任何寫入。
  - 機器人以 `fix_base=False` 匯入，是浮動根，靠每步覆寫根速度驅動。
  - park_mode=hold 是 HoldMonitor 的監看狀態，不是位置保持控制。停車伺服在求解端，閂鎖後求解器已停止。
- **能證明到哪一層**：
  - (1) 紀錄命令：有。
  - (2) API 寫入參數：沒有直接紀錄。由 (1) 與同步 yaw 決定性轉換，零命令 ⇒ 精確零向量（程式可證）。
  - (3) 物理步後的實際速度：沒有紀錄，只有相鄰列位姿差分。
- **逐段比較**（本體座標，命令 (1) vs 位姿差分 (3)）：
