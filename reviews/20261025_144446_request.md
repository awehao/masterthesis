# W2 保持／待交接 整合設計 draft-2（純設計；**未核可實作或實跑**；draft-1 保留）

依 Codex 20261025_034022：方向可行，但 H1–H6 不足以直接落地。本版拆成兩件事：
- **W2**：同一 W-GMPC 命令流內的受控模式轉換。
- **W3**：全身控制到導航的擁有權交接。
- 「新 segment、獨立序號區間」不是現有封裝能力（door_k3m_applied_src 採固定 stage 與單調 source_seq），本版不再沿用此說法。

## 0. 現況（同 draft-1）
- ADM9 在監督器 DONE 後停發；任務端 DONE ⇒ /room/stop；執行端由鏈逾時接手 ⇒ 有空窗。

## 1. W2：同一命令流內的模式轉換（不換命令發布者）
- **命令發布者始終是同一個 W-GMPC 求解端**：同一 run_id、同一 stage、source_seq 單調遞增。
- 手指張開是手指命令變更（任務端 /gripper/cmd），不是另一個底盤或手臂命令來源。

**模式序列**（求解端監督器的版本化擴充；既有門檻不變）：
`PAUSE（LOWSPEED→ZERO_PUB→CONFIRM→STOPPED→觀察通過）→ HELD → RELEASE_PREP → GRIP_OPEN → CAP_RESTORE → RETREAT → STOW → HELD_STOWED`

**模式切換的原子性**
- 由執行端模式權威在物理步 k 選定新模式：比照 K3-M 模式與暫停握手，回 ack {seq, mode, switch_step: k}。
- **同一步 k 同時切換**：套用的命令類別、手指命令，以及**監看適用表**（§3）。
  - 不等求解端或任務端收到 ack 才換監看，否則正常退離會被 HELD 的手臂靜止判準誤判。
- k 之後，舊模式的延遲命令一律不生效：執行端以「模式序號＋封裝 source_seq」雙重核對，見 §2。
- **ack 遺失不代表未切換**：任務端與求解端以執行端權威狀態（/door/mode_state 每步發布）與實際套用來源（applied_src）為準，不以是否收到 ack 推定。

**承接**
- 新模式第一筆命令承接實際 applied u_prev 與手臂設定點，並通過既有可行性核對：加速度、輪級、publish_feasible。
- 不通過 ⇒ 不發布，走既有失敗路徑；不放寬核對。

## 2. 防空窗與防雙控（W2 與 W3 共用的證據要求）
- **單一權威**：每個物理步只有執行端權威決定套用哪一筆。applied_src 逐步記 {step, source_seq, mode_seq, chain_mode}。
- **無空窗**：
  - 切換前後每步的鏈模式都是 normal（0），沒有逾時（1）步；
  - 切換步 k 的 applied_src 必須是新模式的第一筆命令，即首筆實際套用證據。
- **無雙控**：
  - k 之後若出現舊 mode_seq 的命令，只能被丟棄並計數，不能進鏈；
  - 判定器核對 applied_src 每步的 mode_seq 單調不減，且與權威狀態一致。
- **N 筆前置**（比照 p2c 的 N＝20）只是啟動等待的既有選值，**不是交接安全證明**；安全性以上面三項逐步證據判定。
- **失效分支**：
  - 切換前候選不合格 ⇒ 拒絕、繼續保持；
  - 切換後新模式失效 ⇒ 中止，**不自動回切 HELD**。

**HELD 的結束條件**（取代 draft-1 中互相矛盾的寫法）
- (a) 下一模式切換確認；
- (b) 中止或失效；
- (c) **有界超時 T_held**：正常結束實驗，標「未交接」。
  - 未交接的實驗終止**不算任務完成**；
  - 也不代表撤除保持後安全停止；
  - 不放爪、不恢復上限。

## 4. W3：擁有權交接（全身控制 → 導航）

- 前置：HELD_STOWED，且門角 ≥ θ_pass，並以實際 K2_READY 包絡與路徑重新核對。
- 門扇依實測門角更新、門框靜態，登錄新鮮度、預測與不確定性處理。

## 5. 優先順序
中止 ＞ 失效 ＞ 逾時 ＞ 正常。
- 失效的兩種情形：切換前 ⇒ 拒絕候選、繼續保持；切換後 ⇒ 中止，不回切。
- 這是既有處置的延續，不是已驗證的故障後安全停止。
