## 0. 對 K3B_release_hold_r1 的用語更正
- 離線結論改為 Codex 的較窄說法：
  > 在本趟量測軌跡及所登錄重放假設下，靜止等待解除確認不能滿足現行幾何判準；同步退離改善部分淨空，但仍不符合現行准入、預測淨空與門角帶。
- **帶 r3 不是由「門近乎靜止」推得。** 它是在指定擾動下，依實測退離量與門角差建立的幾何限制，不能因門轉得快便放寬。r1 該句撤回。
- `near_exit_t` 改稱「**幾何出口條件首次達標**」：只含退離量 s ≥ 0.02 與配對距離 ≥ 5 mm，不含解除確認、門角帶等條件，不是正式退出。
- 配對距離分兩段報：
  - 張爪後 0.5 s（約 71.41 s）約 **0.08 mm**（重放值 0.084 mm）；
  - 72.41–72.71 s 為 0.04–0.05 mm。
  - r1 把兩段混寫，在此分開。
- 實錄重放的說法限定為：「把既有紀錄餵入 r6，仍會因手臂運動失敗」。不推論修正控制連續性後的新閉環軌跡。

## 2. 閉爪卸載候選
### 2.1 流程
1. HELD 後請求 mode 1，mode 1 提交步啟動卸載，手指維持閉合：
   - 執行端 `ExecUnloadMonitor`（door_k3b_unload）依登錄斜坡把手指驅動上限由 20 N 線性降到 5 N；
   - 每步設定並讀回，讀回須＝本步設定。
2. 斜坡結束且讀回＝5 N ⇒ SETTLING；連續 quiet_s 低速（底盤、門 0.1 s 窗與手臂 0.5 s 窗皆 ≤ 舊 HELD 門檻）⇒ UNLOADED。
3. 任務端 `task_gate`：須**執行端 UNLOADED 且求解端子狀態 unloaded**（求解端 /wgmpc/pause_status）才請求 mode 2。
4. 權威 `ModeAuthority7` 的 gate2＝`ExecUnloadMonitor.confirmed_fresh`，請求時與提交當下都核，比照 gate3。
5. mode 2 提交後 handoff 給 ExecReleaseMonitor，之後沿用 K3-B 既有流程。

在 5 N 下張爪後，原「C_CLEAR 後恢復 5 N」一步成為核對：讀回須仍為 5。整合到任務節點時另行版本化，本包未接。

### 2.2 卸載期間的監看（不無限等待）
| 端 | 項目 | 界限 | 來源 |
|---|---|---|---|
| 執行端 | 失接觸：兩指 bar＋ambiguous | ≥ 0.5 N | 既有 GRIP_MIN_N |
| 執行端 | 門角差分速度 | ≤ 0.05 rad/s | 任務端 door_abort_rate（另一訊號，見 §1） |
| 執行端 | 底盤偏離（相對卸載起點） | ≤ 20 mm／2° | door_k3b_release REG base_dev |
| 執行端 | 讀回＝設定、設定＝斜坡 | 容差 1e−3 | W1e 讀回規則 |
| 執行端 | 資料連續、時間遞增；連續無效 | > 0.2 s ⇒ 失敗 | 同 ExecReleaseMonitor |
| 執行端 | 期限：mode 1 提交起到 UNLOADED | ≤ 4.0 s（**候選**） | 見 §2.3 |
| 求解端 | 子狀態 unload：門速、底盤偏離、期限 | 同上 | |
| 求解端 | 子狀態 unload：手臂 | 不以停止門檻核 | 卸載瞬態；任務端漂移、幾何監看照舊 |
| 求解端 | unloaded：四項舊門檻低速連續 0.5 s，且 t ≥ t_c1＋ramp_s | | |
| 任務端 | 夾持漂移、一般幾何、K3-M 監看 | 照舊（本包未改） | |

- 任一不合格 ⇒ 終止：執行端 FAILED、求解端 FAIL 停發、任務端 abort。
- 終止時手指上限停在當下設定值，不重試、不加力、不放爪。

### 2.3 待驗證候選值與依據
| 參數 | 值 | 依據（不是由本趟失敗軌跡反推放行） |
|---|---|---|
| ramp_s | 1.0 s | 候選，無實測依據 |
| unload_max_s | 4.0 s | door_wide_k3b_30_1 暫停起點 W1e 5→20 N 切換（54.03 s）後，門 +0.24°、底盤約 3 mm、手臂 j4 約 0.004 rad，約 2 s 內近乎停止（56.02→57.02 s 門角變化 0.0032°、之後 < 0.001°）；斜坡 1 s＋收斂 ≤ 3 s |

- 本包**不預設**卸載能消除張爪後門運動，也不把接觸衝量當成已確認根因。
- 卸載本身亦會擾動：上述反向切換即使門轉 0.24°。
