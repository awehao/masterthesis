# 連續協同通行 r27：末段鉛直誤差——規劃有修正、實際未實現（唯讀審查、不改檔、不啟動模擬）

## 1. 方法
- **快照**：最接近 90.0、100.0、104.9 s 的已發布輪；時域終點都早於中止 105.32 s，已排除中止後資料。
- **規劃**（規劃證據，非實際軌跡）：
  - 起點 z0＝q_pred／s_pred（延遲補償後）；
  - 手臂 α 用 free4，bias 用當輪 arm_bias；
  - 以記錄的 U_sol 經 rollout_sp 展開，對當輪 T_cyc 算 TCP 誤差的鉛直分量 ez。
- **實測**：預測步 k 對應 snap＋d_state·dt＋k·dt；取同時刻 room 的底盤加手臂實測，對**同一 T_cyc** 算 ez。
  - 三快照 T_cyc z 都是 0.8559 m：門繞鉛直鉸鏈轉，目標鉛直座標不變。

- **回答**：**求解器規劃了修正**（每輪 0.25 s 內把鉛直誤差往 0 拉 0.55–1.20 mm），**實際未實現**（同期實測變化 −0.05～−0.18 mm）。
- **附帶觀察**：延遲補償後的預測起點本身就比實測高 1.1–2.0 mm，而且隨門角增大。也就是求解端以為 TCP 比實際高。
- **偏移估計**：ADM17r3 帶既有的 `--offset-hold-on-free`。紀錄 offset_hold 顯示：
  - 4.72 s（OPEN 4.60 s 之後、切入 free 的那一輪）凍結 d̂；
  - j2 ＝ −0.02337（由初值 −0.02753 經 92 次更新而來）；
  - 之後整段 OPEN（約 100 s）不再更新。三快照 d̂ j2 都是 −0.0234。

## 3. 限制（不判定唯一原因）
- 「預測起點偏高且隨門角增大」與「d̂ 在開門全程凍結」時間上相伴，但不能據此判定原因就是偏移凍結。
- 其他可能也存在：手臂構型改變造成的重力下垂變化、與把手的接觸力、執行端追蹤差。
- 一步殘差的分解（手臂設定點模型 vs 實測）可進一步區分，但依你的指示，本包不自動延伸。
