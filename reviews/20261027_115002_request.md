## 1. gc.freeze 候選（ev9r4、跑法 bench8、凍結 r8 共 404 檔、sha256 核對通過）
- **旗標** `--gc-freeze-before-release`：store_true，預設關 ⇒ 同 ev9r3；需 `--bench-start`，否則拒跑（62）。
- **時點**：台架凍結前置迴圈開始之前，即 `t_b0` 之後、`BenchRelease`（釋放計時）之前，呼叫 `exec_gc_freeze.freeze_once()` 一次。物理尚凍結。
- **不做的事**：不關閉自動 GC、不改門檻、不 collect、不循環。ev9r3 的逐步區段與 GC 診斷全保留。
- **紀錄** room_run `gc_freeze`：
  - Python 版本、freeze 耗時；
  - 前後的 gc.get_count、get_freeze_count、受追蹤物件數；
  - isenabled、get_threshold；
  - VmRSS、VmHWM、ru_maxrss；
  - 結束時的 final_state。
- **揭露**：
  - 被 freeze 的物件（含當時的垃圾）不再被回收；
  - 不保證新物件不再造成停頓；
  - Python 3.12 啟動時 freeze 數已不為 0（測試環境 375）。Isaac 行程同為 3.12.3。
- **測試**：
  - `test_exec_gc_freeze` G1–G5：
    - 子行程實測 freeze 數增加、isenabled／threshold 不變；
    - freeze 後新建的循環垃圾在後續存活配置推動下仍被自動回收（weakref 確認，不呼叫 collect）；
    - 故障吞掉；模組不含 collect／disable／enable／set_threshold，freeze 呼叫只一次；
    - ev9r4 對 ev9r3 只插入，每個插入的 if 區塊後第一個原有行縮排 ≤ 該 if；freeze 位置與拒跑檢查位置核對。
  - `test_door_coopen_core_bench8_static` B1–B2：跑法只差 FRZ、開場字樣、執行端行；ev9r4 可編譯。
  - `test_exec_timing_diag` X1–X7 仍通過。
- **準備過程揭露**：ev9r4 初版把拒跑檢查插在 `if a.bench_start:` 區塊中間，會把其後的 `try:` 吞進新 if。語法合法，pyflakes 沒抓到；未實跑前已修正，G5 新增縮排檢查防止再犯。

## 2. 暫停緩移的有界對時（bench_5，103.02 → 108.04 s；只描述）

- **設定點**：低速段變動最大 0.51 mrad；STOPPED（107.19 s）後**完全固定**。STOPPED 後 applied_arm 六軸 0，套用來源鏈模式 0。

  - 合力約 18.09 N（OPEN 約 10 N），STOPPED 後幾乎不變（+0.016 N/s）。
