**繼續完成同一準備包，不改方向、不另開搜尋。但目前仍有幾項接線前必修，不能把純測試通過視為已可實跑。**

我已讀程式，重跑 gates2、policy1、policy2 的現有純測試，皆通過；另加反例得到以下結果。

### 1. 無效資料恢復當步，仍會洗掉逾時

重現序列：

`0.01 s 有效 → 0.02–0.21 s 無效 → 0.22 s 恢復有效`

距最後有效資料已超過 0.2 s，但 Gate6 回 WAITING、`invalid_t0=None`，沒有 FAILED。

原因是 `_seq()` 只在跳步／時間不一致時先核期限；正常逐步送來無效資料、再恢復時，仍會由 `_hold()` 直接清除計時。

**所有 gate 與 HoldConfirm 都須在接受恢復資料之前，先核既有無效期限。** 補此反例，不調期限。

### 2. 接觸許可集合擴大了，須收回

`OUTER` 把 `post_out0/1`、`ambiguous` 一起列為 mode 1–2、mode 3 前段的允許接觸，與已定矩陣不符。

**解除確認時保守加總這些力，不等於允許接觸它們。**

- 指定持握只認外側橫桿。
- 立柱、panel、ambiguous 依原非預期接觸保護。
- mode 3「已離開後禁止重新接觸」須單向閂鎖；不能因實測退開量又低於 S_EXIT，就重新允許外側接觸。

執行端與任務端必須使用一致規則。

### 3. mode 6 提交當輪，會被任務端舊模式誤擋

我讓權威已提交 mode 6 的第一輪，就收到合法 `bar_in=2 N`。結果：

`ABORTED: rg_contact_not_designated`

當時權威模式是 6，任務端 `k_committed` 還是 5。因為 `_monitor_rg()` 在解析新提交之前執行；現有替身則等任務端更新模式後才注入力，避開了這個交界。

須以**經驗證、與接觸來源步對應的權威提交**決定接觸規則。補提交當輪接觸、通知延遲、錯趟／過期通知的測試；不要用全面暫免接觸保護來處理。

### 4. 缺幾何後端不能先動、再等 gate timeout

目前 `geom_v3_fn=None` 時，換抓監看直接略過幾何，直到請求 mode 4 才等逾時。這不符合缺保護證據即停止的契約。

正式換抓模式須：

- 啟動／進入前確認幾何後端存在；
- 運行中缺後端或有效結果，立即走既定失效路徑；
- 不把它當成一般「尚未到位」等待。

v3 接觸摘要也要保存來源步與來源時間，不能只用 `on_c3()` 的接收時刻刷新年齡；缺 `max`／來源等必要欄位不得當作零接觸。

### 5. 參考銜接存在實際跳變

我用允許範圍內的 **19 mm 起始底盤偏差**核對，mode 3→4 被接受，但底盤參考突然跳約 **18.3 mm**。mode 3 加了起始偏差，mode 4 又直接回到原表；這不是已驗證的銜接。

請在既定銜接段內連續消除偏差，並核對轉換後的速度、加速度及幾何，不能只查偏差大小。

mode 5 的加權旋轉也須補正前饋：目前只旋轉原 `ff`，漏掉旋轉權重變化造成的運動。我重算 Δq＝+1° 時，位置參考差分與前饋最大相差約 **1.73 mm/s、2.88 mrad/s**。應由同一條修正後參考一致產生。

此外：

- −1／0／+1° 三組取樣不能稱整個連續區間已驗證。
- 現在門角修正是在模式開始時取一次，不能寫成每輪跟隨實測把手；須明列固定參考與即時准入的差異。
- 配對預測距離目前只扣 `v_floor`，仍須按既有規則處理實測接近率，不能把 floor 當成接近速度上界。
