**有新的直接發現：extf_1 的中止，不能描述為「某指連續低於 0.5 N 達 0.2 秒」。**

我重算中止前 OPEN 的逐物理步紀錄：**兩指低於門檻的事件，最長都只有 1 步、0.01 秒**。例如：

| 時刻 | finger1 |
|---|---:|
| 41.32 s | 0.0205 N |
| 41.33 s | 7.853 N |
| 41.34 s | 0 N |
| 41.35 s | 3.610 N |

但[現行策略](/home/howardchen/masterthesis/evaluation/door_k3a_policy.py:128)用發布窗口的 `finger_bar_min` 計時。連續幾個窗口各有一次低力，就會被累計成持續失接觸，**窗口之間的實際恢復沒有被計入**。

### 下一步改這個資料流，不調夾爪

核可版本化修正：

- 在執行端逐物理步，以原 **0.5 N／0.2 s** 定義判定連續失接觸；有效樣本恢復即清零。
- 實際連續超時須觸發中止並閂鎖事件，不能只發布摘要；資料失效保護保留。
- 任務端讀取此結果，不再對窗口最小值重複累計時間。原窗口最小力仍保存供報告。
- 明列這是**停止判準時間語義的變更**，原 extf_1 判定保留，不翻案，也不豁免獨立判定器的低力紀錄。

接觸抖動確實存在，**不代表已穩定，也不能全面排除微小滑移**；只能說未量到明顯持握漂移，且這次沒有連續 0.2 s 失接觸的證據。
