# bottle_p1_2 定位結果：支撐不成立是因為桌面只承擔約 1/3 重量（加上接觸初期逐步跳動）

**趟況**：同阻點 place_phase_timeout（LOWER，17.7 s），未鬆爪。
- 首次支撐 38.60 s：fz 1.758、fh 0.002、gap 0，d_freeze 48.25 mm（h_lift 47.8）。
- 和 p1_1 不同：這次**停止有效未通過**，停止 1 s 後手臂速率 0.0031 rad/s（>1e-3），rc 4。p1_1 是 0.00033 rad/s，有效。
- 禁止接觸全 0，資料有效 100%。

**place_log 逐步時序（支撐後 1591 步）**
- 失敗分項只有 fz（1501 步），fh、gap、tilt、inside、nodata 全部 0 次。good 比例 0.057，n_sup 峰 7 步（需 30 步）。
- 接觸初期約 0.4 s：每一步 fz 在 0 和 1.0–2.4 N 之間交替，例如 0, 1.76, 0, 1.61, 0.6, 1.35…，原始值與轉換後相同。
- 之後每 0.1 s 平均穩定在 0.59–0.66 N（≈0.33 mg），p90 0.85、最大 2.38；fz<0.98 佔 94%，fz=0 佔 1.5%。
- 瓶底 gap 中位 0、最大 0.01 mm；傾角最大 0.21°。
- 手指對瓶力：|F| 中位 2.55／2.44 N，z 分量中位約 0。這個 API 看來不含摩擦分量，所以 fz 加手指 z 不等於 mg（0.66 對 1.96），夾爪的摩擦承重量不到。
- 可以說：瓶底到達桌面高度、仍由夾爪握持；桌面穩態支撐約 1/3 mg。**不能說**已獨立站穩。

**判讀**：下降在首次支撐時凍結，夾爪仍靠摩擦撐住約 2/3 重量。0.5 mg 支撐門檻在「鬆爪前」這個時點達不到，這是設計假設錯誤，不是量測失效。接觸初期的逐步交替另外也會打斷連續計數。

**選項（都要你裁定）**
1. **支撐後有界小步下壓**：凍結後以 1 mm／s 再壓，直到窗口平均 fz ≥ 0.98 或額外下壓達上限（例如 3 mm）就停。風險：滑移監看仍有效，可能觸發；桌面與手腕受力增加。
2. **改判準**：支撐門檻改為窗口平均 fz ≥ 0.25 mg（約 0.49 N）＋窗口內樣本全有效＋gap 與傾角持續成立。不再要求鬆爪前桌面已承擔半重；實際承重改在鬆爪後的 HOLD 驗（≥0.9 mg）。
3. **兩段鬆爪**：支撐初步成立後，先張到部分開度（降低夾持力），桌面承重上升到 ≥0.98 N 後再全開。和「支撐成立才鬆爪」的原則有張力。

另外，不論選哪個，逐步計數都要改成窗口判準（窗內全有效、平均與比例），否則接觸初期的交替會一直歸零。這也是判準變更。

**建議**：選 2＋窗口判準。理由：
- 鬆爪前桌面能承重多少，取決於夾持摩擦，不是放置能力本身。真正的放置成功（支撐、手指解除、穩定）已經在 HOLD 以 ≥0.9 mg 與位移、傾角驗收。
- 1 會增加下壓與滑移風險，你上次也說不要增加下壓。

**另一件事**：p1_2 停止有效未通過（手臂 0.0031 rad/s），疑似停止時手臂與桌面、瓶的接觸平衡在調整。要不要另外分析？
