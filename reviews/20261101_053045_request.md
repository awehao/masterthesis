# 下一包回報：滑移短分析、位姿互核修正、V2 最小設計

## 1. v1_1 滑移短分析（既有紀錄，只定位）
- 分解：瓶相對 TCP 的位移幾乎全在世界 −z，是瓶子在指間往下滑。
- 時序（v1_1）：

| 時刻 | 下滑 |
|---|---|
| 抓持成立 20.74 s | 0 |
| 離桌 22.45 s | 0.40 mm |
| 25 s | 0.97 mm |
| 30 s | 1.68 mm |
| LOWER 開始 34.90 s | 3.42 mm |
| 首次接觸 38.13 s | 4.37 mm |
| 之後到鬆爪 | 不變 |

  持瓶段約 0.2 mm/s 線性爬升，下降段到接觸前再增加 0.95 mm，接觸後沒有增加。
- p1_3：離桌 0.07 mm，到 30 s 都約 0.1 mm；30–34.9 s 之間跳到 0.61 mm，之後不變。
- 兩趟同條件：持瓶段底盤加速度 RMS 0.15／p99 0.59 m/s²（相同）；手指法向力平均 2.50 N（相同）、最小 1.57–1.59 N；底盤速度峰 0.277 m/s（相同）；手指開度 3.70 對 3.73 mm。
- 不同處：關節角加速度 RMS 0.026 對 0.016 rad/s²（v1_1 高約 60%）。只是相關，不推定原因。
- 口徑：v1_1 的滑移是持瓶途中的持續下滑，不是放置接觸造成的。原因未定，不歸給相機負載。這次接觸 API 回報的手指力看不到摩擦分量，無法直接看摩擦飽和。

## 2. 位姿與時間互核修正（未實跑）
- v1_1 互核全是 NaN 的原因：影格的 rendering_time 都對到前一步，渲染資料比當下晚一步，取影格時回讀的位姿是下一步的。
- 改法：每一步 record_step 時就存渲染端回讀的相機位姿。影格依 rendering_time 對到哪一步，就用那一步存下的回讀，與「量測底盤×外參」比較；另外記錄影格落後幾步（frame_lag_steps）。
- 起跑前第一張影格也改成要 pose_dev < 1 mm、< 0.1°。
- 位姿與時間互核尚未在 Isaac 驗證，所以偏差 2.6 mm 的來源先不推定。

## 3. V2 最小設計 draft-1
全文在設計檔「V2 最小設計」一節。要點：
- 一次性視覺定位，只適用靜態瓶。
- 取得：有效估計且距離 0.5–2.0 m；最近 1 s 內 ≥5 筆、xy 兩兩差 ≤3 mm、軸傾角 ≤3°。
- 凍結：取中位數 xy；展臂前（x ≥ −1.55）必須凍結，抓取、預抓、抬升目標與手臂分支依凍結值重算，之後不改。凍結到閉爪超過 15 s 就停止。
- 停止條件（不回真值）：vision_no_fix；凍結後估計和凍結值差 >5 mm → vision_inconsistent；重算後分支不可達 → vision_target_unreachable。
- 仍用真值（明示）：底盤定位；5 mm 淨空拒絕線與禁止接觸的安全監看；評估；第二桌放置點。
- 先做離線誤差預算：Δ 側向／插入方向各 ±3 mm，加 v1_1 的 y 系統偏差 +2.6 mm，看非手指淨空、開口餘裕、抓取深度。不足再談 V1b。
