# Howard 新要求：逐步加入視覺，移動抓瓶後放到第二張桌子

日期：2026-11-01（Asia/Taipei）。用途：同步 Claude／Codex 的下一階段工作；不直接授權新增 Isaac 實跑或批次。

## 1. 使用者確認的目標

Howard 原話：「還不錯要慢慢加入視覺 然後夾道之後放到另一個桌子 放的時候可以停下當終點」。其中「夾道」依上下文理解為「夾到」。

新任務為：**導航避障 → 移動接近及抓瓶 → 抬離與持瓶搬運 → 接近第二張桌子 → 可停車放置 → 穩定支撐、鬆爪及安全退離，完成任務。**

- 放置允許停車，是名目任務條件，不算降級；不要求移動中放置。
- 抓取仍延續目前移動中操作，不因末端允許停車就改回全程停車抓放。
- 延續同一個全身 GMPC，不新增導航／操作控制權交棒。階段目標、速度參考及指定接觸可以改變。
- 完成終點由「持瓶到出口停下」擴充為「瓶子放在第二張桌子並穩定釋放」；既有出口任務與結果封存，不回改成功判定。

## 2. 逐步實作，避免視覺與放置同時首跑

以 `bottle_n2_1` 作為已有 ROS 掃描與規劃鏈路的參考，另建版本，不修改封存跑法。

1. 先提出第二桌放置的最小場景與流程：沿用已驗證抓取，新增持瓶導航目標、停車對位、下降、支撐確認、鬆爪、退離。第一版若用真值，須明示，不宣稱視覺成果。
2. 相機先旁路取得影像／深度、標定與物件估計，不直接改控制命令；保存來源時間、座標系、有效性及對真值的估計誤差。真值只作評估，不混作視覺輸出。
3. 再讓瓶子視覺位姿進控制；第二桌先維持已知位置，接著才用視覺估計桌面／放置區。先處理已知瓶型、靜態桌面，不一次新增未知抓法或移動物件。
4. 估計缺失、過期或跳變時必須有明確保持／重估／停止條件，不能默默退回真值卻仍稱視覺成功。更新任務目標需維持連續性，不重設機器人或瓶子。

先送最小設計與必要離線核對，不新增大掃描或反覆重跑無關測試。新的場景／控制變更與具體物理一趟另送審；不因本指令直接重跑 S1～S3。

## 3. 放置成功與安全必須分開驗收

- 不能只看 TCP 到位、張爪命令或任務 DONE；需以瓶子實際位姿、第二桌支撐、手指解除接觸、瓶子穩定及退離後仍留在放置區判定。
- 放置前確認底盤停穩；保持穩定的時長、速度／傾角／位置容差在設計中事前提出，不為通過結果臨時調整。
- 第二桌、桌腳、瓶子和持瓶外形須進規劃、感知及對應幾何／接觸判定。LiDAR 看不到桌面，不以桌腳安全代替手臂／瓶子安全。
- 瓶底↔第二桌是放置階段的指定支撐接觸；手臂、掌面等禁止接觸不可一併排除。先確認支撐再解除夾持，不用焊接、瞬移或直接修改物件位姿冒充放置。
- 停止、資料有效性、Shield、熱守護與既有抓持判準保留。GUI 照常開啟、不等 Howard、不自動製片。
