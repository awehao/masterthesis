# V_HIGH B 案只渲染核對結果＋物理前置包規劃（唯讀審查、不改檔、不啟動模擬）

依 021353 核可，0.60 與 0.75 各渲染一次。另外 0.75 多跑了一次，原因如下。

## 0 揭露：0.75 第一次渲染是工具缺陷，已用新 RUN_ID 重渲染

- `vhigh_render_z075_1` 的手腕深度全程是同一格。原因：不推進物理時，`get_current_frame()` 不會更新。RGB 正常。
- 修正：改用 `get_depth()` 直接讀標註器（與 `get_rgba` 同源），並加防呆：相鄰格深度完全相同就判結果碼 5。
- 以 `vhigh_render_z075_2` 重渲染一次。這是擷取工具修正，不是依結果補跑；z075_1 的紀錄與評估檔都保留。

## 1 方法

**渲染**：`isaac_bottle_render_seq.py`（replay_w1z 的版本化複本）
- 只渲染，不推進物理、不跑控制、不起 ROS。
- 合成來源 `runs/vhigh_seq_src_z0XX`（標 synthetic）：
  - 底盤：名目趟實測軌跡；
  - 手臂：B 案（K2_READY→V_HIGH 4.65 s；保持 9.42–12.42 s；轉名目備妥 2.35 s；原漸變到 T_pre）；
  - 瓶：靜置。
- 擷取：10 Hz，t 3.9–17.8 s，共 139 格。
- 手腕相機同實跑 w1 設定。存 RGB-D、K、逐格 FK 位姿與渲染端回讀（差 ≤ 0.0008 mm）、九維構型。

**評估**：`bottle_vhigh_render_eval.py`
- 凍結權重 `bottle_seg_v1_continue3/best.pth`。
- 照 bottle_seg3d_node 的流程逐格處理：遮罩 → locate（自身濾除＝該格構型，開閉手指聯集）→ 尺寸閘 → 取最高信心合格實例。
- 結果列送 CandidateTracker（候選節點同規則）。收到時刻＝擷取＋**假設**延遲 0.10 s，不是量到的資料年齡。
- 真值可見性（只用於評估）：以渲染深度判遮擋，點的相機深度與該像素深度差 ≤ 1 cm 才算可見。
