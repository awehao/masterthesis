## 短分析（`bottle_hold_slip_analysis.py` → `results/bottle/hold_slip_analysis.json`）

基準是判定器的抓持成立時刻 t_grasp（三趟都是 20.74 s）的夾持相對位姿；位移以 TCP 座標表示，TCP x 為世界鉛直。

閉爪時（19.35 s）的相對位姿差 ≤ 0.3 mm。依紀錄，V_HIGH 沒有改變初始抓持狀態；但這只是同一指標下的比較，不排除未量到的接觸差異。

- 手指實測開度全程 0.00371（不變）；兩指平均受力約 2.5 N，最小約 1.6 N。
- 停穩後機器人完全靜止，瓶仍以 0.74 mm/s 下滑。持續承重本身就足以造成滑移，不只是運送擾動。

**3. 材質與驅動**
- 資產 `bottle_s0.yaml` 中，瓶的材質設定是靜摩擦 1.0、動摩擦 0.8、恢復係數 0；physics dt 0.01。這是**已知的設定值**。
- **尚未核實**：各實際碰撞面（瓶、兩指的碰撞形狀）的有效材質綁定與合成模式。
- 接觸力 API 不含切向力，所以不能據此判摩擦飽和。
- 依設定值估算，2×1.0×2.5 N 遠大於瓶重 1.96 N；但實際仍在滑。這只說明「設定值與觀察不一致、待查綁定」，不據此下結論。

## 提案：單因素夾持保持實驗（離桌後靜態懸持）

**唯一改變**：抬升完成且離桌判定成立（t_lift_ok）後，**延後持瓶路徑請求 T_HOLD＝13 s**（約等於本趟持瓶行進＋放置接近的長度）。
- 期間底盤參考為 0（LIFTC 既有「等路徑」行為）。
- 手臂維持進 CARRY 時的側持相對位姿（T_carry_rel）。
- 緊湊收近不啟動（它要等 CARRY_NAV）。

其餘全部與 `bottle_w1_vhigh_z060_p1_1` 相同：
- V_HIGH 接近、移動抓取；
- 0.60／P1；
- 原夾持參數（不加摩擦、不加夾持力）；
- 5 mm 判準不放寬。
懸持結束後照原流程運送與放置。若懸持中滑移超過 5 mm，依原判定受控停止，照實報。

**實作**：版本化子類只覆寫 LIFTC 的 `_carry_pending`，讓請求延後到 t_lift_ok＋T_HOLD；Isaac 腳本是 dynsr18 的版本化複本。

**唯讀附加**：起跑時記錄瓶與兩指碰撞形狀上綁定的物理材質與摩擦值，只讀 USD／PhysX 屬性、不修改。這可以回答「設定值是否真的綁上」。

**離線**：假世界核對懸持期間底盤速度為 0、手臂設定點不變、期限不觸發，之後完整抓放；並負測懸持中訊息中斷時照既有規則處理。假世界沒有滑移模型，所以只驗流程。

**物理**：0.60／P1 一趟，新 RUN_ID `bottle_w1_vhigh_hold_z060_p1_1`。報：
- 懸持期間滑移率；
- 與本趟各段比較；
- 手指開度與受力；
- 材質綁定讀值。

**判讀**：
- 懸持中滑移率 ≈ 停穩後的 0.74 mm/s ⇒ 主因是持續承重的保持能力。
- 懸持中 ≈ 0、只在運送段滑 ⇒ 主因是運送擾動。
