**選 C 作主線，但必須同時修正路徑／航向的執行契約。暫不選 A，也不把 B 當通用解法。** 現有候選未通過，原先的 `m8nav_2` 起跑授權暫不適用。

### 1. 先修正對 EXIT 失效的結論

原始碼顯示：開啟 `heading_enable` 後，GMPC 由路徑前瞻方向產生航向參考，**不會照 EXIT 各點填入的「目前車頭方向」執行**。這是上層計畫與控制器的契約不一致，不能直接概括為「GMPC 不會側移／後退」。

先做無行人的前向、側向、後向三個短核對，記錄實際的航向參考、速度參考、QP 輸出、輪級後處理與最終命令。需要修改時用版本化介面，不動封存檔，也不繞過 GMPC／CBF。若無法得到可執行的離開軌跡，就不能把 EXIT 當可靠後備。

此外，`cand_2`、`cand_3` 同時改了程式與起步時刻，不能僅憑兩趟差異證明成功只取決於角度。

### 2. 核可實作穿越時窗候選

核心改成：**在預測衝突區外等待，取得足夠通過時窗才進入，而不是進入後反覆被趕開。**

但時窗必須：

- 只來自線上追蹤與當下狀態，不讀行人生成路線、週期或折返時刻。
- 包含從進入到**整個底盤離開衝突區**的時間、在途延遲、加減速及估測不確定性；不能只算中心點到達時間或一律用 0.30 m/s。
- 持續更新；失追、過期或預測不足不能視為通路已清空。
- 等待點與停止掃掠仍須避開其他障礙。等待超時記未完成，不能到期強行穿越。

EXIT 保留為經上述執行核對的必要處置；「先轉向再走」只能在時間與掃掠確實可行時採用。直接速度伺服繞過 GMPC 不納入本包。

### 3. 起步時間固定，不再靠啟動耗時形成差異

修正版先凍結，登錄五個假世界案例：

- **25.83 s**：已知失敗情境回歸。
- **26、32、38、44 s**：相位敏感性核對。

五案使用同一機器人起點、初速、版本與行人世界軌跡；只改明示的行人世界起步時間。ROS 啟動等待不得再變成隱藏變因。

這是開發場景的有限相位核對，不是泛化成功率。若途中改版，五案須分版本保存，不能拼接通過結果。

### 4. 何時可進 Isaac

上述執行契約核對及五案閉迴路均須：

- 在原期限內到達；
- 對行人、箱體與已知幾何無安全包絡侵入；
- 命令符合原速度／加速度／輪級限制；
- 沒有失效資料放行或來回卡死；
- 完整報等待、行程、耗時、鬆弛及 Shield 行為。

通過後完成碰撞鎖存接線、凍結，即可跑 **`m8nav_2` 一趟**，不必另等起跑裁定。若未過，交第一阻點，不追加起步時間或調裕度挑成功。

這次改善要同時回答兩件事：**能否安全通過，以及等待／繞行代價是否合理。** 不能用永久等待換無碰撞，也不能靠取消 GMPC 來取得表面上的進展。
