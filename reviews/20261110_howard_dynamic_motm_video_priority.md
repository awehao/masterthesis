# Howard 最新方向：先驗證動態複雜場景的移動夾取，交兩種影片（2026-11-10）

## 優先序

1. 下一個主要實驗改為「視覺驅動的移動夾取＋靜態障礙＋移動物」，不是繼續只驗 S→門前導航。先以既有同型瓶作技術驗證；先單瓶完成有資訊的案例，再擴到多瓶。
2. 門把手擷取的已產生資料與程式保留，不打斷或刪除既有工作；後續開門／抽屜整合讓位給本包。最終「開門、開抽屜、取粗馬克筆返回」目標不取消。
3. 這項指示取代 README 先前「瓶子新物理趟擱置」的優先序，但不是授權直接重跑舊 F1 預設流程或沿用答案位置。本文只更新任務與交付範圍，未執行模擬、未修改控制或場景參數。

## 下一包範圍（Codex 的開發安排，不冒稱 Howard 指定了數值）

- 使用靜態障礙加一個移動物；初版提案速度取 0.20 m/s，作低速開發條件，不代表一般行人速度或最終能力。具體世界軌跡、速度與任務時鐘排程在閉迴路前登錄，不跟隨機器人、不依失敗反覆降速或移動障礙。舊高速失敗保留，新條件另立版本，不作單因素效果宣稱。
- 交互須與接近／移動夾取任務有關，不能只把移動物放在放好瓶後的返回段，就稱為動態下移動抓取。分列接近、插入、閉爪、抬升、運送各段的追蹤與約束作用；若接觸段未形成交互，照實揭露，不宣稱該能力已驗證。
- 目標位置由當次視覺提供，取得後由量測與目前狀態生成接近計畫。桌面區域、同型瓶尺寸與地圖可以是明示先驗；精確瓶位、觀看點與選物答案不能來自生成設定。
- 優先保留現有 GMPC 與已核對的執行／狀態承接模組，不為展示另外繞過全身控制。接觸段動態協調仍是已知限制，不能停用避障、碰撞停止或改成停車夾取來掩蓋。
- 精準與速度共同驗收：插入→抓持成立的實測車速與近停時間、TCP 誤差、滑移／抓持品質、放置偏差、最小淨空、任務總時間、非必要等待及求解／發布延遲。維持原品質門檻，接觸力與離桌判定的模擬真值依賴繼續揭露。
- Claude 以一份有界實作／案例包交代現有模組、必要修改及第一阻點，避免拆成無關的多輪審查。不在本文件下自行啟動新 Isaac；依具體包的核對與起跑授權執行。

## 同一 RUN_ID 必交兩支影片

1. **Isaac 模擬畫面**：全景看清底盤、手臂、物件與移動物，搭配手腕相機視野。可以依該趟實際位姿紀錄渲染重播，但須標「實錄重播」，不重新跑控制、改路徑或剪掉失敗。
2. **2D 追蹤疊圖影片**：由同一趟紀錄重建，呈現原始掃描、追蹤位置與速度、預測、規劃／實走路徑、機器人包絡及抓取相位。評估真值與控制端觀測用不同圖例，不以真值代替追蹤結果。

兩片使用相同模擬時間與播放倍率，預設 1×；標明 RUN_ID、版本、相位及實際成敗。需要加速或剪輯版時另存，不取代完整版本。兩片都交付才算影片素材齊全，不再只有 2D 動畫。
