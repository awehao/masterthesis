# 開門執行層 r2：兩個停止缺陷已補；發現 release（解綁）停法本身與夾爪幾何不相容

提交 `git log -1`。幾何耦合測試＋反算力矩紀錄（無接觸物理）。資料 `第八次進度報告素材/資料/door_open_exec_fake_r2/`。「設定點閉鏈」已改稱**設定點模型的幾何偏差監看**。

## 修正
1. **停止期間監看與核對持續**：停止分三種——
   - path（只用於 forced_stop／open_done／end_not_reached／door_not_following／設定點模型偏差／候選或停止掃掠被拒）：g 0.5 s 斜降、同一全身求解繼續追蹤；**每拍新候選照樣經提交前核對**（被拒 ⇒ hold）；實測淨空、實測閉鏈、非有限、限位、超力持續監看；淨空或閉鏈比上一拍惡化 >2 mm ⇒ hold。
   - hold（其餘原因：求解失敗、非有限、限位、淨空、閉鏈、path 逾時／被拒）：命令有界減速、管線走完、**綁定保持**。
   - release（超力 40 N：模擬工程中止值、手腕傳遞力範數、每物理步取樣、任何模式都檢查）：request_unbind＋request_finger_open。只升級不降級（path→hold→release）。
2. **解綁建模**：控制器有 bound 狀態；執行器在下一物理步前解除並 `confirm_unbind`；之後門角是獨立狀態（假世界：ω̇＝−2.0·ω、限位 0–110°；手指視為立即張開——假設）；閉鏈監看停用、淨空改張開手指模型＋獨立門角。每拍另預測 release 路徑（機器人命令減速＋門自由轉＋手指張開），只記錄。
3. 正式 checks 加入：最終停止模式、輪速、本體加速度、手臂設定點速率、停止期間閉鏈位置**與姿態**、解綁要求／確認與模式一致。

## 發現：release 停法與抓持幾何不相容
- 抓持時夾爪殼離橫桿只有約 7 mm（抓持幾何本身）。解綁後機器人命令減速，手臂把設定點超前量走完（τ·q̇ 量級 ~20 mm），同時門照慣性再轉一點；兩者讓殼撞上橫桿。
- release 路徑預測全程都違反（名目案每拍預測最小殼對桿 −13 mm）；所以如果把它當候選命令的門檻，正常開門每拍都會被擋。我沒有把它當門檻，只記錄。
- 實際上 release 只在超力時觸發；名目開門不會走到這條。但它是最後手段，現在這個手段本身會撞。

## 請裁定 release 怎麼處理（我的建議排第一）
(a) **超力也先 hold**（綁定保持、命令減速到停穩，門跟著停），停穩後才解綁＋張爪＋沿接近軸退出 30 mm（退出路徑對已靜止的門核淨空）。代價：超力期間連接仍承載，理想綁定無斷裂，力會持續到停穩（多 ~0.5–1 s）；只是模擬保護訊號，本來就不是安全上限。
(b) release 時同時下「沿接近軸退出」的手臂動作（解綁＋張爪＋退出一起），用自由轉門的預測核退出路徑。需要新寫並驗證這段退出動作。
(c) 保留現狀，結果揭露 release 會碰橫桿。
若選 (a)，我改完重跑兩個超力案，然後依你上次的條件做執行器不動作接線核對、登錄、凍結，起跑正式一趟（局部預抓 → 插入 → 閉爪 → 綁定 → 規劃 → 開門 → 停穩 → 解綁／張爪觀察；不含退出）。
