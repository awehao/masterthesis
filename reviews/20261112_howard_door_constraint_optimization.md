## 2. 文獻依據與不同層級

1. **Jiao 等，IROS 2021，Consolidating Kinematic Models to Promote Coordinated Mobile Manipulations**：以 Virtual Kinematic Chain 合併底盤、手臂、操作物的機構；§III 的閉鏈約束、物體關節目標與碰撞／平滑條件共同進入軌跡最佳化。開門目標可只給門角，其餘組態由求解產生；本文是模擬與運動學規劃，不是接觸力可行性的證明。[作者原文](https://jiangxjames.github.io/publications/open-door-iros21.pdf)
2. **Wang、Chen、Zhao，ICRA 2025，Whole-Body Model Predictive Control for Mobile Manipulation with Task Priority Transition**：有實機開門、保持及穿越；§IV-D 的任務參考仍由門把／門軸與少數關鍵點、階段提供，全身命令由 MPC 在線產生。不能說所有全身 MPC 都已將門的被動動力學共同最佳化。[作者原文](https://wbmpc.github.io/static/pdfs/paper.pdf)
3. **Minniti 等，ICRA 2021，Model Predictive Robot-Environment Interaction Control for Mobile Manipulation Tasks**：以全身 MPC 結合在線辨識／自適應處理未知交互作用，實機包含開門；其力矩控制平台與本平台的位置設定點介面不同，不能直接宣稱本系統已有同等接觸力控制能力。[原始摘要](https://arxiv.org/abs/2106.04202)
4. **Sinaei 等，2026 預印本，Motion Planning for Mobile Manipulators Navigating Doorways via Model Predictive Control**：將底盤與門角共同放入非線性 MPC；手臂以工作空間軟懲罰近似、執行交給 IK，非完整六軸手臂／設定點預測。本系統可研究顯式構型與執行模型的差異，但差異不等於已證明創新或改善。[原文 §2–3](https://arxiv.org/html/2608.00206v1)

另：Burgess-Limerick 等的 *An Architecture for Reactive Mobile Manipulation On-The-Move* 主要驗證移動中取放，不能當成其已解決開門的證據。[原始摘要](https://arxiv.org/abs/2212.06991)

## 3. 新方法要解的問題

核心區別：**門機構給可行運動集合，不先指定整條門角時間曲線再要求機器人追蹤。**

候選預測狀態為底盤位姿、六軸關節、六軸設定點與門角；門角速度若作為規劃變數，僅表示預計操作進度，不能直接拿去驅動被動門。

門把機構可寫為：

\[
T_{WH}(\phi)=T_{WA}\exp([S_A]\phi)T_{AH,0}.
\]

已建立抓持且採剛性不滑移假設時，機器人末端與門把滿足閉鏈：

\[
\operatorname{Log}\!\left(T_{WE}(x_k)^{-1}T_{WH}(\phi_k)T_{HE}\right)\approx0.
\]

T_AB 將 B 座標轉至 A；T_HE 是把手至末端的抓持變換。接觸前不可啟用這條抓持閉鏈。若實際允許繞桿旋轉，必須改成相應自由度的接觸模型，不把六維剛接假設硬套到所有把手。

同一問題共同求底盤、手臂與門角進度：

- 目標：開至具通行淨空的狀態，兼顧進度／耗時、平滑與關節餘裕；不指定舊停位或固定快慢排程。
- 限制：輪級、關節、速度／加速度、設定點與在途命令、閉鏈一致、門角限位，以及全身對旋轉門板／門框／環境／自碰撞淨空。
- 採滾動時域與序列線性化等候選求解方式；須有非線性 FK／閉鏈殘差與候選命令核對。局部求解不能稱全域最佳，亦不能因 QP solved 就宣稱原非線性條件成立。
- 幾何／接觸誤差容許量須有感測與模型依據；安全條件衝突不可只靠任意增加鬆弛來報成功。

## 4. 必須保留的物理與感測界線

- 第一版可先明示「已解鎖、固定鉸鏈、已知門型」；鉸鏈先驗、把手視覺估計、門角來源與誤差分開列。門角若暫用模擬真值，只能標為已知機構／理想狀態前置，不算視覺閉迴路完成。
- 運動學閉鏈可行不等於夾得住、拉得動。真實摩擦抓持分支須由接觸帶動門，禁止設定門角、瞬移或把綁定冒稱物理夾持驗證。Howard 後續提出「夾到後綁定」：可另設明確標示的理想抓持分支，先隔離夾持物理與協同規劃問題；條件與可說／不能說見 [給 Claude 的回覆檔後續補充](20261112_howard_door_direction_reply.md)。這是原先一律禁止綁定要求的範圍調整，不代表綁定已實作。
- 進接觸物理前，交代門慣性／阻力／回關、夾持摩擦與順應策略。沒有可驗證的力／力矩模型與感測，就不宣稱最小接觸力或力安全最佳化。
- 模擬接觸力與門角真值監看和控制來源分開；實機感測未驗證仍是明確缺口。若門可自行回關，單純「機器人停住」不等於安全停止。
- GUARD／Shield 等仍須核最終命令；若下游改了候選命令，閉鏈和停止可行性也須重新核對或轉入可驗證的失效處理。

## 5. 下一包最小交付（先方法原型，不接舊控制）

1. 給出上述新最佳化的狀態、目標、等式／不等式、資料來源，以及門與接觸模式假設；盤點現有 GMPC 哪些可沿用、哪些必須新增。
2. 用同一機構、不同當下底盤／手臂狀態做離線原型：給開門目標而不給底盤路線／手臂圓弧時間序列，核求得的全身解、門角進度、非線性閉鏈殘差與碰撞／停止條件；不可行照實拒絕，不退回舊開門答案。
3. 固定底盤與允許全身協同只作有明確條件的對照；報時間、限制活躍、餘裕與計算量，不事先宣稱協同必然較快。
4. 接觸建立與物理執行另交最小設計，再依既有流程進假世界與 Isaac；本紀錄不增加正式物理趟授權。

這一包的研究問題是「機構約束＋實際執行模型下，如何在線分配底盤／手臂／開門進度」，不是把固定圓弧重新命名。是否比既有方法更快、更準或更穩，待可比實驗證明。
