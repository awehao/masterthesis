# 給 Claude：依 Howard 最新指示，門操作不沿用舊開門控制

日期：2026-11-12（Asia/Taipei）。本檔由 Codex 依 Howard 直接要求建立，供 Claude 讀取；不是 `tools/codex_review.sh` 某筆舊請求的自動回覆，不覆寫既有審查紀錄。

## 最新指示

**不要把新視覺接近接回既有開門控制，也不要只換住宅場景就沿用舊開門流程。**

`evaluation/run_house_door_open.sh` 目前是舊 `run_door_m4r14.sh` 換世界、地圖與起點，只能算「舊方法移植場景」，不是這次要研究的新方法。既有結果保留並明確標示，不再沿此方向追加起跑。若已有測試正在執行，不強制殺程序；依既有安全停止／收尾機制處理，保留實際結果，不計為新方法驗證。

## 下一包：門機構約束下的全身最佳化

1. **門角、底盤、手臂一起求解。** 給開門／通行目標，不預先指定底盤路線、關節序列或整條門角時間曲線。
2. 抓持成立後，將門的鉸鏈運動與末端—把手接觸關係放入約束，同時納入旋轉門板、門框、全身碰撞、輪級及關節限制。接觸模式必須明示，不把剛性不滑移假設冒充物理驗證。
3. 由最佳化決定底盤如何配合、手臂如何運動及開門進度，兼顧速度、精度與流暢度；不能只是生成固定圓弧再追蹤。
4. 可沿用已驗證的視覺、FK、設定點／延遲模型與底層求解框架，**但不沿用舊開門的動作答案**。導航必要功能與完整修改紀錄要求不變。
5. 門不能直接設定角度或瞬移。真實摩擦抓持分支由接觸帶動；Howard 後續提出的「夾到後綁定」可另設理想抓持分支，依下節界線處理，不能混報成摩擦抓持已驗證。模擬真值與實機感測缺口照實列。
6. 非凸求解先稱局部最佳化／可行解；未證明前不稱全域最佳、安全保證或已超越文獻。

**先交新問題的數學定義與離線求解原型**，展示不同當下底盤／手臂狀態如何產生不同協同解，再進接觸物理驗證。不需要先重跑舊版開門。本檔不增加正式 Isaac 趟次授權。

詳細模型、文獻與界線見 [門機構約束最佳化方向紀錄](20261112_howard_door_constraint_optimization.md)。這次只建立回覆文件，沒有修改控制程式或啟動模擬。

## 後續補充：可先做理想抓持綁定版，避免反覆調摩擦阻擋方法驗證

Howard 提議：若抓持接觸使門開不了，可在夾到把手後綁定，以免把大量時間耗在力道／摩擦調整。Codex 建議採獨立的 **ideal attachment（理想抓持）分支**，先驗證機構約束下的全身協同；不必等反覆摩擦調參失敗才建立此分支，也不先認定現有問題必然來自摩擦。

本補充取代前文一律禁止綁定的範圍，但不改「不沿用舊開門控制」的要求：

- 視覺接近與閉爪仍要執行；僅在夾爪到達把手周圍、閉合且符合事前登錄的位置／姿態／相對速度條件後建立可釋放的物理連接，不遠距吸附。採當下相對變換，不把門或夾爪瞬移到理想位置。觸發若使用模擬接觸／幾何真值，必須標為模擬判據，不冒充實機抓持感測。
- 綁定的是夾爪與門上被抓的剛體，**不是門與世界**。保留被動鉸鏈、門質量／阻力／限位，以及機器人的致動限制；由機器人動作透過連接帶動門，不逐拍拷貝物件位姿、不命令門角。
- 先核安裝版本與物理求解器對閉鏈連接的支援；監看連接誤差、數值穩定與其他碰撞。若特定夾持對必須調整碰撞設定，逐對登錄，不關掉整扇門或全身碰撞。釋放時解除連接，門仍按被動物理運動。
- 結果、影片與 RUN_ID／設定明列「理想抓持綁定」。可驗證此假設下的協同、機構一致性、幾何淨空與耗時；**不能用來證明真實夾持可靠、摩擦／滑移已解、實機力安全或實機可直接開門**。若連接不設力矩／力斷裂限制，也要明示這是理想承載假設。
- 真實摩擦抓持保留為另一條後續驗證線，不再靠反覆調摩擦作為新方法原型的前置。本補充是設計範圍調整，不是新增正式 Isaac 趟次授權；目前尚未實作綁定。

文獻支持的是建模抽象，不是本夾爪的物理成功：[VKC 原文 §II 採剛性連接假設](https://jiangxjames.github.io/publications/open-door-iros21.pdf)。Isaac 亦有以物理關節建立／解除抓持連接的機制，但具體 API 必須依本機版本核對：[官方 Surface Gripper 文件](https://docs.isaacsim.omniverse.nvidia.com/latest/robot_simulation/ext_isaacsim_robot_surface_gripper.html)。
