裁定：**先修期限備援與相對速度兩個缺口，再做 P2 執行層整合；末段模式可以做一版，但切換條件須修正。仍限離線／假世界，不核可 Isaac。**

1. 第一阻點：r10 還不能稱「晚到後走已驗證停法」

   [掃掠判定](/home/howardchen/masterthesis/evaluation/door_open_exec_ctrl.py:351)遇閉鏈位置／姿態超限，目前只增加計數，不會拒絕；但 [`_deadline_stop`](/home/howardchen/masterthesis/evaluation/door_open_exec_ctrl.py:396)卻據此轉成各軸有界減速。這重新引入了先前發現的「減速停法與閉鏈不相容」問題。

   請先修：

   - 備援必須同時驗閉鏈位置／姿態、淨空、命令限制及停穩，不能只驗幾何淨空。
   - 路徑停止期間晚到也須符合相同條件，不能直接假定上一拍核過就仍適用。
   - 沒有及時可用、狀態仍適用的機構相容備援，就按既定模擬中止政策處理；不能先標 `settled`。
   - 加反例：「淨空通過但閉鏈停止偏差超限＋同拍期限觸發」，確認不會放行該停法。

   因此，目前負載趟只能說「晚到候選未提交、假世界隨後停下」，不能宣稱接觸／閉鏈備援安全已成立。

2. 抓持的相對速度還有一處需要修正

   [目前速度計算](/home/howardchen/masterthesis/evaluation/door_motm_grasp_ctrl.py:392)仍對 TCP **世界位姿**差分。門靜止時可用；門動、夾爪跟著把手時，它不是夾爪對把手的相對速度。

   改用同時間戳的把手—TCP 相對變換計算，補兩案：

   - 門與夾爪共同運動、相對姿態不變：應判相對靜止。
   - TCP 世界不動、把手移動：應判有相對運動。

   另外，鎖定任務參考解決了「追著估計漂移跑」，但沒有解決滑脫偵測。保留融合估計供規劃，另以新鮮量測／短時一致性作快速拒絕通道；不要再讓一秒融合延遲掩蓋真實相對移動。門角及接觸訊號的來源須明列。

3. 末段模式同意，但不能直接用目前 N 公式判斷入口

   現有公式含固定「＋2 秒」。以 `dt=0.2`：

   - 名目 1 秒段的 N＝5，整段估計 N 至少為 10，永遠放不進。
   - 名目 2 秒段的 N＝10，也幾乎只能在剩餘角度已為零時符合。

   改成：**嘗試有限時域的到位候選，完整驗收通過且能按時接管，才接受為末段**。公式可作候選搜尋的提示，不能當可行性證明。

   接受後鎖定該有限段，讓它執行停穩尾段，不再每 0.4 秒替換、反覆破壞停穩；安全監看和作廢條件仍持續。彈性終點列可沿用，但鬆弛未消除、未實測達 END 時，不得報完成或解綁。目標 85°、完成判準及其他限制不變。

4. 期限政策與加速都要做，不是二選一

   抓持、退出也須加入**符合當下接觸狀態**的期限政策；同時可把接觸停止軌跡生成等準備工作移到工作程序，分版本驗等值。

   但目前是算完後才檢查期限。這是「拒絕晚到結果」，不是保證在第 50 ms 已執行備援。整合時要核實際命令生效時間、計算期間管線如何前進，以及備援何時可用，不能靠假世界等計算時狀態不動掩蓋。

   50.1 ms 仍算晚到，不放寬門檻；正常拍與停止拍分開統計，避免停下後的低耗時稀釋結果。

5. 下一步順序

   **先補上述兩個正確性缺口與反例 → 加齊三個控制器的期限處理 → 做 P2 真管線換段整合。** 末段模式可獨立做一版對照，不必等它調到滿意才核接口。

   整合交付須涵蓋首段延遲、當下狀態接管、有界重接、實測停穩重啟，以及接管／停止期間的新故障。此時再分別報「任務是否完成」「安全拒絕是否正確」「是否連續 MotM」「是否符合控制期限」，不要合成一個 PASS。
