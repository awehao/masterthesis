**核可方案 A，並條件式核可下一趟 `m8house_door_motm_5`；有效讀回併在同一程序，不另開靜態趟。逐段計時也併這趟做。** 起跑前補齊以下兩點即可，不擴測試矩陣。

1. 摩擦設定採 `static=1、dynamic=1 N·m、viscous=0`。

   接受，但口徑須明確：靜、動摩擦相等是本版模型假設；viscous＝0 是維持既有 kp／kd＝600／60、不另外增加被動黏滯項，**不是完整還原 URDF dynamics，也不是實機摩擦辨識值**。本趟不再另加 1 N·m·s/rad，不加控制補償。

2. 逐軸 API 不能順便改掉其他限制。

   顯式保留原本的 angular `maxJointVelocity≈179.90875°/s`、armature 與各關節力矩上限，並讀回。避免套用逐軸 API 後，由預設值取代舊上限；控制器的 1 rad/s 限制也不變。[NVIDIA 逐軸優先規則與單位](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/110.1/dev_guide/joints/physx_joint_schema.html)

3. 起跑閘門必須讀到真正的後端設定。

   初始化、設定 gains 後，開始任務運動前，用後端 `get_dof_friction_properties()` 核六關節的三項值，並記錄 DOF 名稱、單位、kp/kd、速度及力矩上限。**不能只用舊 `get_friction_coefficients()`，也不能用 USD fallback 冒充執行期讀回。** 無法讀取、非有限或不符預期就拒跑，不能退回舊模型繼續。

4. 期限接受現況，但新增計時不得排除在期限之外。

   求解、閉鏈 IK／重力、掃掠準備、派工／等待、監看與整拍分開記；寫檔放迴圈外。交接預熱／試跑仍另報完整耗時。這些數字尚未證明 Isaac 已有 50 ms 餘裕，仍標非即時。
