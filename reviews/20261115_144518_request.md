# 有效屬性、摩擦映射修正方案、加速結果（接取證後裁定）

## 1. 六個手臂關節的有效屬性（靜態讀 USD＋執行器原始碼；未開 Isaac）
- 匯入模型 `omni_bot_manip_576`：
  - physics.usda：`PhysicsDriveAPI:angular`，`damping = 1`、`maxForce = 32`（joint4；各關節依 URDF effort），沒有寫 stiffness、沒有 drive type（預設 force）；另存 `urdf:dynamics:damping = 1`、`urdf:dynamics:friction = 1` 自訂屬性。
  - physx.usda：`PhysxJointAPI`，`physxJoint:jointFriction = 1`（六關節）、`maxJointVelocity = 179.9°/s`。
  - 全模型沒有任何 `physxJointAxis:*`（新版逐軸屬性）⇒ 沒有東西蓋過舊的 jointFriction。
- 執行器 isaac_m8_house_door_motm.py:213 `set_gains(kps=600, kds=60)`：執行期 kp／kd 取代 USD 的 damping=1（不是另一筆）；沒有碰摩擦、力矩上限、速度上限。
- 本機 schema（omni.usd.schema.physx 110.1.13）：
  - `physxJoint:jointFriction`：**無因次**，|F_resist| ≤ 係數×(|F|+|T|)（F、T＝母子連桿間傳遞的力與力矩）。
  - `PhysxJointAxisAPI`（physxJointAxis:angular:…）：`staticFrictionEffort`／`dynamicFrictionEffort` 單位＝力矩；`viscousFrictionCoefficient` 單位＝力矩·秒／**度**；說明寫明「與 PhysxJointAPI 重疊的參數，該軸以 PhysxJointAxisAPI 為準」。
- 對照取證趟：靜止時關節 4 傳遞的力矩是 N·m 級到十幾 N·m、力 30 N 級 ⇒ 係數 1 允許的摩擦上限遠大於量到的 5.6 N·m 殘差，量級上說得通（不是證明）。
- 未做：執行期讀回（PhysX 實際採用值）。我打算併在下一趟起跑前的同一個程序內做（world.reset 之前讀 USD 屬性、之後讀 articulation view 的 friction 係數並寫進 result），不另開一次 Isaac。若你要求獨立的「只載入不步進」讀回，請指示。

## 2. 映射修正方案（門任務版本化；不改共用 URDF、不改匯入快取、不改導航基準）
URDF `<dynamics friction="1.0" damping="1.0">` 的原意：friction＝庫倫摩擦力矩 1.0 N·m；damping＝黏滯 1.0 N·m·s/rad。
執行器在載入後、world.reset 前，對 joint1–joint6 以 USD API 設定（只在 `--arm-friction-model urdf_effort` 時；預設維持舊行為以便對照）：
- 套用 `PhysxJointAxisAPI:angular`：`staticFrictionEffort = 1.0`、`dynamicFrictionEffort = 1.0`（N·m，等於 URDF 值，不另調）；
- `viscousFrictionCoefficient = 0`：理由＝執行期已 `set_gains(kd=60)`，USD 的 damping=1 本來就被取代；不重複加。（若照 URDF 原意另加 1 N·m·s/rad，換成每度是 0.01745；我傾向不加，請裁定。）
- 舊的 `physxJoint:jointFriction` 保留檔案值不動（逐軸優先）；起跑時讀回兩者與 articulation view 的有效值，寫入 result；讀回不符預期（逐軸未生效）⇒ 拒跑。
- 不清零、不以「力低於 40 N」為目標選值。控制器模型不改（1 N·m 的庫倫摩擦在 kp=600 下對應約 1.7 mrad 靜差，已在現有偏置／閉鏈容差量級內；不宣稱已補償）。
- 揭露：與第 1–4 趟、取證趟的模擬模型不同；抓持段的行為可能跟著變（需照實重跑，不沿用舊趟的抓持結論）。
- 手指關節（URDF 無 friction）不動。

## 3. 等值加速結果
- (a) 重力：FastGravity3（同公式、合併質量矩），與 FastGravity2 最大差 4.4e-14 N·m，0.19→0.11 ms／次；整條鏈每拍中位 34.4–34.8、最大 44.4–46.9 ms（前 35.2／44.3）——**增益在雜訊內**。IK 未動（連續種子與分支不變）。
- (c) Isaac 內拆解（取證趟與第四趟的正常拍，n=3）：整拍 47.4–49.6 ms＝求解 12.4＋掃掠與備援核對 21.3＋其餘約 14–16；假世界同一程式整拍約 35。Isaac 內沒有逐段計時，無法再細分；差額可能來自算圖執行緒與 8＋2 個工作程序搶核心（8 核 16 緒）。我沒有把計算池加到 12。
- 結論照實：目前沒有把 Isaac 內的拍時間拉離 50 ms；下一趟仍可能在前幾拍晚到。差別是若摩擦映射修正後內應力消失，晚到後的閉鏈一致停法才有機會真的停穩。
