## 原因（已離線重現）
模擬器啟動時把 OPENBLAS_NUM_THREADS 改回 16 並讓主程序的 OpenBLAS 開了工作執行緒；這些執行緒在我把主執行緒移到 CPU 0 之前建立，留在 [1,2,9,10]——與模擬器執行緒及兩個規劃程序同一組 CPU。主執行緒做矩陣運算時在 CPU 0 等這些被擠掉的工作執行緒。
離線重現（模擬器 Python、無 Kit；6 個忙碌程序佔住 [1,2,9,10]）：120×120 矩陣乘 0.05 ms → **20.2 ms**，250×250 0.32 → 60.4 ms；以 ctypes 把 OpenBLAS 設成 1 執行緒後回到 0.048／0.32 ms。
⇒ 第十趟的失敗是我這次排程變更引入的，不是控制器或 B2 的問題；T2 的假世界核對沒有涵蓋「模擬器改寫 BLAS 設定」這件事（假世界沒有 Kit）。
