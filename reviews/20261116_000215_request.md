# 遠距整合第一包：離線接線骨架（可執行）＋真入口結果

commit 8dda1c9f4（已推）。程式 evaluation/door_far_link.py、door_far_link_check.py；結果 第八次進度報告素材/資料/door_far_link_check_r1.json。未跑模擬。

## 骨架內容（door_far_link）
1. `nav_baseline()`：只認原全開導航基準趟（isaac_bigarena_gmpc_scan_heading__seed8__fullon_s8_1）的現場紀錄——方法 gmpc_scan_heading、heading_enable 讀回 True、/cmd_vel 唯一發布者＝wheel_limit_guard、/cmd_vel_smoothed＝scan_safety_shield、/cmd_vel_nav＝gmpc_controller、Shield 與追蹤器訂閱 /scan；設定來源檔（run_bigarena_isaac.sh、lib/run_guards.sh）附雜湊。任一不符 ⇒ 不通過。本檔不內建另一套參數。
   **缺口**：該趟側錄的逐節點 param dump 全是空檔（當時 Node not found）——逐參數值沒有存檔，整合前要在基準配置下重 dump。
2. `Authority`：NAV／GRASP／OPEN／STOP，單一命令來源；非擁有者發布即拒並計數；切換只在交接核對全過時發生。
3. `HandleObs.intake(frame, t_now)`：深度影像＋內參＋同一渲染時刻的 FK 相機位姿＋讀值 → 凍結偵測 → 分類 → 幾何估計。缺欄位、缺同刻讀值、時間戳在未來、非有效中心、估計失敗 ⇒ 拒收＋原因。`est_fn()` 即 MovingGraspCtrl 的估計介面。不讀真值。
4. `pass_line(T_WH, …)`：通過方向＝−把手桿軸；門面法向＝接近軸；底盤朝向與側向位置＝讓「預抓構型的 TCP」落在「抓取位姿沿接近軸後退 S_PRE」處。全部由估計與機器人運動學算，不讀 full_2 的線。
5. `handover_request(…)`：命令權在 NAV、估計有效且年齡 ≤0.3 s、機器人在線上（側向 ≤10 mm、朝向 ≤1°）、沿線速度在 v_pass ±20%、尚未過抓取點、8 步管線完整、設定點與上一筆命令齊全 ⇒ 回交接包（座標系、通過線、設定點、管線、上一命令、估計與年齡）；否則回原因列表。

## 照實的限制
- 骨架還沒有真的把 ROS 導航節點接起來跑；`nav_baseline` 只核對基準紀錄，`Authority` 是邏輯層。
- 通過線的「何時開始沿線等速」（導航把機器人帶到線上並交出控制權的那一段）尚未設計：導航終點姿態＋進線段由誰控制。
- 估計只在兩格上跑過；移動中的延遲、模糊、時間同步未驗。
- 交接時的估計新鮮度（0.3 s）代表移動中需連續取像（偵測 42–67 ms／格）。
