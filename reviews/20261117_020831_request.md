# B1 離線證據：兩段入口方案送不到可接手區；請裁定是否改為「沿導航自然門前線＋觀察姿態＋越過把手時關節空間轉換」

唯讀討論，不改檔、不啟動模擬。本機 HEAD＝最新已推（結果在 evaluation/results/motm_b/）。

## 證據（運動學層離線；把手＝far_door_9 近距鎖定參考）
1. **奇異帶地圖**（door_band_map）：門旁分支在基座正對把手（a≈0.00–0.02）時，離門 0.45–0.80 任何距離、後退量 ≤0.45 都無 σ≥下限的解。⇒ 只要基座橫越把手正前方時手臂在追蹤分支，必撞帶；與離門距離無關（之前猜「離門 0.6 以上可越過」不成立）。
2. **可接手窗口地圖**（door_window_map；沿門 −a、0.05 m/s、2.2 s、σ／限位／淨空／Shield）：只有 a_w＝−0.08…−0.12、離門 0.45（a_w −0.08 時到 0.50）可行；a_w≤−0.16 或離門 ≥0.55 都不可行。
3. **B1 兩段實測路徑**（入口離門 0.6–0.7、終點門前線）：第 2 段在入口附近離把手太遠（終點 IK 失敗），回到門前線時已在把手後方 ~0.3 m（窗口不可行）⇒ 15 個候選接手點 0 可行。Smac 只給 45° 斜線＋軸向線，無法把路徑在 a≈−0.1 處「沿門、不轉向」地送進窗口。
4. **原導航自然路徑**本來就沿門前線（離門 ≈0.46）往 −a 走、正好穿過可接手窗口，方向與固定方向抓持模型一致、接手前不轉向。
5. **沿門前線的關節空間轉換**（door_line_transition_check）：手臂由導航姿態以最小急動 3 s（底盤 0.05 m/s，由 a＝+0.05 走到 a_w＝−0.10，期間越過奇異帶但不做 IK 追蹤）到接手點預抓位：淨空全過（self 8.6 mm、env ≥37 mm）、關節速率 0.94 rad/s（4 s：0.71）。**但轉換全程相機看不到把手**（導航姿態與預抓位都看不到）。

## 提議（請裁定）
- 不用兩段入口；**導航目標＝門前線遠端（由可接手窗口反推，離接手點 ≥0.45 m 以免到達容差停車），路徑＝Smac 自然門前線**；任務條件：朝向＝面門、窗口前 ~0.3 m 起速度框收到 0.05 m/s。
- 手臂：越過奇異帶前（a≥+0.1）用**觀察姿態**（相機朝把手、連續更新估計；需另搜一個沿門前線可見且連續的觀察構型）；接手前 3–4 s 由觀察姿態**關節空間**轉到接手預抓位（越帶時不追蹤）；轉換起點與終點構型以當下估計與預測接手狀態線上重算。盲段＝轉換期間約 0.15–0.2 m。
- D2：接手方向＝沿門 −a（路徑切向，接手前直線）；開門首段以預測接手狀態＋實測速度重規劃。
問題：可否改走這條？或你仍要求 B1 兩段，則需要接受更遠的接手點（目前判不可行）或換抓持分支。
