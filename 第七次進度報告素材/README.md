# 第一部分　D1 S4：腕部把手幾何辨識的線上 shadow 功能確認

**問題**：凍結的深度幾何辨識器（D1）能否在一趟真實執行的整機協調操作（MotM）中持續產生可追溯觀測，且不造成積壓、不接管控制？
**做法**：模擬器新增 `--wrist-live`（預設關）在 5 Hz 擷取點渲染腕部深度；獨立 shadow 節點以凍結 D1 處理（待處理槽 1 張、配對有界）；只發布 `/d1/handle_obs`，控制仍用真值。
規格 `規格/D1_S4_online_plan.md`（r1–r6，含 Codex 每輪必修）；結果 `規格/D1_S4_result.yaml`；稽核 `資料/d1s4b_M_d1_s4_audit.json`。

- **正式說法（Codex 審定）**：一趟整機協調操作中，幾何辨識器以 shadow 方式線上運行，438 格來源影格中 435 格完成處理與發布，接近窗口取得 44 格把手中心觀測；
  控制仍使用真值，任務判準通過。此結果支持限定配置下的線上觀測通路，不代表視覺閉迴路、實機或跨物件泛化。
- 通路：3 格在節點上線前遺失；覆蓋、逾時、工作執行緒錯誤 0；任務 S1–S6 全 PASS、重播 PASS、漏時槽 0（同版本無相機三趟 3／0／1 只作參考）。
- 時間：本趟 render-on-demand 配置下，讀取時刻均比影格時間戳晚約 0.200 s；以歷史位姿完成時間匹配（是否可改善尚未確認；時間匹配正確≠觀測足夠新鮮）。
- 第一趟 `d1s4_M` 是擷取端紀錄程式缺陷造成的 startup_failure，保留不計；修正後加入感知故障隔離（擷取例外先停用擷取、不中斷控制）。

**不能宣稱**：視覺閉迴路；線上 5 Hz 可用於控制（觀測晚約 0.2–0.4 s、未接控制）；0.2 s 是不可改善的固有延遲；相機零開銷（n = 1）；

程式 `產生程式/dl2_obs_to_target.py`、`dl2_eval.py`、`test_dl2_obs_to_target.py`（r3 36/36）；圖 12。

- **定位**：既有把手觀測（凍結幾何 G0、學習式遮罩 L1）結合明示抓取與方向先驗，能否生成一致的物體局部座標目標候選。
- **做法**：L2 中心＋L1 軸線＋前板法向（N-obs 由深度擬合前板；N-prior 鉛直先驗）→ DL1 組姿 → 兩個軸號候選各產生工具目標，以設計抓取旋轉選定 → s = 0／30 mm 目標。
- **結果（兩開發群組 186 格）**：0.4–2 m 候選率 G0 70/74、L1 65/74；2–3 m 明顯下降；候選缺失幾乎全來自偵測器沒有中心，N-obs 只多拒絕 1 格。
  0.4–3 m 抓取目標 TCP 位置誤差中位 G0 2.78 mm、L1 2.47 mm（p95 5.78／4.10 mm）。
- **限制**：滾轉誤差近 0 是模擬前板正好鉛直；軸號一致來自先驗；G0 與 L1 接受集合不同，中位數不能比較準度；無負樣本、相機位姿來自模擬器；同一把手、開發資料、未驗收新鮮度與碰撞，目標不可直接執行。

# 第七部分　DL3：幾何視覺預抓取接入（只到把手前 30 mm；不閉爪、不開抽屜）

**狀態：規格 draft-2 ＋最小實作與離線測試完成，送 Codex 審查中；尚未開跑。** 規格 `規格/DL3_vision_pregrasp_spec.md`；配置 `規格/DL3_control_config.yaml`；
離線鎖定演練 `資料/DL3_latch_rehearsal.json`；程式與測試見 `產生程式/dl3_*`、`run_nav_handover_dl3.sh`。

- **要回答的問題**：任務中 ALIGN 的接觸前目標改由視覺（凍結幾何偵測＋DL2 估計）鎖定時，能否接入既有控制並到位；其餘配置與 S4 正式趟相同。
- **鎖定規則**：ALIGN 進入時取前 5 s 內已收到的 ≥ 3 筆一致估計（中心 5 mm、軸與法向 3°）融合；不足或不一致即受控停止，不回退真值。
- **離線演練（既有 S4 紀錄）**：7 筆入選、年齡 3.25–4.85 s、散佈 1.58 mm／0.65°／0.35°；鎖定目標對真值偏 2.25 mm／0.25°。
- **前檢**：GC2 對估計物體（只代表抓取與物體模型相容）、固定底盤 IK（含 0.05 rad 有效限位餘量）。
- **測試**：鎖定 18、視覺節點 12、任務整合 16（真值刻意偏 30 mm，目標只跟估計）、truth 模式回歸 7×2。
- **鎖定前不發任何目標**（求解端須收到鎖定後目標才開始）；不使用地圖先驗。
- **不能宣稱**：夾持、開抽屜、學習式控制、泛化。
