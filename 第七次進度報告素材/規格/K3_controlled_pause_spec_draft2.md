## ① 凍結＝最後已發布目標
- `PauseReference` 記錄每筆已發布目標 (seq, t, T)。觸發當輪**不推進** DoorTargetK3，`freeze()` 鎖住上一筆已發布目標並記錄其 seq 與 t。
- 凍結前若沒有任何已發布目標，就拒絕凍結。凍結後再收到的目標不會更新；回傳值是複本。
- 離線逐週期核對：凍結後使用的目標與該 seq 的已發布目標逐元素相同。
- **P1 觸發改為正式 SETTLE 條件**：|q − 8°| ≤ 0.5°、|q̇| ≤ 0.002 rad/s，連續 1.0 s，與 `door_k3a_policy` 的 SETTLE 相同。不再用「q_ref 到 8° 後 1 s」。
  - 離線工具沒有漂移量與接觸量，這兩項 SETTLE 子條件不在核對內。

## ② 減速命令在共同可行集合內（以 applied u_prev 承接）
`decel_step(u_prev_applied, u_goal)` 以**上一物理步實際套用**的底盤命令為起點，依序：
1. 逐軸朝 u_goal 移動，每步變化 ≤ 0.8·a·dt；
2. 截在逐軸速度框內（0.035255 m/s、0.1999 rad/s）；
3. 輪級檢查沿用 `wb_wheel_limit` 的本體輪速矩陣 W：輪速 ≤ r·ω_max，每步輪速變化 ≤ r·α_max·dt。不符時，沿 u_prev→u 線段二分縮短（與 limit9 同一種 λ 語意，只用底盤三軸）。

- 保持段的伺服命令（park_hold_cmd）同樣經 `decel_step`，所以減速→保持的切換也受同一組限制。
- 反例：Codex 舉的 applied 0.035255 m/s、量測 0.010 m/s。
  - 舊律以量測為起點，要求直接給 0；相對 applied 的變化 0.035 > 0.025 框，不可行。
  - 新律由 applied 承接，變化 = 0.8 框。
- 200 組隨機起點 × 30 步（含中途換伺服目標）逐步都在可行集合內。輪速上限與輪加速度上限都有反例。
- 離線逐週期核對 `feasible(applied, base_hold)`。

## ③ 分段完成序列（PauseSequencer）
| 狀態 | 進入條件 | 本狀態發布 |
|---|---|---|
| LOWSPEED | 觸發 | 正常求解結果（底盤＝base_hold） |
| ZERO_PUB | 量測低速連續 1.0 s：底盤線速 ≤ 1 mm/s、角速 ≤ 0.005 rad/s、門速 ≤ 0.002 rad/s、手臂套用速率 ≤ 1e-3 rad/s | 手臂 0；底盤＝decel_step 朝 0 |
| CONFIRM | 發布的底盤命令已為 0 | 零速 |
| STOPPED | 執行端套用值（底盤＋手臂）≤ 1e-6，連續 5 物理步，且來源發布序號 ≥ 零速第一筆 | **停止發布** |
| DONE | STOPPED 後觀察 1.0 s，量測仍低速 | — |
| FAIL | 任一週期求解失敗（LOWSPEED／ZERO_PUB）、量測無效、套用回報無效、逾時 8 s、STOPPED 後又動 | 走既有閂鎖，記為暫停失敗 |

- 求解失敗時，閉迴路工具會代入零命令。這條退化路徑判 FAIL，不算健康暫停成功。
- 報告取**各狀態轉換當下**的量，不取觀察窗末。
