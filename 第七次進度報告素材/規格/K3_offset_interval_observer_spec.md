# 有限區間等效偏移觀測：候選規格（2026-10-22；純離線，未接入、未實跑）

上位：Codex 20261022 旋轉定位 r4 裁定。r4 封存為「兩趟既有資料的探索性旋轉追蹤診斷」。

## 0. r4 說法修正
- 「約十倍」撤回，改為：兩趟 OPEN 期間，相鄰快照的繞桿旋轉殘差多為負向（83%），平均約 −0.08°／區間；HOLD 約 +0.01°／區間。
  兩者平均絕對值相差約 8–9 倍。運動期間的模型預測落差較大，但尚不能區分負載、估計誤差與其他動態因素。
- 求解區間是 4 或 6 個物理步（各約一半），不是固定 50 ms。跨相位切換的區間依起點歸類。

## 1. 觀測式
手臂模型（每物理步、逐軸）：q⁺ = q + α(s − q) + α·d，s⁺ = s + dt_p·u（α、dt_p 取自 `wgmpc_arm_sp_ident_free4.json`）。
d 在區間內近似恆定時，m 步後 d 對 q 的貢獻為 d·[1 − (1 − α)^m]，對 d 為線性。所以先用前一估計 d̂ 預測區間終點 q_pred，再得

  **d_obs = d̂ + (q_meas − q_pred) / (1 − (1 − α)^m)**，m＝區間實際物理步數。

d_obs 是「區間內近似恆定的等效偏移」，**不是真實負載**。

## 2. 更新與界線（事前登錄）
- 只在區間結束、資料完整時更新：q_k、s_k、各步套用速度、q_{k+1} 都有限，且 m ≥ 1。否則保持 d̂ 並記錄原因。
- 濾波：d̂ ← clip(d̂ + (m·dt_p/τ)(d_obs − d̂), ±max)，**沿用** τ＝0.5 s、max＝0.05 rad。不把殘差當固定前饋。
- 預測一律用**更新前**的 d̂；回報的是樣本外殘差。不以同區間反解後的近零殘差當改善證據。
- 不改其他控制、安全參數或門檻；不接節點。

## 6. 措辭修正（取代 §4 判讀中的對應句）
- 改善限於繞桿旋轉殘差的**平均絕對值**：約減 22%／27%。**不是所有關節都改善**：door_k3a_1 的 j1、j2 平均 |殘差| 反而變大（j1 0.469→0.479、j2 0.656→0.766 mrad）。
- 「17→25 mrad」指**等效偏移觀測 d_obs**；濾波後 d̂ 末值約 **22.5／22.2 mrad**。
- 回放使用區間內已發生的實際輸入，殘差稱「**更新前估計的區間條件預測殘差**」。這不代表區間起點就知道未來的套用命令。
- 只說「本資料、此濾波下仍有方向性殘差」；不推論這類觀測器必然無法解決。

## 7. 兩項防護（`offset_interval.py`；測試 12/12，含 `-W error::RuntimeWarning` 嚴格模式）
1. **有限性**：alpha、phys_dt、τ、max、d0 任一非有限 ⇒ 拒絕建構。運算結果（殘差、d_obs、新 d̂）非有限 ⇒ 保持、不提交，why＝nonfinite_result。
   - 反例：d0＝NaN／inf、τ／max／phys_dt＝inf 或 NaN、alpha 含 NaN 都拒絕；輸入有限但 s − q 溢位 ⇒ 保持且 d̂ 不變。
2. **區間長度**：登錄 m ∈ [1, m_max]，**m_max＝10** 物理步（名目 4–6 步的約兩倍）。建構時檢查 m_max·dt_p/τ ≤ 1（本設定為 0.2）。
   超出 ⇒ 保持，why＝interval_too_long；濾波公式與 τ 不改。
   - 反例：100 步區間被保持，d̂ 維持 +0.01 不翻號；10 步區間照常更新；τ＝0.05 搭配 m_max＝10（增益 2）拒絕建構。

## 8. 線上資料契約（接線小規格；先登錄，不實作）
**資料來源**（執行端每個物理步發布，帶同一個 physics_step_id 與 sim_t；現有求解節點已訂閱）：
- `/coman/arm_setpoint`：[step_id, sim_t, ready, sp1..6, exec_mode, api_applied]，該步**實際寫進 API 的設定點**。
- `/coman/applied_cmd`：[step_id, sim_t, 底盤 3, qd1..6, …]，該步送進物理 API 的命令速率。

**區間組成**：
- 相鄰兩個求解快照 k、k＋1 各帶 sp_step_id。區間＝物理步 (step_k, step_{k+1}]，m＝step_{k+1} − step_k。
- 預測所需的設定點序列＝**逐步實際設定點** s_j，j＝step_k … step_{k+1}−1，直接取自 `/coman/arm_setpoint` 的步號緩衝。
  **不積分、不拿求解請求或包絡值補成實際輸入。**

**完整性條件**（任一不成立 ⇒ 該區間保持並記原因，不提交）：
1. 步號從 step_k 到 step_{k+1} 連續、不重複、不倒退；每步都有 ready＝1、api_applied＝1，且值有限。
2. 每步兩個話題的 (step_id, sim_t) 一致（沿用節點既有的 `_step_t` 交叉核對；不一致的步不入緩衝）。
3. 起點快照的 s_meas 與緩衝中 step_k 的設定點逐軸相等（容差 1e-9），終點同理。
4. 設定點積分對帳：s_{j+1} − s_j 與 dt_p·u_{j+1}（同步號的 applied_cmd 手臂部分）之差 ≤ 1e-6 rad。這是核對設定點與命令兩個來源，不是改用積分。
5. 區間內 exec_mode 不變（避免跨停止、切換段）；1 ≤ m ≤ m_max。
6. 緩衝有界：只保留最近 256 步（同 `_step_t`）。區間所需的步若已被淘汰 ⇒ 視為缺漏。
7. 過期：快照年齡沿用節點既有的新鮮度判定；過期快照不形成區間。
