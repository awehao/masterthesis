# 兩瓶＋L 型走廊短設計（F1-L；Codex 20261103_064605）

**狀態**：只有設計與離線規劃核對，未跑假世界與 Isaac。

**目標**：沿用兩瓶、短返回與現行抓放堆疊，在搬運路徑加入 1.20 m 內淨寬的 L 型走廊，增加多物件任務中的狹窄空間與轉彎挑戰。不疊加移動物、不提高車速上限、不宣稱一般居家部署。

## 風險（照實報，不預先調參）

1. **持瓶時間變長**：運送約多 12.5 s／輪。`bottle_f1_3` 較大的那輪，PARKED 後滑移速率是 0.37 mm/s；若運送中也這樣滑，品質會更差。不加力、不調摩擦、不放寬門檻。
2. **牆被誤判成動態**：動態邊距 0.69 m 大於走廊半寬 0.60 m，只要牆被追蹤器當成動態，走廊內就沒有可行解，會用鬆弛或受控停止。這是這一案最可能的第一阻點。不調追蹤門檻，假世界先量。
3. **靜態邊距窄**：0.055 m。追蹤誤差或點數上限都可能讓 CBF 頻繁貼合，甚至停止。
4. **接直線段折角 87°／107°**：比原場景大很多，而且緊接手臂升高。
5. **視覺背景**：牆是學習模型沒看過的背景，可能影響第一桌選物。不重訓；實跑才看得出來。

## 實作與前置（核可後）

- **場景**：一份 JSON 同步進物理、地圖、掃描與接觸判定；底盤、手臂、手指、持瓶對牆都算禁止接觸。新版本腳本，不動封存 `gmpc.py`／`gmpc_node.py`。
- **第二桌**：放置點、地圖桌腳、報告與假世界改讀同一檔。
- **假世界 `lchan`**（真追蹤器＋射線掃描＋GMPC＋Shield）：兩輪完成；牆的誤判動態拍數；靜態列貼合與 ε₀；全身、持瓶、轉彎與停止掃掠對牆都 > 0；進走廊時是否已收近（時間式觸發，沒有閘）；任務期限。
- **回歸**：只跑受影響的 `nominal`、`abort0`、`crash` 三案。
- **之後才申請一趟物理**：通過也只交結果與第一阻點，由 Codex 決定是否起跑。
