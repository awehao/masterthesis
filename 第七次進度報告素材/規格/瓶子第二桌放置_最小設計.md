## 2. 場景與流程

### 2.1 第二桌位置

- 用同一份桌子資產（頂高 0.60、0.8×0.5 m）。中心放在 (2.4, −0.39)，對應的放置直線 y＝−1.0，桌子近緣在 y＝−0.64。放置直線和抓取直線錯開 1.0 m，持瓶段得轉向，才用得到規劃。
- 起點、方塊、第一桌、瓶子都同 S1。舊出口區不再使用。
- 桌腳進已知地圖與掃描；桌面在掃描面之上，LiDAR 看不到，所以桌面、手臂、瓶子的安全由三維幾何判定與接觸通道負責，不拿桌腳安全代替。

### 2.2 停車位與放置點

停車位姿 P_park 取「放置點 ⊖ 持瓶相對位姿」：

- 持瓶相對位姿是持瓶段起點量到的「TCP 相對底盤」與「瓶相對 TCP」。
- 停車後，瓶底比第二桌頂面高出的距離，就等於抬升後的實際高度（約 40–50 mm）。
- 手臂構型和已驗證的抬升相同，下降就是抬升的逆過程，不需要新的手臂分支。
- 放置點名目為 (2.4, −0.58)，距桌近緣 6 cm，和第一桌的瓶位相同。實際落點由停車位姿與持瓶相對位姿決定，事後以瓶子實際位姿判定。

### 2.3 持瓶段規劃

- LIFT 開始時，以當下量測的底盤位姿為起點，向 planner_server 請求到「放置直線入口」（停車位 x 往回 0.6 m、y＝−1.0）的路徑。接著是指定直線，在 P_park 停下。
- **採用條件**：
  - 和 N2 相同：frame＝map，起點、終點、間距、代價都要核對，接上直線的 Bézier 段也要再核對一次。
  - 新增連續性條件：採用當下，機器人到新路徑的橫向距離 ≤ 0.05 m。
- 規劃回覆到之前，沿 LIFT 原參考，不加速。CARRY 開始時仍沒有有效路徑，就受控停止，不退回直線出口路線。
- **進度統一用弧長 σ**：CARRY 錨定在實際底盤 SE(2)，σ 由投影取得（只往前找、不低於起點）。新控制器自己處理參考推進與領先限制，不殘留任何世界 x 的夾限（不沿用 S0b 的 `s_ref ≤ x＋S_LEAD`）。
- 路徑監看同 N2：剩餘規劃段遇內切以上代價，或代價圖超過 2 s 未更新，就受控停止。不重規劃（P4 另案）。

### 2.4 放置相位

| 相位 | 內容 | 進入下一相位的條件（事前定） |
|---|---|---|
| PLACE_APPROACH | 直線上依剩餘距離減速到 0，參考停在 P_park | 參考到 P_park |
| PARKED | 底盤命令 0，手臂維持持瓶 | 實測底盤速度 < 0.01 m/s、\|ω\| < 0.02 rad/s 連續 0.5 s，位置誤差 ≤ 20 mm、偏航誤差 ≤ 1° |
| LOWER | TCP 沿世界 −z 以 ≤ 0.02 m/s 下降，最多下降「抬升高度＋10 mm」 | 支撐成立：瓶↔第二桌法向力 ≥ 0.5 mg（0.98 N）連續 0.3 s，瓶傾角 ≤ 3° |
| RELEASE | TCP 保持，手指 0.5 s 斜坡張開 | 兩指↔瓶力 < 0.05 N 連續 0.5 s（張開後 2 s 期限內） |
| RETREAT | TCP 沿工具 −z（抓取插入的反方向）退 0.06 m，再回 K2_READY；底盤保持停住 | 手臂全連桿↔瓶淨空 ≥ 10 mm，且回到 K2_READY |
| HOLD | 全部靜止 3 s 觀察 | 第 3 節的放置成功條件全部成立 ⇒ DONE |

LOWER 走到下降上限仍未支撐，或任何相位超過期限（事前定為名目時長 ×3），就走既有受控停止。期限屬於判準，跑之前凍結。

## 3. 放置成功與安全（分開判定，事前凍結）

**放置成功**：以下全部成立，才算 DONE。不以 TCP 到位、張爪命令或相位 DONE 代替。

1. 鬆爪前支撐已成立（同 LOWER 條件）。
2. 兩指解除接觸（同 RELEASE 條件）。
3. 從鬆爪到 HOLD 結束：瓶位移 ≤ 5 mm、傾角 ≤ 3°；最後 1 s 瓶速 < 1 mm/s；瓶↔第二桌法向力 ≥ 0.9 mg。
4. 瓶軸離第二桌任一桌緣 ≥ 半徑＋10 mm；落點離名目放置點 ≤ 30 mm（只報告、不設門）。

**安全**：既有判準全部保留。

- 禁止接觸：≥0.05 N 連續 3 物理步，或穿透 ≥1 mm。
- 新增通道：手臂與手指↔第二桌（桌面、桌腳）、底盤↔第二桌桌腳、瓶↔第二桌桌腳、瓶↔第一桌（抬離後）。
- 指定接觸只有兩個：手指↔瓶（RELEASE 完成前）、瓶底↔第二桌桌面（LOWER 起）。掌面、非手指連桿↔瓶仍禁止。
- 缺資料不當零；Shield、資料有效性、92 °C 熱中止、既有抓持判準照舊。
- 不用焊接、瞬移，也不直接改物件位姿來冒充放置。

## 5. 視覺分階段

| 階段 | 相機與估計 | 進控制？ |
|---|---|---|
| V1 旁路 | 底盤相機（base_camera，RealSense 型）與手腕相機（camera_link，門任務 D1／CP1 用過）出 RGB-D。保存來源時間（模擬時鐘）、frame、內參、有效性。瓶位姿估計：深度在桌面平面上方分割＋圓柱擬合，已知瓶型。每筆估計對真值記誤差；真值只做評估。 | 否 |
| V2 | 瓶位姿估計進抓取目標；估計缺失、過期（> 0.3 s）或跳變（> 10 mm）時，依事前規則保持、重估或停止，不默默退回真值。 | 是（瓶） |
| V3 | 第二桌桌面與放置區由視覺估計。 | 是（桌） |

V1 不和第二桌首次物理放置同一趟改控制來源。相機渲染會增加負載：V1 只存估計與稀疏影格，影格頻率另定。

## 6. 第一包與實跑申請

**第一包（只有離線與假世界，不開 Isaac）**

- 新版本檔：場景（加第二桌與接觸通道）、地圖加第二桌桌腳、放置控制器（新類別，弧長進度、無 x 夾限）、持瓶段規劃請求與採用核對、放置判定。
- 假受控對象：瓶在 LOWER 接觸桌面後由支撐承接、鬆爪後留在原位。驗相位、判定與停止路徑。
- 負測：持瓶規劃失敗 ⇒ 停止；下降到上限仍未支撐 ⇒ 停止；支撐未成立不准鬆爪；鬆爪後手指仍有力 ⇒ 不准退離；路徑被擋 ⇒ 停止。
- 離線幾何：持瓶規劃路線上的手臂、瓶對兩張桌與方塊的淨空；停車構型的手臂關節餘裕；退離段手指↔瓶淨空。

**實跑申請（第一包通過後另送）**：bottle_p1_1 一趟，S1 場景＋第二桌、N1 鏈路＋兩段規劃、真值瓶位姿，停車放置。開視窗、熱守護、不錄影、失敗不補跑。

**不做**：返家、再次抓取、比較矩陣、S3 三維障礙與放置同趟、視覺進控制。
