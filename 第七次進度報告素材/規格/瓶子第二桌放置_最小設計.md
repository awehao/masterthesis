## 1. 任務與沿用

## 2. 場景與流程

### 2.1 第二桌位置

- 用同一份桌子資產（頂高 0.60、0.8×0.5 m）。中心放在 (2.4, −0.39)，對應的放置直線 y＝−1.0，桌子近緣在 y＝−0.64。放置直線和抓取直線錯開 1.0 m，持瓶段得轉向，才用得到規劃。
- 起點、方塊、第一桌、瓶子都同 S1。舊出口區不再使用。
- 桌腳進已知地圖與掃描；桌面在掃描面之上，LiDAR 看不到，所以桌面、手臂、瓶子的安全由三維幾何判定與接觸通道負責，不拿桌腳安全代替。

### 2.2 停車位與放置點

- **底盤朝向**：明定停車偏航 θ_park＝0（與放置直線同向），不讓幾何解自由選。
- **停車位置**：用完整座標變換解平面位置。底盤→TCP 取當下實際構型，TCP→瓶取抓持成立時固定的 T_rel。解出讓瓶軸 xy 落在放置點 (2.4, −0.58) 的 P_park＝(x, y, 0)。
  - 持瓶段一開始算一次，作為規劃目標。
  - PARKED 時用實際構型重算一次，偏差超過 15 mm 就停止。第一版不做原地微調。
- **不宣稱**「下降就是已驗證抬升的逆過程」。搬運中手臂會變（CARRY 的 TCP 底盤座標任務仍會調整），所以要另外核對：
  - PARKED 時的實際構型與關節餘裕。
  - 下降段：手臂與瓶對兩張桌的淨空。
  - 退離段：手指與手臂對瓶的淨空。
  - 第一包離線核對，實跑時 PARKED 線上再核一次，不過就停止。
- 放置點名目距第二桌近緣 6 cm。實際落點以瓶子實際位姿判定。

### 2.3 持瓶段規劃

- LIFT 開始時向 planner_server 請求到「放置直線入口」（P_park 往回 0.6 m，沿 θ_park）的路徑，接著是指定直線，在 P_park 停下。請求起點＝實測底盤位姿沿實測速度外推 LIFT 名目時長（1.0 s）的預測位姿：以 LIFT 開始時的位置當起點，到 CARRY 時機器人已前進數公分，真規劃器路徑初始斜向，橫向距離會超過 0.05 m（bottle_place_fake1 實測 0.0506 m）。
- 規劃回覆到之前，沿 LIFT 原參考，不加速。
- **CARRY 開始時採用**，用最新實際狀態重新核對，全部通過才換參考：
  - N2 的路徑核對：frame、起終點、間距、代價、Bézier 接段。
  - 承接點：取在途命令走完後的預測底盤位姿，投影到新路徑。
  - 承接（draft-2 修正，Codex 20261101_035929 同意以 Bézier 取代切向差 ≤20°）：從在途預測位姿、沿當下速度方向，用三次 Bézier 相切接到路徑前方 0.8 m。
  - 核對：橫向 ≤ 0.05 m；接段每 20 mm 轉角 ≤ 3°；以持瓶速度上限估的最大橫向加速度 ≤ 0.5 m/s²；承接前後參考點跳動 ≤ 0.05 m。
  - 參考速度沿用承接前的參考速度，參考對實測的領先量也沿用（≤ S_LEAD），位置與速度都連續；之後依既有斜率限制升到 v_carry。
  - 停車位在 CARRY 採用時以實際構型重算；規劃段、接段、直線段到停車位整條都過代價核對。
  - 任一項不過，或 CARRY 開始時仍沒有有效路徑，就受控停止，不退回直線出口路線。
- **進度統一用弧長 σ**：CARRY 錨定在實際底盤 SE(2)，σ 由投影取得（只往前找、不低於起點）。新控制器自己處理參考推進與領先限制，不殘留任何世界 x 的夾限（不沿用 S0b 的 `s_ref ≤ x＋S_LEAD`）。
- 路徑監看同 N2：剩餘規劃段遇內切以上代價，或代價圖超過 2 s 未更新，就受控停止。不重規劃（P4 另案）。

### 2.4 放置相位

| 相位 | 內容 | 進入下一相位的條件（事前定） |
|---|---|---|
| PLACE_APPROACH | 直線上依剩餘距離減速到 0，參考停在 P_park | 參考到 P_park |
| PARKED | 底盤命令 0，手臂維持持瓶 | 實測底盤速度 < 0.01 m/s、\|ω\| < 0.02 rad/s 連續 0.5 s，位置誤差 ≤ 20 mm、偏航誤差 ≤ 1° |
| LOWER | TCP 沿世界 −z 下降（詳見下方 LOWER 細節） | 支撐成立（詳見下方） |
| RELEASE | 只在支撐成立後准入；TCP 保持，手指 0.5 s 斜坡張開 | 實際手指開度 ≥ 0.8×全開，且兩指↔瓶力 < 0.05 N，連續 0.5 s（張開後 2 s 期限內） |
| RETREAT | TCP 沿工具 −z（抓取插入的反方向）退 0.06 m，再回 K2_READY；底盤保持停住 | 手臂全連桿↔瓶淨空 ≥ 10 mm，且回到 K2_READY |
| HOLD | 全部靜止 3 s 觀察 | 第 3 節的放置成功條件全部成立 ⇒ DONE |

**LOWER 細節**
- 快段 0.02 m/s：下降到預測瓶底高出桌面 10 mm 為止。預測用實測 TCP、T_rel，並納入在途命令走完後的位置。
- 預接觸段 0.005 m/s：在途 8 步只多走 0.4 mm。
- 首次有效支撐：
  - 瓶↔第二桌接觸力沿桌面法向（世界 +z）的分量 ≥ 0.98 N，水平分量 ≤ 0.3 倍法向。
  - 瓶底實際高度離桌面 ≤ 3 mm。
  - 瓶軸 xy 在放置區內。
- 首次有效支撐出現後，凍結下降目標、不再加深，接著確認連續 0.3 s 都符合，才算支撐成立。側碰（法向分量不足，或瓶底不在桌面高度）不算支撐。
- 走到下降上限（抬升高度＋10 mm）仍未支撐，就受控停止。

**失抓監看**：既有的抓持監看（掉瓶、滑移）一直到 RELEASE 准入前都照常有效；准入之後才把「手指脫離接觸」改成預期事件。

任何相位超過期限（名目時長 ×3），就走既有受控停止。期限屬於判準，跑之前凍結。

## 3. 放置成功與安全（分開判定，事前凍結）

**放置成功**：以下全部成立，才算 DONE。不以 TCP 到位、張爪命令或相位 DONE 代替。

1. 鬆爪前支撐已成立（同 LOWER 條件）。
2. 兩指解除接觸，且實際手指開度達標（同 RELEASE 條件）。
3. 從鬆爪到 HOLD 結束：瓶位移 ≤ 5 mm、傾角 ≤ 3°；最後 1 s 瓶速 < 1 mm/s；瓶↔第二桌法向力 ≥ 0.9 mg。
4. 瓶軸離第二桌任一桌緣 ≥ 半徑＋10 mm；落點離名目放置點 ≤ 30 mm（只報告、不設門）。

**安全**：既有判準全部保留。

- 禁止接觸：≥0.05 N 連續 3 物理步，或穿透 ≥1 mm。
- 新增通道：手臂與手指↔第二桌（桌面、桌腳）、底盤↔第二桌桌腳、瓶↔第二桌桌腳、瓶↔第一桌（抬離後）。
- 指定接觸只有兩個：手指↔瓶（RELEASE 完成前）、瓶底↔第二桌桌面（LOWER 起）。掌面、非手指連桿↔瓶仍禁止。
- 缺資料不當零；Shield、資料有效性、92 °C 熱中止、既有抓持判準照舊。
- 不用焊接、瞬移，也不直接改物件位姿來冒充放置。

## draft-3 變更（bottle_p1_1、p1_2 之後；Codex 20261101_043002、20261101_043404）

**實測依據**：bottle_p1_2 的 place_log 顯示，首次接觸後桌面回報的向上接觸力，每 0.1 s 平均穩定在 0.59–0.66 N（約 0.33 mg）。接觸初期約 0.4 s，逐步在 0 和 1.0–2.4 N 之間交替。原本的 0.5 mg 連續 0.3 s 在鬆爪前達不到。夾爪仍分擔重量是合理解釋，但缺摩擦力資料，無法斷言分擔比例。

**鬆爪准入改為「接觸就緒」**（不是已獨立承重）
- 首次接觸（凍結下降）：單步 fz ≥ 0.25 mg、水平 ≤ 0.3 fz、瓶底間隙 ≤ 3 mm、傾角 ≤ 3°、在放置區內。
- 就緒：首次接觸後最近 0.3 s 的窗內，樣本全部有效；平均 fz ≥ 0.25 mg；平均水平 ≤ 0.3×平均 fz；每筆間隙、傾角、在區內都成立；最小 fz ≥ −0.05 N（無反向力）；fz < 0.05 N 連續不超過 5 步。
- 不額外下壓。窗口只用在接觸就緒，不套到失抓、禁止接觸等既有判準。
- 鬆爪後原驗收不變：HOLD 期間 fz ≥ 0.9 mg、位移 ≤ 5 mm、傾角 ≤ 3°、末 1 s 速度 < 1 mm/s、手指解除接觸、退離淨空。

**停止有效改為「有界微動下的停穩」**（判準變更，只用在放置複本；不是證明瞬時速度低於原門檻）
- bottle_p1_1、p1_2 停止後，手臂每步約 1e-5 rad 往返微動，逐步差分 50–60% 的步數 > 1e-3 rad/s。原判定（p1_1 有效、p1_2 無效）保留。
- 停止後第 0.5–1.5 s 須全部成立：
  - 命令為 0、在途佇列為 0、設定點固定。
  - 所有滑動 0.5 s 窗：手臂各關節位移速率 ≤ 1e-3 rad/s，底盤平移 ≤ 0.01 m/s。
  - 整個觀察窗峰峰值：手臂 ≤ 1e-3 rad，底盤 x、y ≤ 5 mm，偏航 ≤ 0.002 rad。
- 覆蓋率 < 95% 或含非有限值，判未驗證（ok＝None），不能通過。

## V1 視覺旁路設計（draft-1，Codex 20261101_045309；不進控制）

**選相機**（evaluation/bottle_v1_cam_visibility.py，沿 bottle_p1_3 量測軌跡的純幾何可見度，瓶軸 10 點、盒遮擋近似）

| 階段 | 底盤相機（URDF base_camera，hfov 87°、深度 0.3–8 m） | 手腕相機（camera_link，hfov 69°、fx 465.6） |
|---|---|---|
| 導航（距瓶 1.8–3.4 m） | 70% 看得到、瓶寬 3–6 px | 61%、4–8 px |
| 展臂接近（0.5–1.8 m） | 53%、6–20 px | 30%（手臂轉動）、8–100 px |
| PREGRASP／INSERT／CLOSE | 0（瓶在車側、出視野） | PREGRASP 看得到（0.14 m、100 px），INSERT 13%，CLOSE 0 |

V1 選**底盤相機**：外參固定在底盤，接近段從 3.4 m 到 0.5 m 都有機會看到。手腕相機只在最後 0.14 m 清楚，且展臂時指向在變，留作 V1b 近距補強。

**資料與時間**
- Isaac 以底盤相機光學座標（URDF 外參）建相機，5 Hz（每 20 物理步）出 RGB（640×480）、光軸深度（float32 m）、讀回內參。
- 每格附擷取時刻（模擬時鐘）與擷取時刻的相機世界位姿：由底盤量測位姿乘固定外參，並和渲染端回讀核對。
- 相機與估計走 ROS 話題（/v1/color、/v1/depth、/v1/camera_info，stamp＝擷取時刻）。估計節點另一程序，發 /v1/bottle_estimate（stamp＝影格擷取時刻，另附處理耗時）。
- 物理步、控制週期不改。相機負載只量牆鐘，不靠改步長吸收。

**估計（非 oracle）**
- 深度反投影到世界座標（光軸 Z、公尺）。
- 桌面高度與範圍取已知地圖（任務先驗，不是瓶子真值）。原本用 RANSAC 找桌面，但底盤相機離地約 0.36 m，低於桌面 0.6 m，看不到桌面；合成核對時把桌板正面、方塊側面當成平面（z 誤差 30–195 mm、遠距誤認方塊），所以改用先驗。
- 取桌子範圍內、桌面上方 0.02–0.25 m 的點分群，挑符合已知瓶型（半徑 15 mm、高約 0.2 m、近直立）的群。
- 固定半徑圓擬合得瓶軸 xy；軸向用 PCA（有估）。瓶底 z 兩種推法分開標：z_from_support＝桌面高度（支撐假設）、z_from_top＝觀測瓶頂−瓶高（瓶型假設，瓶頂出視野時錯）。
- 只估瓶中心位置與軸方向，繞軸朝向不估（圓柱對稱）。
- 不用真值遮罩或 ROI。

**評估**（真值只在評估端）
- 有效率。
- 位置誤差：xy、z。
- 軸角誤差。
- 資料年齡：估計發布的模擬時間減擷取時刻。
- 處理耗時：牆鐘。
- 依距離與相位分層。
- 沒有估計就記失敗，不用真值補。

**離線核對**（不開 Isaac）：以 Python 射線投射合成無雜訊深度圖（桌、腳、方塊、瓶圓柱，同 p1_3 軌跡與相機外參），驗證座標約定與估計器在理想資料下的誤差。不能代表渲染深度的表現。

**採集申請**（另送）：同 p1_3 配置，加旁路相機與估計節點，一趟，不進控制、不改抓放。

**V1 離線核對結果**
- 合成資料（Python 射線投射、無雜訊、無機器人自遮擋，沿 p1_3 軌跡 5 Hz，抓取前 104 格）：
  - 約定：像素深度＝光軸 Z，且確實和沿射線距離不同；反投影能回到原點。
  - 有效率：全部 0.538（56/104）；幾何預期可見 1.000（54/54）。
  - 失敗都是近距瓶子出視野或被桌緣擋住（no_object_points）。
  - xy 誤差 < 1e-4 mm（理想資料，只代表演算法一致）；軸角最大 1.34°。
  - z_from_support 0.002 mm；z_from_top 在 1–2 m 為 0.53 mm，近距瓶頂出視野時可錯 98 mm。
- ROS 整合（真估計節點、不開 Isaac）：同戳配對、缺話題不估、壞訊息回失敗、佇列有界有丟棄計數；資料年齡 0.01 s（模擬時間）、處理 5–6 ms。
