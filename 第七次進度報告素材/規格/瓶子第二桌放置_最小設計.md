## 1. 任務與沿用

導航避障 → 移動接近及抓瓶 → 抬離與持瓶搬運 → 接近第二桌 → 停車放置 → 確認支撐、鬆爪、退離。

| 部分 | 第一版做法 |
|---|---|
| 抓取 | 沿用 bottle_n2_1：同一個全身 GMPC、移動中抓取，K2_READY 起始，速度 0.35／0.10／0.25 m/s |
| 掃描與 Shield | 沿用 N1 真 ROS 話題鏈路 |
| 起點→抓取直線入口 | 沿用 N2 的 Smac 規劃 |
| 持瓶→第二桌 | **新增**：Smac 規劃持瓶段（2.3） |
| 放置 | **新增**：停車對位、下降、確認支撐、鬆爪、退離（2.4） |
| 控制權 | 同一個全身 GMPC，不交棒；只換階段目標、速度參考與指定接觸 |

## 2. 場景與流程

### 2.1 第二桌位置

- 用同一份桌子資產（頂高 0.60、0.8×0.5 m）。中心放在 (2.4, −0.39)，對應的放置直線 y＝−1.0，桌子近緣在 y＝−0.64。放置直線和抓取直線錯開 1.0 m，持瓶段得轉向，才用得到規劃。
- 起點、方塊、第一桌、瓶子都同 S1。舊出口區不再使用。
- 桌腳進已知地圖與掃描；桌面在掃描面之上，LiDAR 看不到，所以桌面、手臂、瓶子的安全由三維幾何判定與接觸通道負責，不拿桌腳安全代替。

### 2.2 停車位與放置點

- **底盤朝向**：明定停車偏航 θ_park＝0（與放置直線同向），不讓幾何解自由選。
- **停車位置**：用完整座標變換解平面位置。底盤→TCP 取當下實際構型，TCP→瓶取抓持成立時固定的 T_rel。解出讓瓶軸 xy 落在放置點 (2.4, −0.58) 的 P_park＝(x, y, 0)。
  - 持瓶段一開始算一次，作為規劃目標。
  - PARKED 時用實際構型重算一次，偏差超過 15 mm 就停止。第一版不做原地微調。
- **不宣稱**「下降就是已驗證抬升的逆過程」。搬運中手臂會變（CARRY 的 TCP 底盤座標任務仍會調整），所以要另外核對：
  - PARKED 時的實際構型與關節餘裕。
  - 下降段：手臂與瓶對兩張桌的淨空。
  - 退離段：手指與手臂對瓶的淨空。
  - 第一包離線核對，實跑時 PARKED 線上再核一次，不過就停止。
- 放置點名目距第二桌近緣 6 cm。實際落點以瓶子實際位姿判定。

### 2.3 持瓶段規劃

- LIFT 開始時，以當下量測的底盤位姿為起點，向 planner_server 請求到「放置直線入口」（P_park 往回 0.6 m，沿 θ_park）的路徑。接著是指定直線，在 P_park 停下。
- 規劃回覆到之前，沿 LIFT 原參考，不加速。
- **CARRY 開始時採用**，用最新實際狀態重新核對，全部通過才換參考：
  - N2 的路徑核對：frame、起終點、間距、代價、Bézier 接段。
  - 承接點：取在途命令走完後的預測底盤位姿，投影到新路徑。
  - 承接條件（候選）：橫向距離 ≤ 0.05 m；路徑切向與預測底盤速度方向差 ≤ 20°；參考速度從當下實測速度起算，再依既有斜率限制升到 v_carry，不跳變。
  - 預測位姿到投影點若需要接段，用三次 Bézier 接上，接段也要過代價核對。
  - 任一項不過，或 CARRY 開始時仍沒有有效路徑，就受控停止，不退回直線出口路線。
- **進度統一用弧長 σ**：CARRY 錨定在實際底盤 SE(2)，σ 由投影取得（只往前找、不低於起點）。新控制器自己處理參考推進與領先限制，不殘留任何世界 x 的夾限（不沿用 S0b 的 `s_ref ≤ x＋S_LEAD`）。
- 路徑監看同 N2：剩餘規劃段遇內切以上代價，或代價圖超過 2 s 未更新，就受控停止。不重規劃（P4 另案）。

### 2.4 放置相位

| 相位 | 內容 | 進入下一相位的條件（事前定） |
|---|---|---|
| PLACE_APPROACH | 直線上依剩餘距離減速到 0，參考停在 P_park | 參考到 P_park |
| PARKED | 底盤命令 0，手臂維持持瓶 | 實測底盤速度 < 0.01 m/s、\|ω\| < 0.02 rad/s 連續 0.5 s，位置誤差 ≤ 20 mm、偏航誤差 ≤ 1° |
| LOWER | TCP 沿世界 −z 下降（詳見下方 LOWER 細節） | 支撐成立（詳見下方） |
| RELEASE | 只在支撐成立後准入；TCP 保持，手指 0.5 s 斜坡張開 | 實際手指開度 ≥ 0.8×全開，且兩指↔瓶力 < 0.05 N，連續 0.5 s（張開後 2 s 期限內） |
| RETREAT | TCP 沿工具 −z（抓取插入的反方向）退 0.06 m，再回 K2_READY；底盤保持停住 | 手臂全連桿↔瓶淨空 ≥ 10 mm，且回到 K2_READY |
| HOLD | 全部靜止 3 s 觀察 | 第 3 節的放置成功條件全部成立 ⇒ DONE |

**LOWER 細節**
- 快段 0.02 m/s：下降到預測瓶底高出桌面 10 mm 為止。預測用實測 TCP、T_rel，並納入在途命令走完後的位置。
- 預接觸段 0.005 m/s：在途 8 步只多走 0.4 mm。
- 首次有效支撐：
  - 瓶↔第二桌接觸力沿桌面法向（世界 +z）的分量 ≥ 0.98 N，水平分量 ≤ 0.3 倍法向。
  - 瓶底實際高度離桌面 ≤ 3 mm。
  - 瓶軸 xy 在放置區內。
- 首次有效支撐出現後，凍結下降目標、不再加深，接著確認連續 0.3 s 都符合，才算支撐成立。側碰（法向分量不足，或瓶底不在桌面高度）不算支撐。
- 走到下降上限（抬升高度＋10 mm）仍未支撐，就受控停止。

**失抓監看**：既有的抓持監看（掉瓶、滑移）一直到 RELEASE 准入前都照常有效；准入之後才把「手指脫離接觸」改成預期事件。

任何相位超過期限（名目時長 ×3），就走既有受控停止。期限屬於判準，跑之前凍結。

## 3. 放置成功與安全（分開判定，事前凍結）

**放置成功**：以下全部成立，才算 DONE。不以 TCP 到位、張爪命令或相位 DONE 代替。

1. 鬆爪前支撐已成立（同 LOWER 條件）。
2. 兩指解除接觸，且實際手指開度達標（同 RELEASE 條件）。
3. 從鬆爪到 HOLD 結束：瓶位移 ≤ 5 mm、傾角 ≤ 3°；最後 1 s 瓶速 < 1 mm/s；瓶↔第二桌法向力 ≥ 0.9 mg。
4. 瓶軸離第二桌任一桌緣 ≥ 半徑＋10 mm；落點離名目放置點 ≤ 30 mm（只報告、不設門）。

**安全**：既有判準全部保留。

- 禁止接觸：≥0.05 N 連續 3 物理步，或穿透 ≥1 mm。
- 新增通道：手臂與手指↔第二桌（桌面、桌腳）、底盤↔第二桌桌腳、瓶↔第二桌桌腳、瓶↔第一桌（抬離後）。
- 指定接觸只有兩個：手指↔瓶（RELEASE 完成前）、瓶底↔第二桌桌面（LOWER 起）。掌面、非手指連桿↔瓶仍禁止。
- 缺資料不當零；Shield、資料有效性、92 °C 熱中止、既有抓持判準照舊。
- 不用焊接、瞬移，也不直接改物件位姿來冒充放置。

## 5. 視覺分階段

| 階段 | 相機與估計 | 進控制？ |
|---|---|---|
| V1 旁路 | 底盤相機（base_camera，RealSense 型）與手腕相機（camera_link，門任務 D1／CP1 用過）出 RGB-D。保存來源時間（模擬時鐘）、frame、內參、有效性。瓶位姿估計：深度在桌面平面上方分割＋圓柱擬合，已知瓶型。每筆估計對真值記誤差；真值只做評估。 | 否 |
| V2 | 瓶位姿估計進抓取目標；估計缺失、過期（> 0.3 s）或跳變（> 10 mm）時，依事前規則保持、重估或停止，不默默退回真值。 | 是（瓶） |
| V3 | 第二桌桌面與放置區由視覺估計。 | 是（桌） |

V1 不和第二桌首次物理放置同一趟改控制來源。相機渲染會增加負載：V1 只存估計與稀疏影格，影格頻率另定。

## 6. 第一包與實跑申請

**第一包（只有離線與假世界，不開 Isaac）**

- 新版本檔：場景（加第二桌與接觸通道）、地圖加第二桌桌腳、放置控制器（新類別，弧長進度、無 x 夾限）、持瓶段規劃請求與採用核對、放置判定。
- 假受控對象：瓶在 LOWER 接觸桌面後由支撐承接、鬆爪後留在原位。只驗流程、判定與停止路徑；合成支撐不能證明物理放置成功。
- 負測：持瓶規劃失敗 ⇒ 停止；下降到上限仍未支撐 ⇒ 停止；支撐未成立不准鬆爪；鬆爪後手指仍有力 ⇒ 不准退離；路徑被擋 ⇒ 停止。
- 離線幾何：持瓶規劃路線上的手臂、瓶對兩張桌與方塊的淨空；停車構型的手臂關節餘裕；退離段手指↔瓶淨空。

**實跑申請（第一包通過後另送）**：bottle_p1_1 一趟，S1 場景＋第二桌、N1 鏈路＋兩段規劃、真值瓶位姿，停車放置。開視窗、熱守護、不錄影、失敗不補跑。

**不做**：返家、再次抓取、比較矩陣、S3 三維障礙與放置同趟、視覺進控制。
