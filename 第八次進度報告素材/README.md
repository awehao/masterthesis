## 起點：第七次結尾的狀態

**Howard 11/3 的指正（以此為準）**：「又是拿一套寫死的控制騙我，根本不是什麼視覺看到去夾」。查程式屬實：

- 視向目標 `x_look`＝0.15／−0.15，等於瓶子實際的 x；每輪選物區域與「遠瓶先抓」的順序也寫死。
- 接近路徑在看到瓶子前就排好；放置點、預備姿態、視角序列、抓取方向 +x、轉向點都是預設。
- 看不到瓶子只會停下（`segtarget_no_fix`），不會找。
- 視覺實際決定的只有最後的精確抓取位置（例：`bottle_f1c_2` 第一瓶 (0.15044, 0.42029)）與抓取窗口的平移；真值沒有進控制器。

所以第七次的兩瓶結果只能這樣講：

| 素材 | 可以說 | 不能說 |
|---|---|---|
| `bottle_f1c_2`（n＝1，154.00 s，兩輪滑移 2.11／1.29 mm） | 預設流程下的整合驗證：連續交接、移動物、10 N 夾持同趟完成 | 視覺驅動、依視覺抓放、會找瓶子、可泛化 |

## 第八次主線：真的「看到才去夾」

Codex 20261103_151057 裁定（`reviews/20261103_151057_reply.md`），順序如下：

1. **第一包：單瓶，先看見再生成接近計畫**。範圍：已知來源桌區域、同型單瓶、精確瓶位未知、放到指定放置區。
   - 觀看點與掃視只來自桌面範圍，不讀瓶子生成座標，不用瓶子真實 x 當視向。
   - 未找到時做有界掃視或換觀察點；預算用完報「未發現」，不宣稱桌上沒有瓶。
   - **取得目標後**才依量測位置與當下運動狀態算接近路徑、可達抓取窗、展臂與抓取排程。
   - 暫保留共同的 +x 抓取方向與指定放置點，要明示。
   - 驗收：瓶位由亂數生成器產生（只檢查擺放合法，不挑容易的位置），預先登錄 3 個佈置；失敗照算，只報「完成數／3」，不是泛化成功率；中途改版前後分開計分。
2. **第二包**：同一套視覺驅動流程做兩瓶選物與順路接取，再加入交通（不是回到固定輪次腳本）。

影片要呈現：原始視野／全部偵測 → 選中目標 → 計畫生成時刻與路徑 → 移動抓取。

## 必須揭露的前提

- 凍結模型是同型瓶的實例分割，不是任意物件辨識，也不是學得的抓取策略。
- `known_type` 用瓶半徑、抓持帶等尺寸先驗；不是未知物體的幾何重建。
- 訓練與量測不保證全桌每個位置、遠距、遮擋、新背景都有效；看不到或搆不到都算結果。
- 桌面區域、地圖、放置點屬於任務先驗；接觸力、瓶底間隙與真值安全網的實機缺口繼續揭露。
- 維持 10 N 模擬夾持設定，不再掃力、不重訓模型。

## 口徑規則（每份素材都適用）

- 分清**線上計算**與**預設**；完成一個流程不等於一般能力。
- 缺少≠零次；數值吻合≠逐筆對應；標籤寫明實際欄位；效應要對比重複波動。
- n＝1 就寫 n＝1；指定場景就寫指定場景。
