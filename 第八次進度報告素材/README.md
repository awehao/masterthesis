## 起點：第七次結尾的狀態

**Howard 11/3 的指正（以此為準）**：「又是拿一套寫死的控制騙我，根本不是什麼視覺看到去夾」。查程式屬實：

- 視向目標 `x_look`＝0.15／−0.15，等於瓶子實際的 x；每輪選物區域與「遠瓶先抓」的順序也寫死。
- 接近路徑在看到瓶子前就排好；放置點、預備姿態、視角序列、抓取方向 +x、轉向點都是預設。
- 看不到瓶子只會停下（`segtarget_no_fix`），不會找。
- 視覺實際決定的只有最後的精確抓取位置（例：`bottle_f1c_2` 第一瓶 (0.15044, 0.42029)）與抓取窗口的平移；真值沒有進控制器。

最終場景＝研究目標頁的情境：**接到「拿抽屜中的筆」→ 前往書房 → 開門通過 → 避開未知靜態／動態障礙 → 找到並開啟抽屜 → 取筆返回**。

- 到觀察點仍沒看到，先跑事前有界的掃視策略，預算用完才報「未發現」；可以停下觀察，但不改成停車抓取。

## 必須揭露的前提（瓶子技術前置）

- 凍結模型是同型瓶的實例分割，不是任意物件辨識，也不是學得的抓取策略。
- `known_type` 用瓶半徑、抓持帶等尺寸先驗；不是未知物體的幾何重建。
- 訓練與量測不保證全桌每個位置、遠距、遮擋、新背景都有效；看不到或搆不到都算結果。
- 桌面區域、地圖、放置點屬於任務先驗；接觸力、瓶底間隙與真值安全網的實機缺口繼續揭露。
- 維持 10 N 模擬夾持設定，不再掃力、不重訓模型。

## 口徑規則（每份素材都適用）

- 分清**線上計算**與**預設**；完成一個流程不等於一般能力。
- 缺少≠零次；數值吻合≠逐筆對應；標籤寫明實際欄位；效應要對比重複波動。
- n＝1 就寫 n＝1；指定場景就寫指定場景。
