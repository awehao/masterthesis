# 任務導引、精準且快速的 MotM：Howard 需求與文獻對照 r1

日期：2026-11-11。狀態：需求澄清與原始論文閱讀整理，非新能力已完成；本次不改控制器、不啟動模擬。

## 1. Howard 最新方向與任務界線

Howard 希望速度更快，也接受告知機器人物品所在位置／區域；後續成果包含「告訴機器人去哪裡拿什麼」。並要求多參考 MotM 論文的方法、遇到的問題與未來工作，評估能否解決。

工作解讀：允許使用者提供目的地、家具／搜尋區域、物件名稱及放置／返回目的地，例如「去 B 房抽屜拿粗馬克筆，帶回起點」。這是任務先驗，不是假裝由感知發現的結果。若提供更精確的位置提示，也須明列來源及精度；控制器仍需當次觀測確認，而不能把生成物件的模擬器真值偷當視覺定位。

- 不再把「完全不提供區域／左右提示的盲搜」列為當前成果的必過前置；它可以另列後續能力。既有右側結果仍須揭露事前右側工作區先驗，不改寫成未知左右搜尋。
- 任務層可以指定拿什麼、去哪裡找；操作層的精確目標確認、可達性、接近方向／站位、全身路徑與安全處置仍依觀測及當下狀態計算。不得以任務提示為由恢復固定抓取答案。
- 先用結構化任務輸入串通流程，之後再接自然語句解析；不必把大語言模型或開放詞彙辨識當成這一階段的必要依賴。現有瓶子、門把手與粗馬克筆的模型／感測缺口仍分開報。
- 最終場景仍是完整牆壁房間、動態障礙、開門、開抽屜、取粗馬克筆返回；不要求關門／關抽屜，尚未完成整體驗證。

## 2. 「快」的定義與近期順序

目標是維持既有精度、抓持品質與碰撞判準下，縮短整體任務時間，而非只提高巡航參數，也不是靠全面降速或影片加速宣稱改善。

1. A0 先完成既有接線缺陷修正及真控制鏈核對；它是同源、可行的時間基礎，不是已提速成果。20261111_200017 審查指出的停止處置、非有限站位成本、共同定時失敗與硬限制接受閘門仍須處理，不因本需求撤銷。
2. 在可行基礎上，優先研究非必要低速區間、固定等待、重複收放與轉向，以及感知／規劃能否與導航重疊。候選方向及站位應同時考慮眼前抓取和下一個任務位置，不只最短底盤路徑。
3. 抓取減速點逐步改由剩餘可達時間、觀測／規劃延遲、手臂轉移、夾爪閉合時間與誤差預算推得。這是待驗假設，不能未驗就刪掉低速段、提高閉合速度或放寬滑移門檻。
4. 以任務提示串接完整場景的觀察與在線操作；瓶子用來驗證可移植的協調模組，不無限擴張成與最終任務無關的盲搜實驗。

交付至少分列：總時間及各段時間、實際抓取車速、停等與反覆加減速、TCP 誤差、滑移、放置誤差、淨空／接觸、所有失敗，以及求解與命令發布耗時。不同側別／場景／交通條件不作單因素提速比較；RTF 上限與模擬時間、牆鐘時間分開，不以慢速模擬證明即時性。

## 4. 優先挑選的研究問題與驗法

| 問題 | 候選改法 | 必須看到的證據 |
|---|---|---|
| 計畫比輪級能力快，實際卻慢行／追趕 | 同源可行剖面，再以時間參數化基準比較 | 真控制鏈不崩、硬界／初末速度符合；同條件總耗時及誤差，不只理想參考速度 |
| 很早進入固定低速段、整體抓取慢 | 依可達窗口與剩餘操作時間決定減速，觀察／規劃與導航重疊 | 相同品質下縮短接近時間；晚偵測／遮擋／規劃延遲時仍正確減速或拒絕 |
| 遇行人突然煞停、分類抖動 | 有時效與不確定性的運動預測、穩定決策及可行等待／繞行 | 比同場景基準減少非必要等待，且不增加碰撞；保留所有相位失敗，不能只挑會遇成功趟 |
| 把物件抓姿當成機器人可執行動作 | 量測後聯合比較接近方向、站位、手臂分支與速度 | 不同來向／遮擋能改變決策；全部候選不可行就拒絕，不退回固定答案 |
| 「抓到了／已離桌」靠模擬真值 | 研究夾爪狀態、雙相機相對運動與可用力覺的證據及盲區 | 誤判、漏判、延遲及失效處置；尚未完成實機驗證前，不宣稱感測問題已解決 |

不是一次改完以上全部項目。以最直接影響目前時間與品質的問題選一項，方法與案例事前固定，對照後再決定是否保留。論文 future work 只是研究切入點，不能直接當成本研究已解決的貢獻。
