## 2 線上與先驗（照實列）

- **線上**：
  - 瓶 xy 與支撐高度：手腕視覺，學習模型、已知型別。
  - 抓取／轉回計畫：由量測與當下狀態產生。
  - q1 視向偏移、GMPC＋CBF、Shield、運送協調。
- **先驗**（這次照樣揭露）：
  - 桌面區域與地圖（區域原點、桌腳 2D）。
  - 視向觀看點 LOOK：取設計域中心，不是瓶位。
  - V_HIGH 手臂觀察序列（U／H／R）、抓取方向、相對窗、速度排程。
  - 放置點：任務目標，第二桌。
  - 同型瓶尺寸。
- **真值流向核對**（`isaac_bottle_w1dynsr34.py`）：
  - 生成瓶位 BX／BY 只給場景與評估（`goal_err_vs_truth`）。
  - 生成桌高 Z1 以位置參數 `table_top_z` 進入 `S0Judge`，只做離桌判定（真值安全網），沒進目標路徑；控制器的 `top_z` 用的是資產先驗。
  - 兩兩瓶 F1 線的 `x_look`＝真實瓶 x 是寫死的答案，**不沿用**那條線。

## 3 案例設計（閉迴路前登錄，之後不依成敗調整）

- **瓶位**：用登錄的亂數種子從設計域抽取（dx ∈ [−0.08, 0.08]、dy ∈ [−0.025, 0.04]）。值只交給執行端與評估，不寫進控制器設定。
- **名目趟**：無移動物，n = 1。只用來量測接近、插入、閉爪的時段和底盤軌跡，作為移動物時程的依據。
- **移動物**：0.20 m/s、半徑 0.25 m、高 1.0 m，世界軌跡等速，不跟隨機器人。兩種時程擇一或依序（請裁定）：
  - **A 接近段橫越**：在名目趟「插入開始」前約 1–2 s 的位置，垂直橫越機器人前進走廊。不反應的話，機器人進入插入窗前會和它衝突，所以必須有實際反應（減速、讓路或等待）後才能抓取。
  - **B 插入段近距錯身**：插入到閉爪之間，在桌子外側近距反向錯身。最近時進入動態 CBF 影響範圍（< 0.69 m），但不反應也不會碰撞。這一案測的是接觸段的已知限制（C2 已封存）。
- **幾何前提**（沿用 `bottle_dyn_case_region` 的四項）：
  1. 軌跡和靜態物保持距離。
  2. 與規劃路徑的關係依 A／B 分別宣告。
  3. 最接近時刻落在指定的任務段。
  4. 連桿點雲與持瓶的淨空。
  
  候選依事前宣告的順序，取第一個全部通過的。

## 4 必要修改

1. **追蹤器門檻與 0.20 m/s 衝突（介面阻點）**：瓶子線用 `min_net_speed 0.25`（2 s 窗平均淨速度）、`min_track_speed 0.2`。0.20 m/s 的移動物會被判成靜態（reject = 3），**不會進入動態 CBF**，只剩代價圖和靜態避障。可選：
   - (a) 這一包把門檻降到 0.10／0.12／0.10，先用既有瓶子紀錄做離線假移動物核對（需要先寫掃描重放夾具）。
   - (b) 移動物改用 0.30 m/s（既有案例的速度，高於門檻）。
   - (c) 維持 0.20 m/s，並揭露「只走靜態路徑」。
2. **案例生成器** `bottle_dyn_case_motm.py`（新寫）＋執行端版本化複本（登錄新案例；控制器不改）。
3. **2D 追蹤疊圖**：新寫 `bottle_overlay_video.py`，從同一趟紀錄重建，同模擬時間、1×：
   - 原始掃描（`scan_log`）。
   - 追蹤位置與速度（`s1_steps` 的 `dyn_t*`、`s1_cbf` 的 `obs_json`）及等速預測。
   - 規劃與實走路徑、底盤包絡、抓取相位、視覺目標（`candidates.jsonl`）。
   - 真值（`dyn_x/y`、瓶位）用不同圖例，只供評估。
4. **Isaac 影片**：沿用既有重播與合成，標「實錄重播」、RUN_ID、版本、相位與成敗，1×。
5. **報表**：分接近、插入、閉爪、抬升、運送各段報追蹤與約束作用（CBF 啟用、Shield 改寫），以及：
   - 插入 → 抓持成立的實測車速與近停時間。
   - TCP 誤差、滑移／抓持品質、放置偏差、最小淨空。
   - 總時間、非必要等待、求解／發布延遲。

## 5 執行順序與負載（筆電）

1. 離線：門檻核對（若選 (a)）、案例生成與前提核對、2D 疊圖工具用既有 `bottle_rb1_dyn_1` 紀錄試做。
2. Isaac 名目趟 n = 1 → 重播 → 兩支影片。
3. Isaac 動態案 n = 1 → 重播 → 兩支影片。

一次只跑一項高負載工作，Isaac 與渲染不並行；每趟之間冷卻；92 °C 熱中止＋記憶體上限；失敗不自動重試。前一包擷取時 CPU 峰值曾到 91 °C。

## 6 預期第一阻點

1. 追蹤門檻（第 4.1 節）：不處理的話，0.20 m/s 不會走動態避障。
2. 接觸段協調：C2 已依判準封存。若移動物在插入段逼使底盤偏移，相對窗可能失效而中止抓取。這是已知限制，不能停用避障或改成停車抓取來掩蓋。
3. 單趟 n = 1 只算有資訊的案例，不是成功率。
