## 1　任務流程

```
S（A 房起點）
 → 導航：A 房內有未知靜態箱體與行人
 → 門（關閉、向 A 房開）：找把手 → 拉開 → 通過
 → 導航：B 房（書房）內有未知箱體與行人
 → 找櫃子與抽屜把手 → 開抽屜
 → 找抽屜內的粗馬克筆代理物 → 抓取、取出
 → 返程：觀察門扇與通道占用，安全通過（不預排關門／關抽屜）
 → 回 S 交付代理物
```

不要求關門不代表可凍結門扇或忽略其運動；門扇／抽屜維持物理模擬。若返程通道被擋住，須處理或回報，不能假定持筆的單一夾爪可直接換抓門把。

## 6　實作順序

**第一包（Codex 180004 核可）：場景＋掃描驅動導航，S → 門前觀察區**（到門前結束，不閉爪、不開門）。通過離線核對、不動作接線檢查並凍結後，可跑一趟 Isaac。

1. 同一配置同時進物理、掃描與評估；未知箱體不進靜態地圖，只能經掃描進局部代價圖與 CBF；生成座標與行人真值速度不餵給規劃或控制。
2. 行人沿固定世界軌跡、用統一任務時鐘，不因機器人位置或失敗重新對時。
3. 報告：掃描→追蹤→求解器的實際事件鏈、靜／動態分類、CBF 鬆弛、Shield、距離、耗時、停止。有行人在場不等於有有效動態會遇。
4. 影片：全景＋掃描／追蹤疊圖。只驗到 A 房，B 房行人不算已驗證。
5. 用實際控制器的底盤包絡（半徑 0.39 m）與限制重核導航連通性，不沿用生成器的 0.35＋0.10 m 假設。
6. 門前觀察區由門框地圖先驗算，不把舊 D1 精確操作停位包裝成在線結果。

同時離線做門把手 RGB-D 幾何法可行性核對（既有或新擷取資料），不擴成操作實跑。

之後：視覺定位門把手 → 在線生成受鉸鏈約束的全身操作 → 抽屜 → 取物 → 串成完整任務並加入動態交互（導航中與接觸操作中分開驗收）。

瓶子「先看見再生成接近計畫」：**新物理趟擱置**（Codex 180004）；候選時間戳、狀態承接、量測後規劃等模組直接用在門把手上。

**共同驗收（精準又快）**：完成時間、非必要停等、TCP 誤差、操作與抓持品質、避障距離、計算耗時，不只報「有完成」。
