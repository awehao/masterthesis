## 一　這次做出什麼

### 1　找到並修掉手臂甩動的根因

成本函數裡命令**變化率**的權重矩陣 `S = w_s / vmax² · I` 是以各軸自己的
速度框正規化的：

| | vmax | `w_s = 1e-3` 的等效權重 |
|---|---|---|
| 底盤 | 0.035255 m/s | **0.805** |
| 手臂 | 0.9999 rad/s | **0.001** |

**底盤天生被罰 800 倍，手臂幾乎不被罰。** 對 0.8 m 的誤差，任務項是
`50 × 0.8² = 32`／步，手臂滿框跳變只罰 `4e-3` —— 差四個數量級。
加重因素：手臂雅可比在移動段接近奇異（條件數 p50 3349、最小奇異值 0.0005，
伸長只有上限的 55% ⇒ 是內部奇異不是工作空間邊界），命令有 p50 17.6%、
p90 80% 的能量落在幾乎不影響 TCP 的方向。

**修法**：把變化率權重分成底盤／手臂兩半，只提手臂那一半。
`w_s_arm = 0.05`、`w_a = 0.05`，底盤維持 `1e-3`。
全域提高也能修甩動，但會把底盤一起壓慢（保持窗誤差 0.70 → 1.66 mm）。

### 2　量到的改善（Isaac 實跑）

移動段：

| 指標 | 修正前 | 修正後 |
|---|---|---|
| TCP 路徑 ÷ 淨位移 | 2.046 | **1.032** |
| 手臂命令翻號率 | 37.2% | **12.4%** |
| 誤差變大的週期 | 21.3% | **2.1%** |
| SQP `no_progress` | 28.2% | **0.0%** |
| SQP 疊代 p50 | 9 | **4** |

保持窗（2 秒內整機實際動了多少）：

| | 所有關節來回總和 | 最大關節速率 | TCP 來回 |
|---|---|---|---|
| 近目標 修正前 | 13.34° | 17.22 °/s | 51.66 mm |
| 近目標 修正後 | **1.93°** | 6.47 °/s | **3.77 mm** |
| 遠目標 修正前 | 0.64° | 3.68 °/s | 5.09 mm |
| 遠目標 修正後 | **0.18°** | **0.53 °/s** | **4.13 mm** |

先前診斷出的 **5 Hz（週期 4）極限環，在新設定的四趟中都未再出現**
（週期皆為 2 且振幅小兩個數量級）。

> **措辭**：維持「未再出現」，**不說「已解決」** —— 樣本仍少，
> 且機制未以反例證明。

### 3　順帶修掉的

- **判準 C 的缺陷**：原本問「底盤與手臂是否同時在動 ≥80%」，一支在速度框
  之間甩的手臂完全滿足它（修正前通過 99%、修正後只有 19%，但兩趟的手臂
  貢獻完全一樣：都在移動段前 16–17% 伸出去、貢獻 45% 的 TCP 位移）。
  已改用 C2（路徑/淨位移、翻號率、誤差單調性、SQP 收斂）。
- **錄製器掉封裝**：主迴圈 `spin_once` 每次只處理一個回呼，高負載時佇列
  溢位。改成獨立執行緒持續 spin，solver 漏錄 15 → 2 筆。
  下游缺口是安全層的速率錯配，**不是遺失**（`recv_seq` 逐筆遞增、
  `n_rejected = 0`、`api_applied` 全為 True）。

## 三　**不能**用這些素材宣稱的事

- **統計穩定性**：每個設定只有兩趟。兩趟之間數字很一致
  （遠目標保持窗 TCP 路徑 4.13 / 4.55 mm），但那是可重現性，不是統計。
- **接觸式操作**：全部是自由空間、無接觸。抽屜任務尚未執行。
- **振動已解決**：只能說新設定的四趟中未再出現 5 Hz 極限環。
- **實測關節角的餘裕保證**：新加的執行端拒寫只保護**設定點**；
  實測關節角因一階遲滯仍可能落在有效界外，要接上物理後才知道。
- **預測能力**：另有量測顯示，遠目標移動段 MPC 的預測比等速外推差 27 倍
  （該段運動本來就接近等速直線）；近目標時反過來好 27 倍。
  **W-GMPC 的預測價值依任務而異**，目前只有近目標那種需要協調與減速的
  情形展現出來。

# 第二部分　移動中操作（MotM）：抽屜開 200 mm → 停 → 關 → 回起點

2026-10-04 新增。主線：**底盤不停、手臂與底盤協同完成抽屜開關**，只在開與關
之間停頓。下面每一項都附「能支持什麼／不能宣稱什麼」。

## 一　這次做出什麼

### 1　先發現：原本的夾持是碰撞近似造成的

舊基線 `motm_200_075305` 雖然整套走完，但**夾持判準以逐物理步看並不成立**
（雙指 ≥ 0.5 N 最長連續 0.25 s，原本以 20 Hz 取樣湊出 2 s）。原因在幾何：

- 手指碰撞在 USD 是單一 `convexHull`。L 形手指被包成 29° 的 V 形楔面。
- Ø10 桿在抓取深度下，手指閉到下限仍離桿 0.09 mm ⇒ **驅動擠不到桿**；
  力是抽屜蠕動、把桿推進楔面才出現（finger1 3.6 N/mm，相關 0.998）。
- 用官方網格的真實形狀，指片閉合間距 22.4 mm，**Ø10 桿根本夾不到**。

修正（圖 06）：手指碰撞拆成根部／指片兩個凸塊（保留真實指片平面）、
把手換 Ø26（`規格/drawer_unit_bar26.yaml`，原資產未動）、抓取深度 6.8 mm。
結果每指 ~5 N 真夾緊（= USD maxForce 5 N ＝ 廠商規格夾力），2 s 判準 2.1 s 內成立。

### 2　MotM 怎麼做

| 層 | 做法 |
|---|---|
| 求解器（W-GMPC 增廣核心） | 新增兩個可選成本項（預設關閉）：**底盤參考速度** `w_vref`、**手臂名目姿態** `w_qn`。任務節點依相位在執行中切換 |
| 接近與夾持 | 底盤照 √ 剖面＋蠕行 4 mm/s 持續前進（可越過停位 ≤ 30 mm），手臂補償；**底盤在走時閉合夾持** |
| 開／關 | 底盤參考速度 = 拉速；手臂名目姿態隨實測開度由夾持姿態內插到「收回 60 mm」⇒ 手臂設計性分擔 |
| 關閉之後 | 底盤立即以 8 mm/s 倒退；放開、退開、收臂、交還導航全程不送零 |
| 量測 | 模擬器發同一物理步的狀態包；夾持判準逐物理步計時；107 剛體的抽屜接觸配對 |

### 3　量到的結果（圖 04、05、09）

**公平對照（b6 批次，2026-10-04 晚）**：停車與 MotM 各 3 趟、交錯執行（M、P、M、P…），
兩組都套用同一套模擬與求解修正（ROS 佇列清空、關閉限位 −10 µm 容差、目標斜坡、
下垂靜態初值、同步收臂、相同進場參數），**唯一差別是 MotM 開關**。

| 指標（平均 ± 標準差，n = 3） | 停車抓取 | MotM |
|---|---|---|
| 完成 | 3/3 | 3/3 |
| 不允許的停頓（≥ 0.15 s、< 2 mm/s） | **5.0 ± 0.0 段**（最長 6.24 ± 0.06 s） | **0** |
| 夾持建立期間底盤位移 | 0.38 ± 0.02 mm | 9.05 ± 0.04 mm（最低 2.85 mm/s） |
| 首次接觸 → 開始拉開 | 2.24 ± 0.02 s | 2.23 ± 0.03 s |
| 夾持漂移最大 | 0.36 ± 0.04 mm | 1.12 ± 0.08 mm |
| 拉開時手臂分擔 | 15.5 ± 0.1 mm | 52.4 ± 3.4 mm |
| 拉開 200 mm 耗時 | 7.85 ± 0.75 s | 7.63 ± 0.63 s |
| 開始移動 → 完成 | **77.7 ± 1.2 s** | **80.2 ± 1.7 s** |
| 啟動擺盪峰對峰 | 0.1 mm | 1.2 mm |
| 閉合前接觸／非預期接觸 | 0／無 | 0／無 |

**解讀**：MotM 的差別是**不停**（5 段停頓 → 0）與**底盤在夾持期間持續移動**、手臂分擔
約 3.4 倍；**不是比較快**——全程反而慢約 2.5 s（接近時 4 mm/s 蠕行），漂移較大但仍遠低於
10 mm 門檻。**更正**：先前「MotM 全程快 4–15 s」是與**未套用修正**的停車流程比較，不成立。

### 4　後續修的兩個可見問題

- **關門後手臂上抬**（圖 08、影片 08）：收臂「j3 最後動」讓夾爪舉高 44 cm。
  改各軸同步收回 ⇒ 高度維持 547–563 mm、收臂 11.8 → 6.5 s。
- **開之前的上下擺盪**（圖 07）：求解節點上線後 1–3 s，週期 ~0.8 s，峰對峰 29–79 mm。
  **根因**：抽屜房模擬器每個物理步只處理**一則** ROS 訊息，數個持續發布的話題在佇列裡
  積壓 ⇒ 全身命令「狀態→生效」延遲 p50 150–210 ms、最大 390 ms，而求解端延遲補償假設
  80 ms。改成每步清空佇列後延遲最大 90 ms，峰對峰 **1.4／1.5 mm**（185942、190426 兩趟）。
  之前修的三個誘因（目標斜坡、下垂靜態初值、啟動期底盤釘參考速度）保留，但不是根因。
  離線閉環模擬重現不出擺盪，正是因為它用的就是 80 ms。

- **統計穩定**：公平對照每組 n = 3；只能說可重現、標準差小，不做顯著性宣稱。
- **比停車快**：公平對照下 MotM 全程慢約 2.5 s（77.7 vs 80.2 s）。收益是**不停**，不是快。
- **自由空間的手臂振盪也解決了**：本次根因（模擬器每步只處理一則訊息）只存在於抽屜房
  模擬器；自由空間用的 `isaac_wholebody_sim_e2.py` 以獨立執行緒 spin，沒有這個積壓。
  WG2 記錄的「手臂振盪未解」不能據此宣稱解決。抽屜啟動擺盪的修正也只有 2 趟。
- **安全**：管線裡沒有安全層；非預期接觸只量了抽屜（107 剛體配對），櫃體或其他物體未量。
- **泛化**：只做過這一個抽屜（直線滑軌、已知位姿、模擬真值量開度）。門／櫃門未做。

## 四　已知缺項

- 抽屜開度與把手位姿取自模擬器真值，沒有感知。
- **關閉帶邊界（已處理）**：限位處數值穿透使開度量到 −2 µm，落出凍結的關閉帶 (0.000, 0.005) m，
  保持計時一直歸零（motm_185942 拖到 8.4 s）。經使用者核准，量測定義改為 [−10 µm, 0) 記為 0
  （`--opening-floor-tol-m`，帶本身不變）；b6 批次 6 趟關閉保持皆 2.08–2.15 s。
- 求解節點的 `--help` 會因既有說明文字的 `38.1%` 崩潰（不影響執行）。
- 每趟 URDF 匯入都產生新的 `evaluation/models/isaac_usd/omni_bot_manip_N`，累積很多。
- 熱況：本期各趟 CPU 峰值 82–87 °C（中止線 92 °C）。
