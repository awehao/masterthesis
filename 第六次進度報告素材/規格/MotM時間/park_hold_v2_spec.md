# PARK_HOLD（PARK_FIXED v2）：主動位置保持的最小接線與判準修訂（草案，待 Codex 審）

日期：2026-10-05。依 Codex `reviews/20261005_122220_reply.md` 裁定 B。**尚未改程式、未開新趟次。**

**修訂時序**：v1（零底盤命令）於功能確認 `runs/pf_func_F` 發生模式違規（UNFOLD 中實測 1.256 mm/s）之後，才提出 v2。
v1 規格、程式、判定與該趟原樣保留；v2 是看過失敗後的新策略，另立版本，不回改 v1。

## 1. 要回答的問題不變

「底盤確實停住再操作」＝**實測**底盤在停車保持期內靜止（速率與相對錨點偏離不超過原門檻），不等於「馬達完全不做修正」。
v2 允許以錨點為參考、經正常限制的**停車伺服修正命令**抵抗漂移；不瞬移、不鎖世界位姿、不加虛構煞車、不改摩擦。

## 2. 停車伺服律（單一純函式，三個命令來源共用）

`park_hold_cmd(anchor, pose)`（`park_fixed.py`）：以錨點為參考的本體座標速度

    e_xy_body = R(yaw)ᵀ (anchor_xy − pose_xy)，e_yaw = wrap(anchor_yaw − yaw)
    v = clip(k_p · e_xy_body, ±v_hold_max)，ω = clip(k_yaw · e_yaw, ±w_hold_max)

事前參數（不看結果調）：k_p = 2.0 /s、k_yaw = 2.0 /s、v_hold_max = 5 mm/s、w_hold_max = 0.02 rad/s。
理由：功能確認量到的漂移約 0.55 mm/s，穩態誤差約 v_drift/k_p ≈ 0.3 mm < 1 mm；上限遠低於既有底盤速度／加速度／輪級限制
（全部不變）。量測 = 各節點收到的 `/odom` 真值位姿（與其他節點同源）；錨點 = 執行端 `/park/gate` 通過當步的錨點（閂鎖，不更新）。

## 3. 誰發停車伺服命令（保持期全窗：實際轉給全身 → 實際交還導航）

| 區段 | 命令來源 | v2 改動 |
|---|---|---|
| UNFOLD／HOLD | `drawer_wholebody_node.py` | 底盤分量 = park_hold_cmd（v1 為 0） |
| ALIGN … RETREAT | 求解節點（W-GMPC） | 核心等式 `u_base[k] = u_hold`（每輪由實測位姿算出，整個時域同值；v1 為 0）；手臂照常求解 |
| RESTOW／HANDBACK_WAIT | `drawer_task_node.py` | 底盤分量 = park_hold_cmd（v1 為 0） |

三者用同一函式、同一參數、同一錨點。命令照原路徑進命令鏈（低速介面界限、輪級 λ、加速度上限都在後面照套），
**真正套用值由執行端回報**；不在限制之後疊加任何修正。

## 4. 判準修訂（只改「命令為零」相關的語意，實測門檻不動）

| 項目 | v1 | v2 |
|---|---|---|
| 入場靜止閘門（轉給全身前） | 套用命令 ≤ 1e-6 等 | **不變**（減速段仍鎖存精確零；閘門判定不變） |
| 保持期實測速率／yaw 速率 | ≤ 1 mm/s、≤ 0.01 rad/s | **不變** |
| 保持期相對錨點偏離 | ≤ 1 mm、≤ 0.5° | **不變** |
| 保持期套用底盤命令 | 各軸 ≤ 1e-6 | 線速度 ≤ v_hold_max、角速度 ≤ w_hold_max（上界核對）；另記「停車伺服修正量」全程統計 |
| 求解器模式閘門 | u_prev 底盤 > 1e-6 ⇒ 拒絕 | u_prev 底盤超出 v_hold_max／w_hold_max（＋1e-6）⇒ 拒絕 |
| 求解器輸出核對 | 發布底盤 > 1e-6 ⇒ 拒絕 | \|發布底盤 − u_hold\| > 1e-6 或 u_hold 超上界 ⇒ 不發布並停止 |
| 違規處置 | 閂鎖中止（v1 已實作） | 不變 |

「任務要求底盤固定」與「停車伺服修正命令」分開記錄：逐輪記 u_hold（求解輸入，重播必須還原）、各節點記其發出的伺服命令；
執行端 `park_gate.json` 另報保持期套用命令的最大值與分布。**不把實際修正值記成零。**

## 5. 必要接線（v1 基礎上的最小改動）

1. `park_fixed.py`：加 `park_hold_cmd` 與參數；`HoldMonitor` 的命令核對改為上界核對（v2 模式），速率／偏離不變。
2. `wgmpc_core*.py`：`base_fixed` 擴充為 `base_hold`（三軸等式值 = u_hold；u_hold = 0 時與 v1 逐位元相同）；名目序列同夾。
3. `wgmpc_wg2_node.py`：`--park-hold`：每輪由 `/odom`（同時刻快照的底盤位姿）與錨點算 u_hold、寫入核心與紀錄；模式閘門與輸出核對改為 §4。
4. `drawer_wholebody_node.py`／`drawer_task_node.py`：`--park-hold`：底盤分量用 park_hold_cmd（取代 v1 的 0），訂 `/park/gate` 取錨點；未取得錨點 ⇒ 不發命令並中止。
5. 模擬器／mission／glide：與 v1 相同（閘門、守門、違規閂鎖、滾動下界 0）；`--park-hold` 只換 HoldMonitor 的命令核對語意。
6. 重播：`horizon_replay` 由逐輪紀錄還原 u_hold。
7. 運行器：`PARK_HOLD=1`（與 MOTM、PARK_FIXED 互斥）。

## 6. 必要測試（不開大規模驗證）

- 伺服律：靜止零輸出、偏離方向正確、上界、yaw 跨 ±π。
- 核心：u_hold = 0 與 v1 逐位元相同；u_hold ≠ 0 時整時域底盤 = u_hold（≤ 1e-12）。
- HoldMonitor v2：伺服命令在上界內且實測靜止 ⇒ PASS；命令超上界 ⇒ VIOLATION；實測漂移超門檻 ⇒ VIOLATION（即使命令合規）。
- 求解節點：u_prev 在上界內接受、超出拒絕；發布值 ≠ u_hold 拒絕。
- 整合反例（沿用 v1）：違規時各來源停止。

## 7. 執行順序（審過才做）

實作＋離線測試 → 送審 → 開發版凍結 → PARK_HOLD 一趟功能確認（同版本 MOTM 功能趟已有，若程式改動觸及共用路徑則重跑一趟 MOTM）→
通過模式判定與 S1–S6 → 正式凍結 → 正式 3 對 M→H、H→M、M→H。
